# [긴급 검증] 동일 사업자번호 중복 가입 및 업체 데이터 접근권한 (대표님 지시 10/19)

받는 방: 서버 방(주관) · 보안 방(4·6번 접근 검사 함께)
우선순위: 타 업체 데이터 접근이 확인되면 **P0**, 접근 없이 중복 업체만 생성됐다면 **P1**

## 재현 상황
- '워시테스트' 계정(대표(본사))으로 브라더광택 사업자번호(876-12-0****) 등록 성공
- 기존 '실제 손님 업체 A 대표' 계정에도 같은 사업자번호가 등록돼 있음
- 관리 › 계정 관리에서 두 계정 모두 «대표»로 표시됨

## 원칙
- **먼저 읽기 전용으로 조사.** 운영 데이터 삭제·병합·변경 금지.
- 실제 개인정보를 다른 계정으로 열어보지 말고, 격리된 시험 자료(시험 업체 A/B)로 검증.
- 조사 결과의 개인정보(전화·이름·사업자번호 일부)는 마스킹.
- 운영 변경·배포는 대표님 별도 승인 없이 실행하지 않음.

## 할 일
1. 두 계정의 user_id, 업체 식별자(shop/tenant id), 사업자번호, 소속 관계, 대표 권한이 어떻게 연결됐는지 확인.
2. 같은 사업자번호 입력 시 다음을 구분:
   - 별도 업체가 중복 생성되는지
   - 기존 업체에 자동 연결되는지
   - 기존 업체의 대표 권한이 자동 부여되는지
3. 사업자번호를 아는 것만으로 기존 업체에 가입하거나 대표 권한을 얻을 수 없도록 **서버에서** 검증. 기존 업체 참여는 승인된 초대·가입 승인 절차로만. 대표 권한 부여·이전은 별도 검증.
4. 모든 조회·수정·다운로드 API와 첨부파일(사진·파일) 접근에서 로그인 사용자의 업체 소속·권한을 서버가 확인하는지 검사. 요청으로 전달된 업체 ID·사업자번호를 그대로 신뢰하면 안 됨. (워시 wash-api · 체크 check-api · 딜러 dealer-api · cgg-api · 가입 · v.html/r/d 보기 주소 · 사진 저장소)
5. 같은 사업자의 서비스별 이용 구조(워시·체크 동시 이용 등)를 먼저 정의한 뒤, 사업자번호 정규화(숫자만 10자리) + DB 고유 제약 + 트랜잭션으로 동시 가입까지 중복 차단. 화면에서만 검사하는 방식은 불충분.
6. 시험 업체 A/B로 차량·거래처·청구서·사진·파일이 서로 조회·수정되지 않는지 자동 테스트 작성.
7. 기존 중복 업체는 임의 병합 금지. 소유권과 데이터 연결 상태를 조사한 뒤 별도 정리안 제시(대표님 승인 후 실행).

- 영향받는 API와 가입 경로
- 차단·수정안 및 검증 결과(자동 테스트 결과 포함)
