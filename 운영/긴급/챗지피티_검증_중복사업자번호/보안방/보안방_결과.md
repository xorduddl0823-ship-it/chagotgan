맡긴 곳: 총괄 (운영/긴급/2026-10-19_중복사업자번호_검증요청.md · 4번·6번 + 섞인 흔적 + 고침 판정)
조사 방식: **읽기 전용**. 운영 서버 · DB 는 부르지 않았어요. 저장소의 지금 최신 서버 코드(워시 wash-api sb27 · 체크 check-api v52 · 딜러 dealer-api d9 · 경비실 cgg-api v1.6 · 결제 pay-hook p1)를 줄 단위로 봤어요.
개인정보: 이 문서에는 전화 · 이름 · 사업자번호를 적지 않았어요.

## 판정 — **P1** (다른 업체 자료에 닿는 길은 코드에서 찾지 못함)
- 사업자번호를 아는 것만으로 **다른 업체에 들어가거나 대표가 되는 길은 없어요.** 모든 서버가 업체 소속을 «사업자번호»가 아니라 **로그인 열쇠(세션)에 묶인 업체**로 정해요.
- 관리 › 계정 관리에서 두 계정이 모두 «대표»로 보인 것은 **각자 자기 업체의 대표**라는 뜻이에요. 워시 계정 표(wash_users)는 번호 하나에 업체 하나만 가질 수 있어서, 한 사람이 두 업체에 동시에 소속될 수 없어요.
- 그래서 지금 상태는 «같은 번호를 가진 **별도 업체가 하나 더 생긴 것**»이에요. 운영 DB 에서 섞인 흔적이 정말 없는지는 아래 «③ 흔적 확인 SQL»로 확정해요.

## ② 같은 번호가 어디로 들어올 수 있었나 (원인 후보)
1. **관리(본사)에서 업체 정보를 고칠 때** — W11. 이 길은 겹침 확인이 없어서 같은 번호가 그대로 들어가요. 관리 기록도 남지 않아 누가 언제 넣었는지 서버에서 알 수 없어요.
2. **동시에 넣기** — 업체 화면 길(W10 · C4)은 «먼저 읽어 보고 → 넣기»라서, 두 곳이 거의 동시에 넣으면 둘 다 통과할 수 있어요. DB 의 «같은 번호 금지» 색인이 있어야 막혀요.
3. **운영에 옛 서버가 올라가 있는 경우** — sb15 전 워시 서버는 겹침 확인이 없었어요. 운영 판을 서버 방이 확인해 주세요.
4. **DB 잠금(서버/sql/급한고침_사업자번호_잠금.sql)이 운영에 안 들어간 경우** — 들어갔다면 같은 번호 두 줄이 생길 수 없어요. ③ SQL 의 ⑧로 확인해요.

## ④ A/B 자동 시험
- 파일: `보안/검사기록/중복사업자번호_10-19/AB_시험_업체격리.js` (Node 18 · 꾸러미 없음)
- 시험 업체 A/B 열쇠로 15가지: B 열쇠 + A 코드로 읽기/쓰기, B 가 A 차 기록 · 사진 · 파일 · 청구서 · 배달 사진에 닿기, B 가 A 사업자번호 넣기, B 가 본사 기능 부르기 → 모두 거절돼야 통과. A 자기 것은 되는지 대조 3가지.
- 안전장치: `AB_OK=시험업체만` 이 없으면 시작하지 않아요. B 로 하는 쓰기는 거절돼야 맞는 것만 해요. 열쇠 값은 화면에 찍지 않아요.
- **아직 돌리지 않았어요** — 시험 업체 열쇠는 서버 방이 시험 환경에서 넣고 돌려요. 정적 검사(①)는 여기서 돌려 16/18 통과.

## ⑤ 고침 제안 (서버 방 몫 · 보안 방은 고친 판을 다시 검사)
1. **DB 에서 막기(가장 중요)**: 사업자번호를 숫자 10자리로 맞춘 «같은 번호 금지» 색인을 워시 업체 · 체크 검사소 · 본사 사이에 걸기. 워시 · 체크를 함께 쓰는 사업자는 «같은 사업자 묶음»으로 따로 정한 뒤 허락된 짝만 같은 번호를 쓰게. (기존 중복 2곳 때문에 색인이 바로 안 걸릴 수 있음 → 정리안 승인 뒤)
2. **hqShopSave 에도 같은 규칙**: 10자리 확인 · bizTaken(다른 곳 거절) · biz_ok_at 다시 «확인 전» · hq_audit 기록(누가 · 언제 · 어느 업체 · 번호는 남기지 않음).
3. **동시에 넣기 막기**: 넣기를 «비어 있을 때만 바꾸는» 조건부 한 번(update … where biz_no is null/'')으로 하고, 색인 위반 오류를 «다른 곳이 쓰는 번호» 안내로 바꾸기.
4. **C5**: 기사 회사 비밀번호를 사업자번호로 받을 때 같은 번호가 둘 이상이면 «검사소 코드로 넣어 주세요»로 거절.
5. 운영 확인: 워시 · 체크 서버 운영 판, ALLOW_LEGACY_KEY 값, 사진 보관함 공개 여부.
