# 차곳간 — 사업자번호·가입·통합 로그인 정책 결정서 (2026-10-19 · 대표 확정)

챗지피티 검증 요청: 아래 정책이 중복 가입·무단 소속 연결·다른 업체 자료 접근을 막기에 충분한지, 빠진 경우가 없는지 검토해 주세요. (구현 결과는 서버 방 보고서가 나오면 2차로 보냅니다.)

## 0. 발생한 일 (요약 · 개인정보 가림)
- 운영 워시에서 사업자번호 876-12-0****가 업체 두 곳(실제 손님 업체 A, 대표 시험 업체 B)에 저장됨. 둘 다 각자 업체의 «대표».
- 보안 방 1차 판정 **P1**: 다섯 서버(wash-api sb27 · check-api v52 · dealer-api d9 · cgg-api · pay-hook) 모두 업체 소속을 **로그인 열쇠에 묶인 업체**로 정하며, 사업자번호로 남의 업체에 붙는 길은 코드에서 발견되지 않음. 점검 18개 중 16 통과, 2 실패(W11 관리 hqShopSave 겹침 검사·감사 기록 없음 / C5 체크 기사 «회사 비밀번호»가 같은 번호 2곳일 때 첫 곳으로 감, 사무실 승인 필요해 열람은 없음). 자세한 것: `보안방/보안방_결과.md`.

## 1. 업체 식별 규칙
- 업체(가게) 고유 키 = **사업자번호(숫자 10자리로 정규화) + 종사업장번호(4자리, 없으면 0000)**.
- 같은 키로 업체 두 개 금지 — DB 고유 제약 + 조건부 단일 트랜잭션(동시 가입 포함). 화면 검사만으로는 불충분.
- 자료(차·거래처·청구서·사진·파일)의 소속은 언제나 **로그인 열쇠의 업체**로 서버가 정함. 요청에 실린 업체 ID·사업자번호는 믿지 않음.

## 2. 가입 규칙
- **처음 등록하는 사업자번호(단독)**: 승인 없이 바로 가입·사용.
- **이미 등록된 번호와 겹칠 때만**: 서버가 연결을 거절하고 «승인 대기»로 기록 → 본사(대표) 관리 화면에서 확인 후 승인/거절. 승인·거절은 감사 기록(hq_audit).
- 개인사업자·법인사업자 **똑같이** 적용(예외 없음).
- 같은 사업자번호로 두 번째 사업장 추가, 또는 한 사업자가 워시·체크 둘 다 쓰기 → 본사 승인으로만. 한 가게에서 제품 두 개는 «가게 하나에 제품 켜기»(업체 두 번 만들지 않음).
- 사업자번호를 아는 것만으로 기존 업체 가입·대표 권한 획득 불가. 기존 업체 참여는 초대·승인 절차, 대표 권한 이전은 별도 검증.
- 관리(본사) 화면에서 업체 정보를 고칠 때도 같은 겹침 검사·10자리 검사·감사 기록 적용(W11 고침).

## 3. 통합 로그인(메인 홈페이지 = 입구 하나)
- cgg.co.kr에서 휴대폰 인증 로그인.
- 계정 있음: 가게 1개 → 워시는 app.cgg.co.kr, 체크는 check.cgg.co.kr로 자동 이동(다시 로그인 없음 · 서버가 만든 한 번짜리 짧은 유효시간 넘김 코드) / 가게 2개 이상 → «가게 고르기»(가게 이름 · 제품 · 역할) 뒤 이동.
- 계정 없음: 바로 회원가입(요금제 먼저)으로 이어짐, 인증한 번호 재입력 없음. 가입 중 번호 겹침 → 안내 후 승인 대기.
- 딜러는 딜러앱, 관리는 별도 주소·별도 로그인(+문자 6자리).

## 4. 기존 중복 처리
- 임의 병합·삭제 금지. 읽기 전용 흔적 확인 SQL(`보안방/읽기전용_흔적확인.sql`)로 자료 섞임·사진 폴더·열쇠 소속 불일치·색인 유무 확인 → 정리안 작성 → 대표 승인 뒤 실행.
