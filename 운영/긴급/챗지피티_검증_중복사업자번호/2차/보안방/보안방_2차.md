범위(총괄 · 대표님 지시): 이번 출시에 꼭 필요한 것만. ① 시험기 고침 ② 다른 업체의 차량 · 청구서 · 사진 조회/변경 차단 ③ 중복 등록 차단 길과 동시 등록 DB 제약 판정. 넓은 범위는 맨 아래 «후속 목록».

## 1. 시험기 고침 (1차 검수 B01 · B02 · B07) — 끝
파일: `AB_시험_업체격리.js` (같은 폴더)
- API 마다 확정 응답 모양: 워시 · 체크 · 딜러 서버는 모두 `{result}` 또는 `{__err}` 한 칸만 돌려줘요(원본 확인). 모르는 모양 · 칸 둘 · HTTP 5xx · 해석 실패는 실패.
- 거절은 서버 원본에 있는 거절 글 10개와 **똑같을 때만** 통과(정적 검사 T1 이 이 글들이 원본에 그대로 있는지 매번 확인).
- 빈 목록 · 지운 수: `links` 칸이 실제로 있는 빈 객체일 때만, `invoiceDel` 은 `n` 0 · `missing` 1 칸이 숫자로 있을 때만.
- 대조군: A 의 그 차 기록 보기 코드(24자 모양) · 그 사진 서명 주소 · 그 차 상세 · 그 청구서 줄을 실제로 확인. 지우기 시도 앞뒤로 A 청구서 줄 지문(sha256)이 같아야 함.
- 필수 값 17개 하나라도 없음 · 시험 하나라도 실행 안 됨 → 끝 코드 2 «미검증»(성공 아님).
- 시험 환경 확인: 서버가 돌려준 업체 · 검사소가 넣어 준 코드와 같고 이름에 «시험/테스트»가 있어야 시작(하나라도 아니면 끝 코드 2). ⚠ DB 에 «시험 업체» 표시 칸은 아직 없어요 → 서버 방에 `is_test` 같은 표시를 요청(후속 4).
- 기록: 시험 번호 · 실패 까닭 종류 · HTTP 상태만. 응답 본문 · 열쇠 · 서명 주소 · 개인정보는 안 찍힘(자체 시험으로 확인).
- **시험기 자체 시험 25개 · 틀림 0** (`node AB_시험_업체격리.js --self-test`): 1차 검수가 든 잘못된 응답 {rows:[…]} · {result:{deleted:1}} · {links:[…]} · {} · 해석 실패 · 500 · 필수 값 없음 · 하나 빠짐 이 모두 «실패/미검증»으로 나옴. 정상 모양만 통과.
- 필수 시험 28개: 환경 확인 4 · 워시 13(대조 4 포함) · 체크 8(대조 2 포함) · 딜러 3(대조 1 포함).

## 5. 남은 출시 차단 문제 (이것이 끝나야 «보안 통과»)
1. **A/B 시험 실제 실행** — 시험 업체 A/B(워시 · 체크 · 딜러)로 필수 28개 모두 통과 · 끝 코드 0. 결과 줄(가린 것)을 2차 묶음에 붙이기. (서버 방이 시험 환경에서 실행)
2. **hqShopSave 고침** — 10자리 정규화 · 다른 곳 겹침 거절(bizTaken) · biz_ok_at 다시 «확인 전» · hq_audit 기록. 고친 diff 를 보안 방이 다시 검사.
3. **DB «같은 번호 금지» 운영 적용 확인** — SQL ⑧ 결과에서 4개 색인이 «유일 · 쓸수있음»으로 나와야 함. 지금 겹친 2곳 때문에 색인이 안 걸리면 정리안(승인 뒤) 먼저.
4. **기사 회사 비밀번호** — 같은 번호가 둘 이상이면 «검사소 코드로 넣어 주세요»로 거절.
5. **운영 상태 읽기 확인** — 사진 보관함 공개=false(SQL ⑩) · 업체 자료 표 RLS 켜짐/바깥 정책 0(SQL ⑪) · ALLOW_LEGACY_KEY ≠ 1 · 운영 서버 판(워시 sb15 이상 · 체크 v32 이상). 권한이 없으면 «미확인»으로 남김.

## 6. 후속 목록 (이번 출시 밖 · 1차 검수 Q4)
1. 워시 · 체크 사이 같은 번호 경쟁까지 막는 공통 사업자 원장 + 불변 업체 id + 제품 권한 모델(통합 로그인과 함께).
2. 역할별(대표 · 직원 · 기사 · 딜러 · 본사) · 퇴사/권한 철회/번호 변경 뒤 남은 열쇠 A/B 시험.
3. 결제 웹훅 중복 · 재전송 · 주문 귀속, 엑셀 · 백업 · 일괄 처리 · 페이지 넘김의 업체 필터 전수, 배경 작업 · 문자 받는 사람 경계.
4. DB 에 «시험 업체» 표시(is_test) — 시험기가 서버 쪽 표시로 환경을 확인하게.
5. 통합 로그인 넘김 코드 명세 · 시험(보안 방 조건 12가지 · 2026-10-19_통합로그인_A안_시안.md).
6. 체크 엑셀 «검사소 정보» 사업자번호 10자리 확인.

## 7. 섞인 흔적 확인 SQL (읽기 전용) — 2차 고침
`읽기전용_흔적확인.sql`: 항목마다 «기대 결과»를 따로 적음(②는 정상도 줄이 나옴 · ⑧은 색인이 있어야 정상 · ⑨는 기록이 있을 수 있음). ③ ⑥은 이상/참고 상태로 나눔. ⑦에 청구서 줄 ↔ 청구서의 차 · 청구서 ↔ 청구처를 더함. ⑧은 실제 정의(유일 · 식 · 조건)를 봄. ⑨는 겹친 업체만 · 번호 가림. ⑩ 보관함 공개 · ⑪ RLS 를 더함. **0건이어도 과거에 남의 자료를 «본» 일이 없다는 증명은 아님**을 맨 위에 적음. 아직 실행 안 함.
