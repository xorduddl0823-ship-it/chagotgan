## [1] rid 하나로 (워시 화면 ↔ 서버)
- R1 서버는 본문 최상위 `rid`만 받음. 형식 검사(소문자·숫자 24자) 밖이면 거절 또는 멱등 없이 처리하지 않음(높음: 형식 검사 없이 키에 그대로 넣기).
- R2 멱등 키에 업체(tenant)·사람·기능이 함께 들어감 — 다른 업체 rid 와 겹쳐도 남의 결과가 돌아오지 않음(높음).
- R3 `sendKey` 를 서버가 따로 받지 않음. 화면 v142 의 sendKey 는 rid 로 바뀜.
- R4 저장된 결과(cgg_idem)에 비밀값·전화번호 원문이 없음(idemScrub 유지, 7674728).

## [2] 발송 멱등 실패 처리 (워시·체크)
- F1 insert 오류가 23505 가 아니면 공급자 호출 0회, «잠시 뒤 다시» (중간: 우회 시 이중 발송).
- F2 done 갱신 error 확인 → 실패면 «확인 중».
- F3 접수 뒤 응답 유실·타임아웃·완료 기록 실패 = «확인 중», 자동 재발송 없음.
- F4 run 행을 시간만 보고 지우거나 catch 에서 무조건 지우지 않음.
- F5 오래된 작업 재획득은 조건부 원자적 update 한 번(읽기→삭제→넣기 금지).
- F6 «확인 중» 답에 공급자 원문 오류·키 값이 섞이지 않음.
