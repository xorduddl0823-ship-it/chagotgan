# 차곳간 통합 디자인 9판 재검수

검수일: 2026-10-19 · 대상: 차곳간_통합디자인_최신_9판.zip, 챗지피티_검수요청_9판.md

## 판단

**9판은 실제 개선판이다.** 8판과 달리 공통1.13.2의 정렬·날짜·0원·한글 조합 입력·선택 UI와 제품별 화면이 수정됐다. 딜러 알림의 본문 누락, 잘못된 필터, 모바일 정렬 표시 불일치, 홈페이지 로그인 단계 혼합은 예시 화면 기준으로 해소됐다.

**현재 디자인 방향을 유지하면서 남은 부분을 마감하면 된다.** 다만 홈페이지 체험 영역의 큰 안내문 자리와 정확하지 않은‘폰400’검수 폭은 수정해야 한다. 서비스마다 기능·메뉴·목록 수가 다른 점은 결함으로 판단하지 않았다.

검수 요청서에 명시한 현장 용어‘받을 금액·낼 금액’과 딜러 고유 단계‘입고·작업 중·출고·도착·상품화 완료’를 존중했다. 이를 미수금·납부할 금액 같은 다른 용어로 바꾸도록 재요구하지 않는다. 예시 요금·연락처·사업자번호도 실제 값으로 확정된 것처럼 평가하지 않았다.

## 범위와 검증 방식

- 워시20개·체크23개·관리23개·딜러6개, 총72개 메뉴 ×1440/400px ×가로/세로 메뉴 = **288개 화면 조합을 새로 렌더링·측정**했다.
- 홈페이지의 외부 비교 화면·로그인·가입·지금·손본 뒤를 두 너비에서 확인해 **10개 기본 화면**을 추가했다. 기본 조합 합계298개다.
- 필터, 초기 정렬,0원/빈값,묶음 상태,검색 조합 이벤트,로그인 단계,제품 선택,구역 이동,비교 폭,키보드 정렬·탭 이동은 별도 동작 검사를 했다.
- 화면 묶음과 주요 원본 이미지를 시각 확인했다. 모든 팝업·모든 오류·모든 실제 데이터 상태를 통과한 최종 인수검수는 아니다.
- 외부 요청은 차단하고 로컬 파일·예시 자료만 사용했다. 실제 로그인·발송·결제·운영 데이터 저장·배포·공개 설정 변경은 하지 않았다. 로그인 클릭은 모의 화면 전환만 확인했다.
- 한글 검사는 composition 이벤트를 사용한 자동 검증이다. Windows/Android의 실제 입력기 전체 조합 검사를 대체하지 않는다.

이전7판 보고서에서‘별도.bx카드가 모바일에도18px 20px padding을 유지한다’고 적은 부분은 정확하지 않았다.7·8·9판 모두760px 이하에서 **14px 14px**으로 바뀌는 규칙이 있다. 이번9판의 새 수정으로 오인하지 않고 이전 판정을 정정한다.

## 2. 새로 확인되거나 수정 과정에서 드러난 문제

### N01 · P1 · 홈페이지 체험 구역이 큰 안내문 자리로 자동 열린다

**디자인 완성본 확정 전 수정 권장. 실제 운영 연결을 요구하는 것이 아니다.**

- 위치: 홈페이지 손본 뒤→미리 써 보기.
-9판은 진입 시 openFirst()가 워시를 자동 선택한다. 탭과 큰iframe이 바로 열린다.
- 하지만 내장pkg-wash/check/dealer의 내용은 각각 약287~289자의 간단한 안내문뿐이다. 워시 iframe에는‘이 미리보기에서는 맨 위 «워시» 단추로 손본 뒤 화면을 봐요’라고 나온다.
- 개별 홈페이지 파일에는 통합 미리보기의 최상단 제품 선택 줄이 없고, 비교 화면 안에서는 해당 줄이 iframe 바깥에 있다. 사용자가 눌러 볼 화면을 기대했을 때 위치가 불명확하다.
- 탭은 정확히 전환되지만 **실제 서비스의 디자인 예시 화면은 이 큰 영역 안에 없다.** 이전 추가 예시표를 없앤 뒤 이를 대체하는 시각 콘텐츠가 부족해졌다.
- 제안: 승인된 워시·체크·딜러 예시 화면을 오프라인으로iframe에 넣거나, 현재 제품의 대표 화면과‘통합 시안에서 보기’전용 버튼을 제공한다. 안내만 둘 거라면 높이를 작은 안내 카드에 맞추고‘체험’과 구분한다.
- 완료 기준: 사이트 파일만 열어도 선택한 제품의 화면 디자인을 확인하거나 명확한 다음 이동 경로가 보인다. 인증·저장·발송·운영 API는 연결하지 않는다.

### N02 · P2 · ‘폰400’비교 모드가 모바일에서 실제368px로 렌더된다

- 외부 창400px에서 비교 화면의figure가368px이며iframe.innerWidth도368px이다.
- CSS의width:400px과max-width:100%가 충돌해 부모 폭으로 줄어든다. 따라서 라벨‘폰400’만으로 정확한400px 검수를 했다고 판단할 수 없다.
- PC1440모드는 실제iframe내부1440px를 유지한 채scale(약0.2556)로 보이는 크기를 줄이는 것은 확인했다.
- 제안: 폰 모드도 내부 폭400px를 고정하고 부모에 맞춰scale한다. 또는 축소하지 않고 가로 스크롤/개별 열기 중 하나를 명시한다. 나란히 보기에서는‘반응형 폭’과‘고정400’의 차이를 표시한다.
- 완료 기준: 외부 창 크기와 무관하게‘폰400’모드의innerWidth가400이다.

### N03 · P2 · 딜러 내 정보에 템플릿 변수 노출

-‘성능점검 유효기간이 끝나기 전에(날수는 검사소 설정 #{유효일수}일)’이 그대로 표시된다.
- 구현 설명과 사용자 안내가 섞여 있다.‘검사소에서 설정한 유효기간에 따라 안내해요’처럼 쓰거나, 예시 화면에는 확정한 예시 일수를 실제 문자열로 넣는다.
- 업무 기간의 법적 타당성은 이번 디자인 검수에서 판정하지 않았다. 고정120일을 다시 넣으라는 뜻도 아니다.

### N04 · P2 · 실행일과 예시 기준일이 섞여 상대 날짜가 맞지 않는다

- 검수 실행일의 일반 화면 머리에는10월19일 월요일이 나오는데, 홈 설명은10월18일 기준으로 고정돼 있다.
- 딜러 청구서도10/31‘13일 남음’,10/13‘5일 지남’이10/18 기준이다.10/19머리와 함께 보면 각각 하루 차이가 난다.
- 원인:CGG.head의기본today()와 고정 예시 자료가 다른 시계를 사용한다.
- 제안: 예시기준일을 한 상수로 둬 머리말·기한·달력·요약에 전달하거나, 상대 날짜는 같은기준일로 계산한다. 예시를10/18로 고정하는 것도 가능하다.
- 완료 기준: 어떤 날 파일을 열어도 화면이 표시한 기준일과‘N일 남음/지남’이 일치한다.

### N05 · P2 · 배달 모바일에서 담당자·사진 정보의 확인 경로가 줄었다

- 명시mobileFields를 도입하면서 차량·차종·목적지·출고·연락처·알림은 잘 보인다.
- 반면PC의‘보낸 사람’과‘사진’필드는 모바일 필드에 포함되지 않고 행 상세 진입도 없다.
- 모든PC열을 모바일에 항상 보여줄 필요는 없다. 다만 업무상 필요한지 정해‘사진 보기/담당자’등 필요한 값은 상세 또는 펼침에 제공한다.
- 완료 기준: 모바일 필수 필드 목록을 명시하고, 필요한 정보가 생략됐을 때 확인할 수 있다.

개별 보조 정보의 말줄임을 전부 없애야 하는 것은 아니다. 중요한 정보에는 전체를 확인할 수 있는 경로를 제공한다.

### F11: 모의 동작 안내

파일이 예시라는 점은 잘 드러난다. 계좌 복사/금액 복사처럼 실제 클립보드 동작을 하지 않는 단추의알림은‘복사 결과 안내 예시입니다’처럼 표시하면 더 명확하다. 실제 기능이 없어도 디자인 검수용으로 문제없지만, 사용자가 복사됐다고 기대하지 않도록 한다.

### F17: 요금제 탭의 마지막 접근성 작업

화살표 전환은 잘 작동한다. 선택 탭만 tabindex=0, 나머지는 -1로 두고, 탭 id와 aria-controls/패널 id/aria-labelledby를 연결한다. 현재 모든 탭은 별도 tabindex가 없고 tabpanel도 연결돼 있지 않다. 문서 언어와 키보드 정렬 수정은 유지한다.

### F18: 딜러 홈 최근 내 차

현재 tbl('dcar',...)에는 select:false가 빠져 있다. 일괄 동작이나 onSelect가 없는 읽기 전용 목록이므로 이 화면에도 선택 비활성 옵션을 전달한다. 계정·업체처럼 선택한 대상으로 실제 일괄 동작을 하는 목록은 선택을 유지한다.
