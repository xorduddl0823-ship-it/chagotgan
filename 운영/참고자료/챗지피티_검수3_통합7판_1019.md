# 차곳간 통합 UI·UX 최신 7판 검수

검토일: 2026-10-19 · 대상: 차곳간_통합디자인_최신_7판.zip

## 결론

**공통 외형은 통합 기준으로 상당히 맞춰졌다. 전체를 다시 디자인할 필요는 없지만, 지금 상태를 최종 완성본으로 확정하기에는 정보 누락·정렬·필터·인증 화면 표현을 고쳐야 한다.** 특히 딜러 모바일 알림은 핵심 내용이 빠져 있다. 서비스마다 다른 기능·항목·메뉴 수를 오류로 판단하지 않았다.

워시·체크·관리·딜러의 같은 역할을 하는 제목, KPI, 폼, 헤더, 표를 공통 기준으로 비교했다. 홈페이지는 홍보·설명 페이지이므로 앱의 작은 제목이나 메뉴 구조를 강제하지 않았다. 현재 홈페이지의 느낌을 살리는 방향을 존중했다. 최근 제안한 세 번째 홈페이지 시안과 똑같이 만들지 않았다는 이유로 결함 처리하지 않았다.

### F01 · P1 · 딜러 알림: 모바일에서 본문이 사라진다 — 재현 확인

- 화면: 딜러앱 → 알림 →400px. PC에는 ‘언제 / 종류 / 내용’이 있다.
- 모바일에는 `10-18 09:10 / 종류 / 도착`만 보이고 차량번호·위치·사진 안내 등 내용이 없다. 차량번호 검색을 해도 결과의 실제 차량 내용을 읽을 수 없다.
- 원인: `V.d_noti`의 `mf:[[1,"종류"],[0,"언제"]]`. 공통 표는0번 필드를 mobileFields에 넣지 않으며, 명시된 mobileFields 밖의 본문2번 열도 자동 표시하지 않는다.
- 수정: 내용2번 열을 주요 제목 또는 다줄 본문으로 표시하고, 시각·종류는 보조 정보로 둔다. mobileFields에0번 열을 넣어 해결했다고 판단하지 말 것.
- 완료 기준:4개 예시 알림 모두 차량번호/청구 내용이 모바일에서 읽히고 PC와 같은 의미를 전달한다.

### F02 · P1 · 딜러 알림: ‘입고·출고’가 입고만 거른다 — 재현 확인

- 전체4건 중 입고1건·출고1건인데 칩은 ‘입고 · 출고1’로 나온다. 선택하면 입고만 남는다.
- 원인: 탭 값은 `입고`, 공통 필터는 상태 문자열의 완전 일치만 사용한다.
- 수정: 입고/출고 칩을 분리하거나, 그룹 필터가 두 상태를 포함하도록 predicates/values를 지원한다. 숫자 집계도 같은 조건으로 계산한다.
- 완료 기준: 묶음 칩을 유지하면2건이고 두 종류가 모두 표시된다.

### F03 · P1 · 공통 모바일 정렬: 표시된 정렬과 실제 순서 불일치 — 재현·소스 확인

- 새 비교/흐름/FAQ를 넣은 방향은 좋다. 기존 구조를 유지한다는 이유로 모든 제품 소개를 중복 유지할 필요는 없다.
- 수정: 첫 화면 제품 카드는 짧은 선택 버튼으로, 새3개 카드는 비교 설명으로, 체험 영역은 탭+예시 화면 하나로 역할을 나눈다. 기존 체험 진입은 현재 선택 제품의 CTA에 연결한다.
- 완료 기준: 세 제품 소개가 각각 다른 정보를 전달한다. 길이 목표를 무조건 정하기보다 같은 설명 반복을 먼저 제거한다.

### F14 · P2 · 딜러 ‘성능검사 유효기간120일’ 문구는 조건 확인 필요

- 딜러 내 정보의 재검사 안내에 고정돼 있다. 이번 검토는 해당 기간의 법적·업무적 타당성을 검증하지 않았다.
- ‘성능검사’와‘성능점검’ 용어도 섞여 있다. 서비스 담당자에게 적용 문서·기산일·예외를 확인해 정확한 안내로 교체한다. 확인 없이 기간을 임의 변경하지 않는다.

### F15 · P2 · 관리자 한글 아이디 지원과 입력 의미 보완

- 새/현재 아이디 폼은 text 타입이어서 이 시안 자체에 숫자 전용 제한은 없다. 한글 입력 불가의 운영 원인이 해결됐다는 뜻은 아니다.
- 지금 아이디가 식별용이라면 읽기 전용 표시로 두고, 새 아이디는 조합 입력·붙여넣기·허용 문자·검증 안내를 정의한다.
- 공통 표 검색은 input마다 DOM을 다시 그린다. 한글 조합 중 재렌더·selection 복원이 입력을 방해하지 않는지 실제 IME로 회귀 확인하고 필요 시 composition guard를 둔다. 소스상 확인 과제이며 이번 검토에서 IME 장애를 재현한 것은 아니다.

### F16 · P2 · 공통 카드의 모바일 크기 규칙을 명확히

- 페이지 제목과 기본 입력은 일치한다. 별도.bx 카드는 모바일에도 padding18px 20px·제목16px을 유지하는 반면 KPI/공통 카드에는 별도 모바일 변형이 있다.
- 특수 폼 카드를 넓게 두는 것이 틀린 것은 아니다. 의도된‘폼 카드’ 변형으로 이름을 주거나 동일 역할 카드끼리만 여백을 맞춘다. 모든 카드 제목을 강제로 같은 크기로 만들지 않는다.
- 긴 설명이 있는 설정 화면에서는 제목→설명→입력 label 간격을 규칙화하고, 보조문과 label이 붙어 보이지 않게 한다.

### F17 · P2 · 문서 기본값·접근성 마감

- 완성_미리보기.html은 doctype과 lang이 없어 BackCompat로 렌더된다. 홈페이지 지금/손본뒤는 CSS1Compat이지만 lang은 비어 있다.
- `<!doctype html>`과`<html lang="ko">`를 명시한 뒤 box sizing·표 폭을 재측정한다. 단순 선언 변경 뒤 레이아웃 재확인 없이 완료 처리하지 않는다.
- 홈페이지 새 tablist에는 클릭 상태가 있지만 키보드 화살표 이동·선택 탭의 tabindex·tabpanel 연결을 보완한다.
- 공통 표 열 머리는 th에 클릭만 연결돼 있으므로 키보드용 정렬 버튼을 넣는다. aria-sort는 유지한다.
- 모든 기본 화면에서 미검출된 중복 ID는 팝업 중첩에서도 회귀 확인한다.

### F18 · P2 · 읽기 전용 표의 선택 UI·개인 메뉴는 제품별로 조정

- 딜러 알림 등 일괄 동작이 없는 표에도 전체 선택·행 체크박스가 있다. 선택 이후 할 일이 없다면 선택 UI를 숨기는 옵션을 둔다.
- 헤더 공통화 때문에 딜러에도 휴지통 관련 표시가 들어간다. 실제 삭제·복구 대상이 있는 제품인지 확인한 뒤 제공한다. 디자인 통일을 위해 없는 기능을 새로 만들지 않는다.
- 카히스토리 충전 비활성화는 좋은 수정이다. 조회 버튼도 준비 중 표시/비활성화 원칙을 맞춘다.

### F19 · P2 · 검토 표시·예시·확정 문구를 최종본에서 분리

- 홈페이지에는 빨간 점선·보라 띠·첫 문구 고르기, 미리보기에는 제품 선택 띠가 있다. 이들은 의도된 검토 도구이며 디자인 결함이 아니다.
- 배포용 산출물에는 검토용 UI와‘참고 시안에서 빌려 옴’ 표식을 제거한다. 예시 가격·고정 전화번호·샘플 사업자·추천 표시는 원천 확정 후 교체한다.
- 읽어보기는1.13.1, 자산 파일명/일부 JS 주석은1.13이다. 동작 결함은 아니지만 공통 버전과 각 제품 버전의 배포 명세를 하나로 관리한다.
