# 11/1 새 판에 문제가 생기면 — 되돌리기 순서 한 장

> 혼자 하지 말고 꼭 총괄 방에 먼저 알려 주세요. 위에서부터 차례로 해요. 대부분 ①에서 끝나요.

## 먼저 (새 판 올리기 «전에» 한 번)
- `서버/sql/29_데이터_백업_1101.sql`을 SQL Editor에서 실행해요.
- 맨 아래 표의 «같음?» 칸이 모두 «같음»이면 백업이 끝난 거예요.
- 이 백업은 손님 화면에서도, 서버 열쇠로도 안 보여요. SQL Editor에서만 보여요.

## ① 서버·화면만 예전 판으로 (자료는 그대로)
1. Supabase › Edge Functions에 예전 판 서버 파일을 다시 붙여 넣고 Deploy해요.
2. 화면도 예전 판 파일로 바꿔요.
- 새 판이 자료를 망가뜨리지 않았다면 이것만으로 예전처럼 돌아가요.

## ② 오늘 실행한 SQL 걷어 내기 (자료는 그대로 · ①을 한 «뒤에»)
- 급한고침 · 24 · 26은 손님 자료를 바꾸지 않아요. 표·칸·트리거·색인을 «더하기»만 해요(24는 승인 대기 줄을 더해요).
  그래서 이것만 걷어 내도 자료는 11/1 그대로예요.
1. **26**: `drop table if exists cgg_idem;`
   - «확인 중» 줄이 있으면 보낸 기록을 먼저 봐요.
2. **24**: 24번 파일 맨 아래 «되돌리기» 다섯 줄(트리거 2개 · 함수 3개)을 실행해요.
3. **급한고침**: 급한고침 파일 맨 아래 «되돌리기» 줄(트리거 3개 · 함수 3개 · 색인 4개)을 실행해요.

## ③ 자료를 11/1 백업으로 되돌리기 (자료가 정말 망가졌을 때만 · 망가진 표만)
- 파일: `서버/sql/30_백업으로_되돌리기_1101.sql`
  - 그냥 실행하면 아무것도 안 바뀌어요.
- 하는 법
  1. 파일 안 `restore_list`에 망가진 표 이름을 넣어요. 예: `array['wash_shops']`
  2. 실행해요.
- 안전장치
  - 되돌리기 «직전» 자료는 `backup_20261101_before_restore`에 먼저 복사해 둬요. 되돌린 것을 다시 되돌릴 수 있어요.
  - 그 표의 잠금 트리거는 되돌리는 동안만 끄고, 끝나면 다시 켜요.
  - 중간에 오류가 나면 «아무것도 안 바뀌어요».
- ⚠ 백업 «뒤에» 들어온 손님 자료(새 입고·청구서 등)는 그 표에서 사라져요. 꼭 필요한 표만 넣어요.
- 사진 파일과 로그인 계정은 이 백업에 없어요. 이번 새 판은 그 둘을 바꾸지 않아요.
