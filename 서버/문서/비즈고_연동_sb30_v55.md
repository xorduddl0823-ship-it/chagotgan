# 문자 업체 고르기 — 솔라피 / 비즈고(인포뱅크 BIZGO) · 워시 sb30 · 체크 v55 (서버 방 · 2026-10-21)

> 운영에는 반영하지 않았어요. 실제 발송은 0건이에요(시험은 가짜 응답으로만 했어요).
> 기본값은 지금처럼 **솔라피**예요. 비밀값 `MSG_VENDOR`를 `bizgo`로 넣어야만 비즈고로 나가요.

## 1. 스위치와 비밀값(이름만 · 값은 어디에도 적지 않아요)
| 이름 | 뜻 | 없으면 |
|---|---|---|
| `MSG_VENDOR` | `solapi` 또는 `bizgo`(대소문자 무시) | **솔라피**(이상한 값도 솔라피) |
| `BIZGO_API_KEY` | 비즈고 콘솔 › 발송관리 › 연동관리에서 받은 API Key | 비즈고로 보내지 않고 «못 보냄»(솔라피로 넘기지 않아요) |
| `BIZGO_SENDER_KEY` | 카카오 채널 «발신프로필 키»(senderKey) | 관리 설정 `ata_cfg.bizgo.senderKey` → 그것도 없으면 알림톡 대신 문자 |
| `BIZGO_ENV` | `sandbox`면 시험 서버(`https://sandbox-mars.ibapi.kr` · 실제 안 나감) | 운영(`https://mars.ibapi.kr`) |
- 솔라피 비밀값(`SOLAPI_KEY` · `SOLAPI_SECRET` · `PF_ID` · `SMS_FROM`)은 그대로 둬요. 스위치를 다시 `solapi`로 돌리면 바로 예전처럼 나가요.
- 보내는 번호는 지금과 같은 `SMS_FROM` 또는 업체 발신번호예요. **비즈고에도 같은 번호를 미리 등록해야 해요**(안 하면 A327 «미등록 발신번호»).

## 2. 템플릿 코드는 업체별로 따로
- 관리 설정 `wash_hq.ata_cfg`
  - 솔라피 코드는 `tpl`과 `pfId`예요.
  - 비즈고 코드는 `bizgo.tpl`과 `bizgo.senderKey`예요.
- 승인 문구(대체 문자 글 · 변수 이름)는 바꾸지 않았어요(`ATA_TPL` 그대로).
- 비즈고 코드가 없는 템플릿은 솔라피 코드를 쓰지 않아요. 알림톡 대신 대체 문구 문자로 보내요.
- 관리 서버 `hqAta`(보기)
  - `tpls`(솔라피)와 따로 `bizgo.tpls` · `bizgo.senderSet` · `vendor`(지금 스위치)를 돌려줘요.
- 관리 서버 `hqAtaSave`(저장)
  - `bizgo:{tpl, senderKey}`도 받아요.
  - 솔라피 칸만 저장해도 비즈고 칸은 지우지 않아요.
- **관리 화면에 비즈고 코드 칸이 아직 없어요(관리 화면 방 몫).** 칸이 생기기 전에는 비즈고 코드를 넣을 수 없어서, 비즈고로 바꾸면 알림톡 대신 대체 문구 문자로만 나가요.

## 3. 어떻게 동작하나
- 보내는 곳은 모두 `solapi()` 한 곳을 지나요.
  - 스위치가 비즈고면 그 안에서 비즈고 모양으로 바꿔 보내요.
  - 답은 솔라피 모양으로 돌려줘요.
  - 그래서 알림톡 → 문자 대체 · rid 한 번 · «확인 중» · 보낸 기록 · 결과 채우기가 그대로 이어져요.
- 메시지 한 통은 비즈고 `POST /api/comm/v1/send/omni` 한 번이에요.
  - 알림톡이면 `messageFlow: [{alimtalk:{senderKey, templateCode, msgType:"AT", sendType:"template"}}, {sms|mms:{from, text(대체 문구)}}]`예요.
  - 알림톡이 실패하면 **비즈고가 같은 요청 안에서** 문자로 대신 보내요.
  - 변수는 `destinations[0].replaceWords`(«#{이름}» 모양)로 넣어요.
- 문자 종류
  - 90바이트 이하면 `sms`예요.
  - 넘으면 `mms`인데 사진이 없어서 LMS가 돼요(제목은 `title`).
  - 사진 문자(MMS)는 지금 비즈고에서 **사진 없이 LMS**로 나가요(비즈고 파일 올리기는 아직 안 넣었어요).
- 성공은 세 가지가 모두 A000이고 msgKey를 받아야 해요.
  - `common.authCode`, `data.code`, 수신자 `data.data.destinations[0].code`예요.
  - 보낸 기록 `msg_id`는 `bz:<msgKey>`로 남아요.
- 결과 판정
  - 받았는지 모름(«확인 중» · 자동으로 다시 안 보냄): 연결 끊김 · 20초 시간 초과 · 5xx · 답을 못 읽음 · 수신자 `A301`(같은 요청 이미 처리)이에요.
  - 거절 확정(같은 rid로 다시 가능): `data.code`나 수신자 code가 A000이 아님(예: A327 미등록 발신번호 · A505 템플릿 코드 · A306 번호 · A020 속도 초과)이에요.
- 업체 쪽 중복 막기
  - 비즈고 `idempotencyKey`는 `cgg-<rid 지문 40자>-<요청 안 차례>`이고, `idempotencyTtl`은 86400이에요.
  - 지문은 (제품 · 업체 · 사람 · 기능 · rid)의 SHA-256이에요.
- **처음 고른 업체로만**
  - rid를 처음 잡을 때 그 줄(`cgg_idem.result.vendor`)에 업체를 적어요.
  - «다시 가능(retry)»으로 같은 rid가 다시 와도, 스위치가 바뀌었어도 처음 업체로만 보내요.
  - 끝난 rid는 어느 업체도 다시 부르지 않아요.
  - SQL 바꿈은 없어요(기존 `result` 칸을 써요).
- 결과 채우기(워시 `sendFill` · 체크 줄도 함께)
  - `bz:` 줄은 `GET /api/comm/v1/report/inquiry/{msgKey}`로 물어봐요.
  - `reportCode 10000` + `serviceType ALIMTALK`이면 «알림톡 도착»이에요.
  - 알림톡이었는데 SMS/MMS가 10000이면 «문자 대체»예요.
  - 실패면 `reportText`예요.
  - 알림톡만 실패하고 대체 결과가 아직이면 기다려요.
  - 조회 사이 0.22초를 쉬어요(속도 제한 other 5/s).
- 예약 문자는 비즈고에서 아직 안 보내요(«못 보냄» 확정).
  - 예약 취소도 «아직 못 해요» 오류예요.
  - 예약이 필요하면 솔라피로 둬요.

## 5. 비즈고에 물어볼 것(확인 전에는 «미확인»)
1. **서버 IP 등록**: API Key는 «허용 IP로 등록한 서버»에서만 쓸 수 있대요. 우리 서버(Supabase Edge Functions)는 **고정 IP가 없어요.**
   - IP 등록 없이 쓰는 방법이 있는지 물어봐요.
   - IP 범위로 등록할 수 있는지 물어봐요.
   - 안 되면 고정 IP 중계 서버가 따로 있어야 해요. **가장 먼저 물어볼 것**이에요.
2. 알림톡 `replaceWords` 이름 모양이 «#{이름}»인지 «이름»인지 물어봐요(지금은 «#{이름}»으로 보내요).
3. `sendType:"template"`과 `msgType:"AT"`를 같이 보내도 되는지 물어봐요. 템플릿 본문 `text`가 꼭 필요한지도 물어봐요.
4. 대체발송 리포트 모양을 물어봐요.
   - 한 msgKey에 «알림톡 실패 + 문자 성공»이 두 줄로 오는지 물어봐요.
   - `reportCode`가 글자인지 숫자인지 물어봐요.
5. 같은 `idempotencyKey`로 다시 오면(A301) 처음 msgKey를 알려 주는지 물어봐요. 알려 주면 «확인 중»을 자동으로 정리할 수 있어요.
6. 예약 발송 필드와 예약 취소 방법을 물어봐요.
7. MMS 사진 올리기(`fileKey` 받는 API)를 물어봐요.
8. 잔액·충전 조회 API를 물어봐요(지금 관리 화면 잔액은 솔라피 것만 보여요).
9. 솔라피에서 쓰던 카카오 채널(발신프로필)과 승인 템플릿을 비즈고로 옮기는 절차를 물어봐요.
   - 템플릿 코드가 새로 나오는지, 다시 심사하는지 물어봐요.
10. 발신번호 사전 등록 절차와 서류를 물어봐요.
