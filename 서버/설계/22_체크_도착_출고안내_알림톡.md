# 설계 22 — 체크 차량 도착 알림을 «차곳간_출고안내» 알림톡으로 (운영/06 M ④ · 대표님 결정 10/17 밤 · check-api v34)

## 무엇을 바꿨나
- 차량 도착 알림(`notifyOne`)이 템플릿을 고르는 순서를 바꿨어요.
  - `tpl.check_arrive`가 있으면 그것을 먼저 써요. 아직 등록하지 않았어요.
  - 없으면 이미 승인된 **`tpl.release`(차곳간_출고안내)**를 써요.
  - 그다음은 검사소 `ata_tpl`(본사 목록 안의 것만)이고, 그것도 없으면 문자예요.
- 출고안내 템플릿을 쓸 때는 본문을 건드리지 않고 **변수만 채워요**. 원문은 알림톡/00_확정본_13개_원문.md 2번이에요.

| 변수 | 값 |
|---|---|
| 딜러명 | 배달 줄 dealer_name, 없으면 «-» |
| 상사명 | company_name, 없으면 «-» |
| 차량번호 | plate |
| 작업내용 | «성능점검 · 배달» (고정) |
| 목적지 | dest_name |
| 출고일시 | 도착 시각 (MM-DD HH:MM, 한국 시간) |
| 업체전화 · 업체명 | 검사소 tel · name |
| 보기코드 | **«d» + 배달 열쇠글(view_key 18자)** |

- 알림톡이 안 되면 대체 문자로 보내요. 대체 문자는 지금 검사소 도착 문자 글 그대로예요(check.cgg.co.kr/d/열쇠).
- 발송 기록 tpl 이름은 `check_arrive_release`예요.

## 버튼 주소와 v.html (워시 방 몫)
- 버튼은 `https://app.cgg.co.kr/v.html?c=#{보기코드}`로 고정이에요. 그래서 v.html은 `c`가 **소문자 d로 시작하면** 체크 서버를 불러요.
  - 워시 보기코드는 대문자 A–F와 0–9 24자예요. 체크 청구서는 «k»로 시작해요. 그래서 서로 겹치지 않아요.
  - 부르는 곳: check-api `{ fn: "deliv_view", args: [c 그대로] }`
  - 서버가 앞의 d를 떼요.
- 답은 `{ result: { office:{name, tel}, photos:[서명 주소 1시간], deliv:{plate, car, dest, driver, dealer, at} } }`예요. 잘못된 주소면 `{ __err }`예요.
  - 받는 번호는 답에 넣지 않아요.

## 보안
- `deliv_view`에 한 아이피당 하루 상한을 붙였어요. `CHECK_VIEW_IP_MAX`(기본 300)로 청구서 보기와 같아요.
- 열쇠글은 무작위 18자라서 찍어서 맞힐 수 없어요.
- 받는 번호 제한(등록된 딜러만), 하루 상한, 보내는 번호 규칙(v32 M2)은 그대로예요.
- SQL은 필요 없어요.
