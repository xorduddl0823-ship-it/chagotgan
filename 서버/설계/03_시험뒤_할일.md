## 1. 체험판 잠금·횟수 세기 (서버가 함)
- 기준표: `워시/기획/2026-10-14_체험판_기능_분류표.md` (대표님 확정: 추천대로 — 잠금 14 · 3번 18 · 보기 13)
- 화면에서 단추를 숨기는 건 보안이 아니에요(규칙 2-1). **잠금과 횟수는 서버가 세고 막아요.**
- 만들 것 (워시 서버 새 판):
  - 기능 이름 → 「잠금 / 3번 / 보기」 목록을 서버에 둬요. 기준표와 한 줄씩 맞춰요.
  - 체험 중인 업체가 「잠금」 기능을 부르면 거절하고, 화면에는 결제 안내 창을 띄울 수 있는 표시를 함께 보내요.
  - 「3번」 기능은 **기능마다 따로** 업체당 3번을 세요. 세는 건 데이터베이스 안에서 한 번에 해요(`cgg_attempt` 와 같은 방식, 동시에 눌러도 새지 않게).
  - AI 번호판 읽기도 「3번 맛보기」예요.
  - 결제하면 잠금과 횟수가 바로 풀려요(요금제 확인은 지금 쓰는 `lockState`·`planInfo` 와 같은 자리에서).
- 함께 할 방: 워시(화면의 잠금 표시·결제 안내 창), 디자인(안내 창 모양), 보안(배포 전 검사)

## 2. 시험 번호 짝을 출입 명단(`cgg_access`)에 넣기
- 결정: 대표님 번호 = 워시+체크, 서브 번호 = 워시만, 회사 대표번호 = 체크만
- **번호는 문서·저장소에 적지 않아요.** 넣을 때 대표님이 SQL Editor 에서 직접 번호를 넣거나, 대표님 PC 방에서 바로 넣어요.
- 넣는 SQL 모양 (번호 자리는 비워 둠):
  ```sql
  insert into cgg_access (phone, name, products) values
    ('<대표님 번호>',   '대표님',   '{wash,check}'),
    ('<서브 번호>',     '서브',     '{wash}'),
    ('<회사 대표번호>', '회사대표', '{check}')
  on conflict (phone) do update set products = excluded.products, name = excluded.name, active = true;
  ```
- 준비 조건: 워시를 줄 번호는 워시 가입이 돼 있어야 하고, 체크를 줄 번호는 체크 검사소 직원으로 등록돼 비밀번호가 있어야 해요.
- ⚠ 체크 서버 v22/v23 을 올린 뒤에는, 워시 로그인 열쇠로 체크를 쓰던 사람도 명단에 체크가 있어야 해요.
