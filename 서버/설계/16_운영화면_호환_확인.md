# 새 서버를 올려도 지금 운영 화면이 되나요? — 확인 결과 (2026-10-15 · 서버 방)

> 총괄 질문: 시험 주소(cgg-test)의 새 화면은 **운영 수파베이스**를 같이 써요. 그래서 SQL 08·09, 체크 서버 v30, 워시 sb13을 먼저 올려야 해요. 그때 지금 운영 화면(워시 v111 · 관리 v3.6 · 체크 v21 화면 · 기사 화면 · 딜러 d2.3)이 그대로 되는지 확인했어요.
> 확인한 방법: 운영 화면 파일이 부르는 창구 이름을 모두 뽑아서 새 서버에 있는지 대조했고, 그다음 바뀐 동작을 하나씩 따졌어요.

## 결론
**대부분 그대로 돼요.** 운영 화면이 부르는 창구는 새 서버에 모두 있어요. 지금 운영 서버(sb1)에 있던 창구가 sb13에서 빠진 것도 없어요.
다만 아래 **조심 3가지**와 **올리는 순서**만 지키면 돼요.

## 조심 3가지
① **체크 직원의 「처음 로그인」(비밀번호가 비어 있는 사람)** — 체크 v30은 처음 로그인 때 휴대폰 확인 번호를 받아야 해요. 그런데 v21 화면에는 확인 번호 칸이 없어서, **새로 넣은 직원이나 비밀번호를 초기화한 직원은 v21 화면으로는 처음 로그인을 못 해요**(이미 비밀번호가 있는 사람은 괜찮아요).
   - 피하는 법: 그런 직원은 **시험 주소(cgg-test)의 새 체크 화면**으로 처음 로그인해서 비밀번호를 정하면 돼요. 그다음부터는 v21 화면으로도 들어가져요.
   - 설계 05의 「체크 시험 직원 넣기」도 마찬가지예요. SQL을 실행한 뒤 **새 화면으로** 처음 로그인하세요.
   - 관리 스위치 「체크 첫 비밀번호 문자 확인」(hqCheckPwSms)은 **운영 체크 화면이 새 판으로 바뀔 때까지 꺼 두세요.** 꺼져 있으면 관리 화면에서 체크 비밀번호 초기화가 막혀서, 사람이 갇히는 일이 없어요.
② **배달 기사** — 체크 v30은 운영 중인 v21.2보다 기사 로그인 규칙이 엄격해요(v23부터).
   - 같은 이름의 기사가 **두 검사소에 모두 사용 중**이면, 예전 기사 화면에는 회사 칸이 없어서 로그인이 안 돼요. → 올리기 전에 아래 SQL ①로 그런 이름이 있는지 확인하세요. 있으면 한쪽 이름을 바꾸거나(예: 김기사2), 새 기사 화면(cgg-test)을 쓰면 돼요.
   - 기사가 직접 [계정 만들기]를 하면 이제 **사무실이 [사용]으로 바꿔 줘야** 들어가져요(v21 사무실 화면의 기사 목록에서 바꿀 수 있어요).
   - 새로 정하는 비밀번호는 6자 이상이에요(예전 4~5자 비밀번호는 그대로 로그인돼요).
③ **통합 입구(경비실)가 아직 v1.1이면** 통합 입구로 들어온 사람은 워시에 모두 「PC」로 기록돼요. 이건 지금도 같아요. 경비실 v1.4와 비밀값 `CGG_INTERNAL_KEY`(워시·경비실 같은 값)를 같이 올리면 고쳐져요(설계 02).

## 올리는 순서 (운영 화면이 안 깨지게)
1. SQL **02 → 04** (체크 로그인 보안 · 첫 비밀번호 — 체크 v30이 이 표를 써요. 이미 했으면 건너뛰기)
2. SQL **05 → 06 → 07 → 08 → 09** (모두 여러 번 실행해도 안전 · 표와 칸만 더함)
3. 아래 SQL ①로 같은 이름의 기사 확인
4. **체크 서버 v30** 올리기 → 운영 체크 v21 화면으로 이미 비밀번호가 있는 직원 로그인 1번 확인
5. **워시 서버 sb13** 올리기 → 운영 워시 v111로 로그인 · 입고 1건 · 알림 1건 확인
6. (같이 하면 좋음) 경비실 v1.4 + `CGG_INTERNAL_KEY`
- 문제가 생기면: 체크는 v21.2, 워시는 sb1로 다시 올리면 바로 예전으로 돌아가요. SQL로 더한 표와 칸은 예전 서버가 쓰지 않아서 그대로 둬도 돼요.
