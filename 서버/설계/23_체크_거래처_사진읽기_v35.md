# 설계 23 — 체크 거래처 사진 읽기 (요청서 C · 운영/요청서/2026-10-18_08 · check-api v35)

## 무엇을 바꿨나
- `aiCard([사진])`는 명함을, `aiBiz([사진])`는 사업자등록증을 읽어요. 창구 이름과 답 모양(JSON 글자 하나)은 그대로예요.
  - 명함 답: `{name, phone, company, bizName, bizNo, email, addr}`
  - 사업자등록증 답: `{bizNo, bizName, ceo, addr, upte, jongmok}`
- **대표만** 써요. 직원은 거절해요.
  - 아무 글이나 시키는 `aiJson`도 대표만 써요. 직원이 이 창구로 돌아가지 못하게 하려는 거예요. 지금 체크 화면은 이 창구를 쓰지 않아요.
- **하루 한도를 따로 둬요**: 검사소당 `CHECK_AI_DOC_DAY`(기본 60)예요. 번호판 한도(`AI_MAX_DAY`)도 함께 세요. 한도를 넘으면 AI를 부르지 않아요(요금이 안 나가요).
- 사진 확인
  - 빈 사진이나 6MB 넘는 사진은 AI를 부르기 전에 거절해요.
  - png, webp, gif도 종류를 알아보고 보내요.
- 돌려주는 칸
  - 정해진 이름만 돌려주고, 칸마다 길이를 잘라요. `< >`와 제어 글자는 지워요.
  - 휴대폰은 010 모양일 때만, 사업자번호는 10자리일 때만 `000-00-00000`으로 돌려줘요. 아니면 빈칸이에요.
- 오류 글은 «사진을 읽지 못했습니다. 직접 적어 주세요.» 쪽이에요. «번호판»이라는 말이나 영어 원문은 섞이지 않아요.
- `check_log`에는 «명함 사진 읽기», «사업자등록증 사진 읽기»만 남겨요. 사진과 읽은 값은 남기지 않아요.
- 모델 이름 고쳐 쓰기(`claude-haiku-5.5` → `claude-haiku-5-5`)는 그대로예요.
- SQL은 필요 없어요.
- 읽은 값은 화면이 칸에 **미리 채우기만** 해요. 저장은 사람이 확인한 뒤 `companySave`나 `dealerSave`(대표만)로 해요.
