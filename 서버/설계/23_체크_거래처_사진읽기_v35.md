# 설계 23 — 체크 거래처 사진 읽기 (요청서 C · 운영/요청서/2026-10-18_08 · check-api v35)

## 무엇을 바꿨나
- `aiCard([사진])`는 명함을, `aiBiz([사진])`는 사업자등록증을 읽어요. 창구 이름과 답 모양(JSON 글자 하나)은 그대로예요.
  - 명함 답: `{name, phone, company, bizName, bizNo, email, addr}`
  - 사업자등록증 답: `{bizNo, bizName, ceo, addr, upte, jongmok}`
- **대표만** 써요. 직원은 거절해요.
  - 아무 글이나 시키는 `aiJson`도 대표만 써요. 직원이 이 창구로 돌아가지 못하게 하려는 거예요. 지금 체크 화면은 이 창구를 쓰지 않아요.
- **하루 한도를 따로 둬요**: 검사소당 `CHECK_AI_DOC_DAY`(기본 60)예요. 번호판 한도(`AI_MAX_DAY`)도 함께 세요. 한도를 넘으면 AI를 부르지 않아요(요금이 안 나가요).
- 사진 확인
  - 빈 사진이나 6MB 넘는 사진은 AI를 부르기 전에 거절해요.
  - png, webp, gif도 종류를 알아보고 보내요.
- 돌려주는 칸
  - 정해진 이름만 돌려주고, 칸마다 길이를 잘라요. `< >`와 제어 글자는 지워요.
  - 휴대폰은 010 모양일 때만, 사업자번호는 10자리일 때만 `000-00-00000`으로 돌려줘요. 아니면 빈칸이에요.
- 오류 글은 «사진을 읽지 못했습니다. 직접 적어 주세요.» 쪽이에요. «번호판»이라는 말이나 영어 원문은 섞이지 않아요.
- `check_log`에는 «명함 사진 읽기», «사업자등록증 사진 읽기»만 남겨요. 사진과 읽은 값은 남기지 않아요.
- 모델 이름 고쳐 쓰기(`claude-haiku-5.5` → `claude-haiku-5-5`)는 그대로예요.
- SQL은 필요 없어요.
- 읽은 값은 화면이 칸에 **미리 채우기만** 해요. 저장은 사람이 확인한 뒤 `companySave`나 `dealerSave`(대표만)로 해요.

## v37 · sb18에 더한 것 — 연락처·이메일 읽기와 사업자번호 확인 (대표님 10/18)
- **사업자등록증 읽기(aiBiz)** 답에 칸 세 개가 늘었어요: `openDate`(개업일 YYYYMMDD) · `tel` · `email`
  - 읽는 글에 «여백에 손글씨나 도장으로 적힌 전화(팩스 말고)·이메일(전자세금계산서용)도 적으세요»를 더했어요.
  - 이메일은 모델 답을 믿지 않아요. 서버가 이메일 모양(영문·숫자·`._%+-` @ 도메인.최상위)으로 첫 번째 것만 다시 골라내고 소문자로 바꿔요. 틀린 모양이면 빈칸이에요. 명함(aiCard) 이메일도 같은 규칙이에요.
  - 전화는 휴대폰뿐 아니라 지역번호(02·031 …)·070·1588 류도 받아요. 모양이 아니면 빈칸이에요.
  - 개업일은 숫자 8자리(19xx·20xx)일 때만 들어가요.
- **새 창구 `bizVerify({bizNo, ceo?, openDate?})`**: 체크(v37)와 워시(sb18)에 같은 모양으로 넣었어요.
  - 국세청 «사업자등록정보 진위확인 및 상태조회»(공공데이터포털 · 무료)를 써요.
  - 상태(`/status`): `state` = 계속 | 휴업 | 폐업 | 없음, 폐업일 `closedAt`(YYYY-MM-DD)
  - 진위(`/validate`): 대표자명과 개업일이 함께 있을 때만 물어요. `match` = true | false. 물어보지 않았으면 null이에요.
  - 답: `{ready, state, closedAt, match, why}`
  - **대표만** 써요(직원은 거절). 하루 한도는 검사소·업체당 100번(`CHECK_BIZV_DAY` · `WASH_BIZV_DAY`)이에요.
  - 기록에는 사업자번호 앞 3자리만 남겨요.
  - 열쇠 이름은 `NTS_API_KEY`예요. 값은 대표님이 Supabase Secrets에만 넣어요. 열쇠가 없거나 국세청이 응답하지 않으면 `ready:false`(«확인 준비 중»)로 조용히 넘어가고, **저장은 막지 않아요.**
- 시험: `시험/사업자확인_v37_sb18_시험.ts`가 체크 17개, 워시 10개 모두 통과했어요.

- 보안 중간 고침(10/18): 열쇠를 주소(`?serviceKey=`)에 넣지 않고 머리글 `Authorization: Infuser <열쇠>`로 보내요.
  - 연결 오류 글에 주소가 담겨도 열쇠는 남지 않아요.
  - 기록에는 정해진 글(`bizVerify 실패 net|key|401…`)만 남겨요.
  - 답의 `why`는 쉬운 말이에요. 열쇠가 맞지 않으면 «국세청 열쇠가 맞지 않아요(열쇠 확인 필요 · key)», 연결이 안 되면 «국세청에 연결하지 못했어요»로 나와요. 그래서 첫 시험에서 인코딩 문제를 바로 알 수 있어요.
  - 시험이 체크 19개, 워시 12개로 늘었어요.
- 체크 v47 약속(체크/기획/2026-10-18_v46_거래처_한화면_창구_약속.md 4장)에 맞췄어요(v38 · sb18).
  - 받는 값: `bizVerify({no, ceo, start})`(start는 YYYY-MM-DD 또는 YYYYMMDD). 예전 모양 `{bizNo, ceo, openDate}`도 받아요.
