# 설계 27 — 체크 단가 구간 서버 (체크 v48 약속 · 체크/기획/2026-10-18_v48_단가_창구_약속.md · check-api v40 · SQL 없음)

## 창구 (모양은 약속 그대로)
| 창구 | 누가 | 하는 일 |
|---|---|---|
| `priceList()` → `[{from_date, items:[{code, name, price}]}]` | 로그인한 누구나 | 이 검사소 단가 구간을 최신 날짜부터 줘요. |
| `priceSave({from, items})` → `{ok:true}` | 대표만 | 같은 날짜면 바꾸고, 없으면 새로 넣어요(`office_id,from_date` upsert). 받는 값은 아래에 있어요. |
| `priceDel({from:[…]})` → `{n}` | 대표만 | 이 검사소 구간만 지워요. 한 번에 20개까지예요. **마지막 하나는 남겨요**(다 지우려 하면 «단가 구간이 하나는 남아 있어야 해요»). |

**`priceSave`가 받는 값**
- `from`: YYYY-MM-DD
- `items`: 1~50개
  - 코드: 20자까지
  - 이름: 1~40자. `< >`와 제어 글자는 지워요.
  - 단가: 1~10,000,000원 정수(부가세 별도)
  - 같은 코드(또는 이름)가 두 번 있으면 거절해요.

- 저장과 지우기는 `check_log`에 남겨요(날짜, 항목 수).
- 청구서 만들기(`invoiceBuild`)는 지금처럼 검사일 기준 가장 가까운 지난 구간을 써요. 이미 만든 청구서는 다시 만들어야 바뀌어요. 세금계산서를 발급했거나 입금된 청구서는 그대로예요(v32 규칙).

## 함께 고친 것 (범위 확인)
- `invoiceRows(id)`: 이 검사소 청구서인지 먼저 확인해요. 남의 청구서 id면 **거절**해요(«이 검사소 청구서가 아닙니다»).
  - 체크 방이 지적했고, 보안 방도 확인한 중간 건이에요. v25부터 있던 문제예요.
  - 다만 로그인은 필요했어요. 그래서 로그인한 다른 검사소 사람만, 청구서 id를 알 때만 볼 수 있었어요.
  - 공개 청구서 보기(`invoiceView`)의 답에는 청구서 id나 검사소 id가 없어요. 정한 칸만 보내요. 그래서 id를 알아내는 길도 막혀 있어요.
- 같은 모양 전체 훑기: id로 찾는 db 문장 가운데 office_id 조건이 없는 것을 모두 뽑아 하나씩 봤어요.
  - 이번에 고친 둘(invoiceRows, deliv_photo) 말고는, 모두 바로 앞에서 이 검사소 것으로 확인한 id만 써요.
  - 고정 id 1인 wash_hq, 본인 세션의 id도 마찬가지로 문제가 없어요.
- `deliv_photo(pin, photoId)`: 그 사진의 배달 기록이 이 검사소 것일 때만 주소를 줘요.
- 국세청 열쇠에 잘못된 `%`가 있으면 풀지 않고 그대로 써요(v39 보안 참고).
