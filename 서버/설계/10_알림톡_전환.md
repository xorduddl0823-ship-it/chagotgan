### 공식 채널로 가짜 링크를 못 보내게 (sb7 · 보안 방 지적)
- `#{업체명}` `#{업체전화}` 는 화면이 무엇을 보내든 **서버가 가진 값**(`wash_shops`)으로 덮어써요.
- 출고·추가작업의 `#{보기코드}` 는 **서버가 만들어요** — 화면은 `rec`(이 업체의 입고 기록 id)만 줘요. 다른 업체 기록이나 없는 기록이면 거절.
- 청구서의 `#{보기코드}` 는 **이 업체의, 청구서용, 기한이 남은** 보기코드일 때만 받아요(대표·매니저가 `viewBill` 로 만든 것). 아니면 거절.
- 이 확인은 업체 캐시를 깎기 **전에** 해요 → 거절되면 돈이 안 나가요.
- 화면이 보낸 변수가 확정본과 하나라도 다르거나 빠지면, 알림톡을 시도하지 않고 확정본 대체 문구로 문자를 보내요(실패로 끝나지 않게). 기록에 「ataKey vars missing」이 남아요.

## 체크 · 딜러 · 경비실 (v29 · d5 · v1.4)
- **체크 차량 도착 `notifyOne`**: ① 관제센터 `check_arrive` 코드가 있으면 본사 채널 알림톡 → ② 없으면 검사소가 정한 템플릿(`check_deliv_conf.ata_tpl`, 채널 비면 `PF_ID`) → ③ 둘 다 없으면 지금처럼 문자·사진문자. 검사소 설정이 「문자」여도 템플릿이 있으면 알림톡 먼저예요. **대신 보내기는 늘 켜짐**(`disableSms:false`) + 대신 보낼 문자 글(검사소 문자 문안)을 같이 넣어요. 알림톡 요청이 거절·오류면 서버가 바로 문자로 한 번 더 보내요.
- **체크 사무실 첫 비밀번호 확인 번호**: 인증번호(`auth`) 알림톡 먼저 → 안 되면 지금 문자.
- **딜러 `sendCode`**: 인증번호 알림톡 먼저 → 안 되면 지금 문자.
- **경비실 문자 확인(two_step)**: 인증번호 알림톡 먼저 → 안 되면 문자. 보내는 번호는 `CGG_SMS_FROM`, 없으면 `SMS_FROM`(비밀값 이름만).
- 네 곳 모두: 채널(`pfId` 또는 `PF_ID`)이나 코드가 없으면 알림톡을 시도하지 않아요. 설정 칸(`ata_cfg`)이 아직 없어도 문자로 나가요.

## 대표님이 할 일 — 템플릿 코드 넣기
**관리 화면(v4.1) 알림톡 설정에서** 넣는 게 제일 쉬워요. 화면이 아직이면 SQL 로:
1. **솔라피** → 카카오 알림톡 → **템플릿 목록**에서 통과된 템플릿의 **템플릿 ID**(`KA01TP…`)를 복사해요. (비밀값 아니에요)
2. **수파베이스 → SQL Editor** 에 아래를 붙여 넣고 `<…>` 만 복사한 ID 로 바꿔요. (아직 없는 줄은 지워도 돼요)
   ```sql
   update wash_hq set ata_cfg = jsonb_build_object('tpl', jsonb_strip_nulls(jsonb_build_object(
     'auth',       '<차곳간_인증번호 ID>',
     'cash_done',  '<차곳간_충전완료 ID>',
     'pay_done',   '<차곳간_결제완료 ID>',
     'intake',     '<차곳간_입고안내 ID>',
     'release',    '<차곳간_출고안내 ID>',
     'extra_work', '<차곳간_추가작업 ID>',
     'bill',       '<차곳간_청구서 ID>',
     'deposit_ok', '<차곳간_입금확인 ID>'
   ))) where id = 1;
   ```
3. **Run** → 1분 안에 네 서버가 새 코드로 보내요. 되돌리기: `update wash_hq set ata_cfg = '{}'::jsonb where id = 1;`
- 채널 ID 는 이미 있는 비밀값 `PF_ID` 를 써요. **체크·딜러·경비실 함수에도 `PF_ID` 가 있어야** 해요(수파베이스 비밀값은 프로젝트 전체 공통이라 보통 이미 있어요).

## 토스페이먼츠 결제 — 지금 켜져 있나요?
- 서버 코드는 준비돼 있어요(`payStart`·`payConfirm`, 비밀값 `TOSS_SECRET_KEY`, 관제센터 스위치 `wash_hq.pg_on`).
- 하지만 기본 안내 글이 「**PG사 승인 대기 중입니다. 지금은 계좌이체로만 충전하실 수 있습니다.**」라서, 계약·열쇠가 끝났다는 흔적은 저장소에 없어요.
- 확인하는 법 (대표님, SQL Editor): `select pg_on, pg_provider, pg_note from wash_hq where id = 1;` → `pg_on` 이 true 이고, Edge Functions → Secrets 에 `TOSS_SECRET_KEY` 가 있어야 켜진 거예요.
