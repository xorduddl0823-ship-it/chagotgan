# 알림톡 전환 (문자 비용 줄이기) — 워시 sb6 · 2026-10-15 · 배포 전

> 규칙 5-6 (9b9ea18): 모든 사용자 제품 안내는 **알림톡 먼저, 실패하면 솔라피가 문자로 대신.** 단가: 알림톡 13원 · 단문 18원 · 장문 45원.
> 확정본 원문: `알림톡/00_확정본_13개_원문.md` (통과 8 · 반려 5). 반려 5개의 새 문안: `서버/설계/09`. 앞으로 문안·템플릿은 **알림톡 방**, 발송 장치는 **서버 방**.

## 한 줄 요약
워시 서버 **sb6** = 「알림톡 먼저 → 안 되면 확정본 대체 문구로 문자」(`noticeAta`). 변수 이름·대체 문구를 **확정본과 글자까지** 맞췄어요(sb5 는 맞추기 전 판이라 쓰지 않아요). 템플릿 코드는 관제센터 설정 칸(`wash_hq.ata_cfg`)에서 읽고, **비어 있으면 지금처럼** 동작해요 → 먼저 올려도 아무것도 바뀌지 않다가, 코드를 넣는 순간부터 알림톡으로 나가요.

## 통과 8개 — 어디서 무엇으로 나가나 (sb6)
| 템플릿 (키) | 받는 사람 | 보내는 곳 | sb4 까지 | sb6 + 코드 넣으면 |
|---|---|---|---|---|
| 인증번호 (`otp`) | 가입·비밀번호 찾기 하는 사람 | `sendCode` → `otpSend` | 문자 | **알림톡**, 안 되면 대체 문구 문자 |
| 충전완료 (`charge`) | 업체 대표 | 카드 충전 `payDone`(cash) · 본사 캐시 넣기 `hqCashAdd`(유료) | 업체엔 안 보냄 | **알림톡**(코드 없으면 안 보냄 — 문자 비용 안 늚) |
| 결제완료 (`pay`) | 업체 대표 | 카드 이용요금 `payDone`(plan) · 본사 「입금됨」 표시 `hqPayMark`(paid) | 업체엔 안 보냄 | 위와 같음 |
| 입고안내 (`in`) | 딜러·상사 | 워시 화면 → `sendMsg` | 업체 템플릿 알림톡 또는 문자 | 화면이 `ataKey:"in"` + 확정본 변수 → **본사 채널 알림톡** |
| 출고안내 (`out`) | 딜러·상사 | 〃 | 〃 | `ataKey:"out"` |
| 추가작업 (`add`) | 딜러·상사 | 〃 | 〃 | `ataKey:"add"` |
| 청구서 (`bill`) | 거래처 | 〃 | 〃 | `ataKey:"bill"` |
| 입금확인 (`deposit`) | 돈 보낸 거래처 | 〃 (업체가 입금을 확인했을 때) | 〃 | `ataKey:"deposit"` |

- **화면이 보낸 변수가 확정본과 하나라도 다르거나 빠지면**, 알림톡을 시도하지 않고 확정본 대체 문구로 문자를 보내요(실패로 끝나지 않게). 기록에 「ataKey vars missing」이 남아요.
- 요금(업체 캐시)은 알림톡/문자가 정해진 **뒤에** 한 번만 깎여요.

## 대표님이 할 일 — 템플릿 코드 넣기 (3단계)
1. **솔라피** → 카카오 알림톡 → **템플릿 목록**에서 통과된 템플릿을 누르면 보이는 **템플릿 ID**(`KA01TP…`)를 복사해요. (비밀값 아니에요)
2. **수파베이스 → SQL Editor** 에 아래를 붙여 넣고 `<…>` 만 복사한 ID 로 바꿔요. (아직 없는 줄은 지워도 돼요)
   ```sql
   update wash_hq set ata_cfg = jsonb_build_object('tpl', jsonb_strip_nulls(jsonb_build_object(
     'otp',     '<차곳간_인증번호 ID>',
     'charge',  '<차곳간_충전완료 ID>',
     'pay',     '<차곳간_결제완료 ID>',
     'in',      '<차곳간_입고안내 ID>',
     'out',     '<차곳간_출고안내 ID>',
     'add',     '<차곳간_추가작업 ID>',
     'bill',    '<차곳간_청구서 ID>',
     'deposit', '<차곳간_입금확인 ID>'
   ))) where id = 1;
   ```
3. **Run** → 1분 안에 서버가 새 코드로 보내요. 되돌리기: `update wash_hq set ata_cfg = '{}'::jsonb where id = 1;`
- 채널 ID 는 이미 있는 비밀값 `PF_ID` 를 써요. (다른 채널이면 `jsonb_build_object('pfId','<채널 ID>','tpl', …)`)
- 관제센터 화면이 생기면 SQL 대신 화면에서(서버 창구 `hqAtaGet`·`hqAtaSave` 준비됨).

## 토스페이먼츠 결제 — 지금 켜져 있나요?
- 서버 코드는 준비돼 있어요(`payStart`·`payConfirm`, 비밀값 `TOSS_SECRET_KEY`, 관제센터 스위치 `wash_hq.pg_on`).
- 하지만 기본 안내 글이 「**PG사 승인 대기 중입니다. 지금은 계좌이체로만 충전하실 수 있습니다.**」라서, 계약·열쇠가 끝났다는 흔적은 저장소에 없어요.
- 확인하는 법 (대표님, SQL Editor): `select pg_on, pg_provider, pg_note from wash_hq where id = 1;` → `pg_on` 이 true 이고, Edge Functions → Secrets 에 `TOSS_SECRET_KEY` 가 있어야 켜진 거예요.
