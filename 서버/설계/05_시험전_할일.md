# 통합 로그인 시험 전 할 일 — 대표님 PC 에서 한 번 (2026-10-15)

> 운영 서버는 그대로(워시 sb1 · 체크 v21 · 경비실 v1.1)예요. 이 장은 **출입 명단(`cgg_access`)에 시험 번호 세 개를 넣는 것**만 해요.
> 번호는 이 문서에 적지 않아요. 아래 `<…>` 칸에 대표님이 직접 넣고 Run 해 주세요.

## 0. 먼저 확인 (번호마다)
| 번호 | 열릴 제품 | 미리 되어 있어야 하는 것 |
|---|---|---|
| 대표님 번호 | 워시 + 체크 | 워시에 가입돼 있음 · 체크 검사소 직원으로 등록돼 있음 |
| 서브 번호 | 워시만 | 워시 **가입 코드로 직접 가입** (가입하면 자기 사업장의 **대표** 직급이 돼요 — 서버 코드에서 확인함) |
| 회사 대표번호 | 체크만 | 체크 검사소 직원으로 등록 + **체크에 한 번 로그인해서 비밀번호가 정해져 있음** → 아래 0-1 로 넣어요 |

- 통합 입구 비밀번호는 **원래 쓰던 비밀번호 그대로**예요. 워시 권한이 있으면 워시 비밀번호로 먼저 확인해요. 대표님 번호는 워시·체크 비밀번호를 같게 맞춰 두시면 편해요.

## 0-1. 체크 시험 직원 한 명 넣기 (「체크만」 번호용 · 2026-10-15 추가)
운영 체크 화면 v21 의 「직원 권한 › + 사람 추가」는 아직 동작하지 않고, 체크 서버에도 직원을 넣는 창구가 없어요. 그래서 SQL 로 넣어요.

**추천: 실제 검사소(가온)가 아니라 「시험검사소(TEST)」를 새로 만들어 그 안의 대표(owner)로 넣어요.**
> ⚠ **가온 대표 계정은 시험에 쓰지 않아요.** 「체크만」 시험 번호는 가온 대표 번호와 **끝 4자리가 같은 다른 번호**예요(결정 기록 2026-10-15).
> - 서버는 사람을 **번호 전체(11자리)** 로만 찾아요. 끝 4자리나 이름으로 찾는 곳은 없어서 두 계정이 섞이지 않아요(서버 방 확인).
> - 다만 화면·기록에는 번호가 `010-****-끝4자리` 로 가려져 보여서 **둘이 똑같아 보여요.** 그래서 `<이름>` 칸에는 가온 대표와 다른 이름(예: 「시험대표」)을 넣어 주세요.
> - 경비실 로그인 때 「010-****-끝4자리로 확인 번호를 보냈어요」가 떠도, 시험 번호로 들어간 거면 그 번호로 와요.
- 시험 계정이 실제 손님 자료(가온의 청구서·딜러·입금)를 보거나 고칠 수 없어요. TEST 안의 자료만 보여요.
- 대표(owner) 직급이라 시험검사소 안에서는 모든 화면을 눌러 볼 수 있어요.
- 팝빌·문자 같은 바깥 연결은 시험검사소에 설정이 비어 있어서 실제로 나가지 않아요(누르면 「설정이 비어 있다」 안내가 나와요).

**① 아래 SQL 의 `<…>` 두 칸만 바꿔서 Run** (여러 번 Run 해도 안전 · 번호가 이상하면 멈춤)
```sql
-- 체크 시험 직원 한 명 넣기 (시험 검사소 TEST 에, 여러 번 Run 해도 안전)
do $$
declare
  v_phone text := '<체크 시험 번호 숫자만>';
  v_name  text := '<이름 — 가온 대표와 다른 이름, 예: 시험대표>';
  t text;
begin
  if v_phone !~ '^01[0-9]{8,9}$' then
    raise exception '번호를 숫자만 01012345678 처럼 넣어 주세요';
  end if;
  -- ① 시험 검사소(TEST) — 실제 손님 자료가 있는 검사소와 따로
  if not exists (select 1 from check_office where code = 'TEST') then
    begin
      insert into check_office (code, name) values ('TEST', '시험검사소');
    exception when not_null_violation then
      select data_type into t from information_schema.columns
       where table_schema = 'public' and table_name = 'check_office' and column_name = 'id';
      execute format('insert into check_office (id, code, name) values (gen_random_uuid()::%s, %L, %L)', t, 'TEST', '시험검사소');
    end;
  end if;
  -- ② 시험 직원 — 비밀번호는 비워 둠 (체크에 처음 로그인할 때 적는 비밀번호로 정해짐)
  if exists (select 1 from check_user where phone = v_phone and office_id = (select id from check_office where code = 'TEST')) then
    update check_user set name = v_name, role = 'owner', active = true
     where phone = v_phone and office_id = (select id from check_office where code = 'TEST');
  else
    begin
      insert into check_user (office_id, phone, name, role, active)
      values ((select id from check_office where code = 'TEST'), v_phone, v_name, 'owner', true);
    exception when not_null_violation then
      select data_type into t from information_schema.columns
       where table_schema = 'public' and table_name = 'check_user' and column_name = 'id';
      execute format('insert into check_user (id, office_id, phone, name, role, active) values (gen_random_uuid()::%s, (select id from check_office where code = %L), %L, %L, %L, true)',
                     t, 'TEST', v_phone, v_name, 'owner');
    end;
  end if;
  raise notice '끝: % 님을 시험검사소(TEST)의 대표(owner)로 넣었어요', v_name;
end $$;
```
- 「끝: … 넣었어요」가 나오면 성공이에요. 오류가 나면 그 글자를 서버 방에 그대로 알려 주세요.

> ⚠ **SQL 을 Run 한 직후 바로 그 번호로 체크에 로그인하세요. 그 사이에 다른 일은 하지 마세요.**
> **비밀번호가 비어 있는 동안에는 번호를 아는 사람 누구나 먼저 로그인해서 비밀번호를 정할 수 있어요.** (운영 체크 v21 의 빈틈 — 새 판 v26 부터는 문자 확인으로 막혀요)

**② 바로 이어서 체크에 한 번 로그인해 비밀번호 정하기** (check.cgg.co.kr → 그 번호 + 새 비밀번호 **6자 이상**)
- 비밀번호가 비어 있는 계정은 **처음 적는 비밀번호가 그대로 정해져요.** 그래서 넣자마자 대표님이 먼저 로그인해 주세요.
- 이 과정이 끝나야 통합 입구(경비실)에서도 이 번호가 들어가져요 (경비실은 이미 정해진 비밀번호로만 확인해요).

**③ 그다음 아래 1번 SQL 로 출입 명단에 `{check}` 로 넣기**

**시험 뒤 빼기**

## 1. 명단에 넣기 (수파베이스 → SQL Editor → 붙여 넣고 `<…>` 만 바꿔서 Run)
```sql
insert into cgg_access (phone, name, products) values
  ('<대표님 번호 숫자만>',   '대표님',   '{wash,check}'),
  ('<서브 번호 숫자만>',     '서브',     '{wash}'),
  ('<회사 대표번호 숫자만>', '회사대표', '{check}')
on conflict (phone) do update
  set products = excluded.products, name = excluded.name, active = true,
      fail_count = 0, locked_until = null, updated_at = now();
```
- 번호는 `01012345678` 처럼 **숫자만** 넣어요 (`-` 없이).
- 여러 번 Run 해도 안전해요 (같은 번호면 고쳐 쓰기).

## 2. 잘 들어갔는지 보기
```sql
select name, products, active from cgg_access order by created_at;
```
- 세 줄이 보이고, 제품이 위 표와 같으면 끝이에요.

## 시험할 때 알아 둘 것 (운영 워시가 sb1 이라서)
- 통합 입구로 들어오면 워시에는 휴대폰이어도 **「PC」로 기록**돼요. 그래서 **같은 번호로 켜 둔 워시 PC 로그인이 끊길 수 있어요.** (대표 직급이라 들어가는 데는 문제없어요)
- 「워시만 계정으로 체크 서버를 부르면 거절」은 체크 v21 이 명단을 보지 않아서 이번 시험에서는 확인하지 않아요 (체크 v24 올린 뒤).
- 시험이 끝나고 명단에서 빼려면: `update cgg_access set active = false where name in ('대표님','서브','회사대표');`
