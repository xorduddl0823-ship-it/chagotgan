## 한 줄 요약
통합 입구에서 한 번 로그인하면 **그 번호에 허락된 제품(워시·체크)만 열리는 창구**를 만들었어요.
**워시만 가진 계정이 체크 서버를 부르면 거절**되는 것까지 가짜 서버로 시험해서 모두 통과했어요(34개).
아직 수파베이스에는 올리지 않았어요. 올리는 건 대표님이 해 주셔야 해요(아래 「대표님이 하실 일」).

### 2026-10-14 보안 방 검사 반영 (cgg-api v1.1 · check-api v22 수정)
- **잠금 구멍 막음**: 틀린 횟수를 데이터베이스 안에서 한 번에 올리도록 바꿨어요(SQL 함수 `cgg_attempt`). 한꺼번에 여러 번 보내도 5번에서 잠겨요. → **SQL 을 다시 한 번 실행**해야 해요(여러 번 실행해도 안전).
- **배달 기사 가입 구멍 막음**: 이제 기사가 [계정 만들기]를 하면 바로 들어가지지 않고 **사무실 승인 대기**가 돼요. 사무실 화면의 기사 계정에서 [사용]으로 바꿔 주면 로그인돼요. 같은 이름도 그 검사소 안에서만 찾아서, 다른 검사소 기사 이름을 가로챌 수 없어요.
  - ⚠️ 체크 손님에게 달라지는 점: 새 기사는 사무실이 한 번 승인해 줘야 해요. 이미 쓰고 있는 기사는 그대로예요.
- 시험 41개 모두 통과, SQL 은 실제 Postgres 에서 두 번 실행해 확인.

### 정한 것 두 가지 (총괄 방 결정 기록에 남겨 주세요)
1. **경비실은 wash-api 안이 아니라 새 서버 기능 `cgg-api`로 따로 둬요.**
   - 이유: wash-api 최신 코드가 아직 저장소에 없고, 워시 서버 이사로 곧 통째로 바뀌어요. 따로 두면 서로 덮어쓰지 않아요.
   - 그래서 통합 입구 화면이 부르는 주소를 `wash-api` → `cgg-api` 로 한 줄 바꿔야 해요 (홈페이지 방 요청서 아래에 있음).
2. **「쓸 수 있는 제품(products)」 칸은 기존 계정 표에 붙이지 않고, 새 「출입 명단」 표(`cgg_access`)에 둬요.**
   - 이유: 계정 표에는 실제 손님 자료가 있어서 시험 없이 바꾸면 안 돼요(규칙). 그리고 워시·체크 계정 표가 따로따로라 한 곳에 모으기도 어려워요.
   - 명단은 **휴대폰 번호 한 줄 = 한 사람**이에요. 예: `{wash}`, `{check}`, `{wash,check}`. 관리는 넣을 수 없게 막아 뒀어요(규칙 1-3).

### 어떻게 동작하나요?
- **로그인**: 휴대폰 번호 + 비밀번호. 비밀번호는 **원래 워시나 체크에서 쓰던 것 그대로** 써요. 새 비밀번호를 만들지 않아요.
  - 워시 권한이 있으면 워시 비밀번호로 먼저 확인하고, 안 맞으면 체크 비밀번호로 확인해요.
  - 워시 비밀번호가 틀렸고 체크 비밀번호로 들어왔다면 워시는 열리지 않아요. 두 제품 비밀번호를 같게 맞춰 두시면 편해요.
- **문자 6자리**: 명단에서 `two_step` 을 켠 번호만 문자 확인을 거쳐요. 기본은 꺼져 있어요.
- **5번 틀리면 10분 잠금**이에요.
- **권한을 빼면 바로 반영**돼요. 명단에서 체크를 빼면 다음 화면 열 때 체크 탭이 사라지고, 체크 서버도 거절해요.

### 체크 서버가 거절하는 경우 (v22)
| 들어온 열쇠 | 명단에 체크 있음 | 명단에 있지만 체크 없음 / 막힘 | 명단에 없음 |
|---|---|---|---|
| 체크 자체 로그인(`chk_…`) | 통과 | **거절** | 통과 (지금 쓰는 체크 손님이 멈추지 않게) |
| 워시 로그인 열쇠 | 통과 | **거절** | **거절** ← 「워시만 가진 계정」이 막히는 곳 |
| 관리(ADMIN) 열쇠 | 통과 | 통과 | 통과 |

## 대표님이 하실 일 (순서대로)

> 배포 전에 **보안 방 검사**를 먼저 받아 주세요(규칙 2-4). 아래 1~5는 검사를 통과한 뒤에 해요.

**1. 표 만들기 (1분)**
1. 수파베이스 누리집 → 프로젝트 `chagotgan-wash`
2. 왼쪽 메뉴 **SQL Editor** → **New query**
3. `서버/sql/01_경비실_표_만들기.sql` 내용을 통째로 붙여 넣고 **Run**
4. "Success" 가 나오면 끝이에요. 기존 표는 바뀌지 않아요.

**2. 시험 계정 2~3개 넣기**
- 같은 SQL Editor 에서 아래처럼 실행해요. 번호와 이름은 실제 시험할 번호로 바꿔 주세요.
  ```sql
  insert into cgg_access (phone, name, products) values
    ('01011112222', '시험-워시만', '{wash}'),
    ('01033334444', '시험-체크만', '{check}'),
    ('01055556666', '시험-둘다',   '{wash,check}')
  on conflict (phone) do update set products = excluded.products, name = excluded.name, active = true;
  ```
- 준비 조건:
  - 워시를 줄 번호는 **워시에 가입된 번호**여야 해요.
  - 체크를 줄 번호는 **체크 검사소 직원으로 등록**돼 있고, 체크에 **한 번 로그인해서 비밀번호가 정해져 있어야** 해요.
- 나중에 권한을 바꿀 때: `update cgg_access set products='{wash,check}' where phone='01011112222';`

**3. 경비실(cgg-api) 올리기**
1. 왼쪽 메뉴 **Edge Functions** → **Deploy a new function** → **Via Editor**
2. 이름에 `cgg-api` 를 적어요.
3. 기본 코드를 지우고 `서버/0_차곳간_경비실_cgg-api_v1.ts` 내용을 붙여 넣어요.
4. **Verify JWT(로그인 표 확인)** 를 **끔**으로 두고 **Deploy** 를 눌러요. 다른 서버와 같은 설정이에요.
5. 새 비밀값은 필요 없어요. 문자 확인(`two_step`)을 쓸 때만 비밀값 `CGG_SMS_FROM`(문자 보내는 번호)을 넣어 주세요.

**4. 체크 서버 v22 올리기 (3번 다음에)**
1. **Edge Functions** → `check-api` → **Code** 탭
2. 내용을 `서버/2_차곳간체크_서버_check-api_v22.ts` 로 바꾸고 **Deploy**
3. 문제가 생기면 저장소의 v21 코드로 다시 올리면 원래대로 돌아가요.
- ⚠️ v22를 올리면 **워시 열쇠로 체크를 쓰던 사람은 명단에 체크가 있어야** 해요. 관리(ADMIN)는 상관없어요.
  그런 분이 있으면 2번에서 명단에 같이 넣어 주세요.

**5. wash-api 코드 보내 주기 (워시 쪽 문지기를 만들려면 필요해요)**
1. **Edge Functions** → `wash-api` → **Code** 탭 → 내용 전부 복사
2. 메모장에 붙여 `wash-api.ts` 로 저장 → `서버/` 서랍에 넣거나 이 방에 첨부
3. `dealer-api` 도 같은 방법으로 보내 주세요.

## 아직 남은 것 (숨기지 않고 적어요)
- **워시 서버(wash-api) 쪽 문지기는 아직 없어요.** 코드가 없어서예요. 지금은 명단에서 워시를 빼도, 그 사람이 워시 주소(app.cgg.co.kr)로 직접 로그인하면 들어가져요. 통합 입구에서는 안 보여요. wash-api 코드가 오면 체크와 똑같이 막을게요.
- **표 보안(RLS) 점검**: 새 표 3개는 잠가 뒀어요. 기존 `wash_*`·`check_*` 표가 잠겨 있는지는 수파베이스 화면에서 봐야 해서, 다음 단계에서 확인 방법을 따로 안내할게요.
- 누군가 남의 번호로 일부러 5번 틀리면 그 사람이 10분 동안 못 들어와요. 시험 단계에서는 이대로 두고, 문제가 되면 바꿀게요.
