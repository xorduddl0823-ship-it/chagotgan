# 워시 서버 sb23 올리기 안내 (대표님용 · 2026-10-18)

> **sb23 = sb22 + 대표님 규칙 «입금 전 세금계산서 발급 없음»**(체크 v47과 같음 · 예외 없음).
> 워시 서버는 **sb23 한 판만** 올리시면 돼요(sb22 관리 인증번호 알림톡도 들어 있어요). **SQL 21을 먼저** 실행해요.

## 무엇이 바뀌나요
1. **업체 → 딜러 세금계산서** — 세금계산서 화면의 묶음(발행처 × 딜러)이나 청구서로 발행해요. 그 안의 차가 **모두 입금 완료**이고, 계산서 합계가 장부 일감 합계(부가세 붙는 청구서면 +10%)와 같을 때만 발행돼요. **같은 차로는 한 번만** 발행돼요(두 번 빨리 눌러도 한 장).
   - 입금 전이면 «아직 입금 전입니다 (남은 금액 ○원)»이 나오고, 캐시·발행 건수도 깎지 않아요.
   - 예전에 만든 청구서(입금 상태를 셀 수 없는 것)는 청구서를 다시 만든 뒤 발행해요.
2. **본사 → 업체 세금계산서(관리)** — 결제 기록에서 고른 결제가 **결제 완료**이고 금액이 같을 때만 발행돼요. 같은 결제로 두 번은 안 돼요(«그대로 다시 보내기»도 안 됨).

## 함께 올려야 하는 화면 (꼭 같이)
- **워시 화면 v135**(워시 방) — 청구서의 «세금계산서» 단추가 청구서 보기코드를 함께 보내요.
- **관리 화면 새 판**(관리 방) — 세금계산서 보낼 때 결제 기록 번호를 함께 보내요.
- 서버만 먼저 올리면, 옛 화면에서는 세금계산서 발행이 «어느 청구서/결제인지 알 수 없습니다»로 멈춰요(잘못 발행되지는 않아요).

## 대표님이 하실 일
1. **SQL 21 실행** — 수파베이스 → SQL Editor에 `서버/sql/21_워시_세금계산서_한번만.sql`(21줄)을 붙여 넣고 Run. 마지막 줄 «있음 = true»면 끝이에요.
   - 같은 차로 세금계산서가 두 번 나가거나, 두 번 빨리 눌러 두 장 나가는 것을 막는 표예요. 이게 없으면 sb23은 실제 발행을 하지 않아요.
2. `서버/1_차곳간워시_서버_wash-api_sb23.ts`(6,733줄)를 wash-api에 올려요(Verify JWT 끔).
3. 워시 방 · 관리 방이 알려 드리는 화면을 같은 날 올려요.

## 올린 뒤 확인
- 워시: 입금 안 된 일감이 있는 청구서로 «세금계산서» → «아직 입금 전입니다»가 나오면 맞아요. 모두 입금 완료된 청구서는 발행돼요.
- 관리: «결제 완료»가 아닌 결제로는 발행되지 않아요.

## 되돌리고 싶을 때
- `서버/1_차곳간워시_서버_wash-api_sb22.ts`(또는 지금 운영 중인 sb21)를 다시 올리면 돼요. SQL이 없어서 따로 되돌릴 것은 없어요.

## 바뀐 곳 (서버 방 기록)
- `pbIssue` 요청(JSON)에 `bill`(청구서 보기코드 24자 · 워시 v135 모양 `{month, key, recIds, …, code}` 이면 `bill.code`) 필수 → `taxBillGate`: 이 업체 · kind bill · `billLive` 로 다시 셈해 `full`(모두 «수금완료») · `doc.totalAmount` = 장부 줄 합계(`sumAmt` · 보안 낮음 1) · 같은 청구서 성공 기록이 있으면 거절(보안 낮음 2) · 서버가 `remark1` 앞에 «청구서 {code} ·» 를 붙여 발행. 아니면 `{ok:false, error, unpaid:true}` (캐시·건수 깎기 전).
- `hqTaxIssue` body 에 `payId` 필수 → `wash_payments` 그 업체 · `status «paid»` · 결제 금액 = 계산서 합계(공급가액 + 부가세) · 같은 결제로 성공 기록이 있으면 거절(force 무시 · 찾을 때 «결제 {payId} ·» 까지 — 보안 참고) · `remark1` 앞에 «결제 {payId}».
- 시험: `서버/시험/세금계산서_입금뒤_워시_sb23_시험.ts` 24개 통과. 기존 워시 시험은 sb22와 같고, sb15 시험 2개(번호 겹침·본사 확인 전)는 이제 청구서 확인에서 먼저 멈춰서 달라져요(발행 안 되는 것은 같음).
- 워시 v135 묶음: `bill.recIds`(입고 기록 id · 300개까지)를 서버 장부로 다시 읽어 이 업체 · 모두 «수금완료» · 계산서 합계 = 차 total 합계(부가세 포함 · 화면 taxGroups 와 같음). 화면의 amount·paid·left 는 안 씀. 비고 앞 «묶음 {달} {N}대 ·».
- 한 번만(SQL 21 `wash_tax_rec` · 기본 키 shop+rec_id): 실제 발행이면 차마다(청구서 코드 길은 그 청구서 줄의 차, 본사는 «pay:결제번호») 먼저 넣고, 겹치면 거절 · 발행 실패면 지움 · 시험 발행은 잡지 않음 · 표가 없으면 실제 발행 안 함.
- 남은 것(보안 낮음 · 다음 판): 받는 사업자번호가 그 딜러 것인지 대조(워시 거래처 사업자번호가 서버 어디에 있는지 워시 방과 확인 뒤).
