# 체크 서버 v40 → v41 올리기 안내 (대표님용 · 2026-10-18 · 보안 검사 대기)

## 결론
- TEST에서 «은행 거래내역 엑셀 가져오기»가 «입금을 넣지 못했습니다»로 멈췄던 것을 고쳤어요.
- 순서는 **① SQL 15 → ② 체크 서버 v41**이에요. 화면은 그대로 두셔도 돼요.
- v41에는 v40의 모든 것이 들어 있어요. v40을 아직 안 올리셨다면 `배포안내_체크_v36에서_v40.md`의 SQL 14까지 먼저 해 주세요. 그다음 v40은 건너뛰고 v41을 올리시면 돼요.

## 대표님이 하실 일
1. **SQL 15 실행**
   - 수파베이스 → SQL Editor를 열어요.
   - `서버/sql/15_체크_입금엑셀_고침.sql` 내용을 붙여 넣고 Run을 눌러요.
   - 마지막 표의 세 줄이 모두 «됨»이면 끝이에요.
   - «안 됨»이 보이면, 그 화면 사진을 서버 방에 보내 주세요(지운 자료는 없어요).
   - 여러 번 실행해도 안전해요.
2. **체크 서버 v41 올리기**
   - `서버/2_차곳간체크_서버_check-api_v41.ts`를 check-api에 올려요. 지금까지와 같은 방법이에요(Verify JWT 끔).

## 무엇이 문제였을 수 있나 (세 갈래 모두 막았어요)
- **빈 칸 제한**: 입금 표가 «계좌»나 «잔액» 칸을 꼭 채워야 하게 되어 있는데, 엑셀 줄은 그 칸을 비워서 보냈어요.
  - SQL 15가 그 칸을 비워도 되게 바꿔요.
  - v41은 쓰는 계좌가 하나면 그 계좌를 채워 넣어요. 잔액도 넣어요(엑셀에 없으면 0).
- **값 제한**: 입금 표가 «가져온 곳»에 «팝빌»만 받게 되어 있었을 수 있어요. SQL 15가 «엑셀»도 받게 풀어요.
- **중복 막기 규칙 없음**: 같은 줄 두 번 막는 규칙이 표에 없으면 넣기가 통째로 멈춰요.
  - v41은 그 규칙 없이도 넣어요(겹침은 미리 걸러요).
  - SQL 15는 그 규칙을 만들어요. 은행 자동 조회(팝빌)도 이 규칙이 있어야 제대로 들어와요.

## 그래도 실패하면
- 화면에 «까닭: 빈 칸 제한 / 값 제한 / 연결 제한 / 중복 / 표 모양 / 연결» 가운데 하나가 쉬운 말로 나와요.
- 그 글을 그대로 서버 방에 알려 주시면 바로 찾을 수 있어요.
