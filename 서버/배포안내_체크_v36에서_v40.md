# 체크 서버 v36 → v40 올리기 안내 (대표님용 · 2026-10-18 · 보안 통과)

## 결론
- 체크 서버는 **v40 한 판**만 올리시면 돼요.
  - v37·v38·v40는 따로 올리지 않아요. v40에 그 모든 것이 들어 있어요.
- 순서: **① SQL 14 → ② 체크 서버 v40 → ③ 체크 화면(체크 방이 알려 드리는 최신 · v47·v48)**
- **SQL 14는 꼭 v40보다 먼저** 해 주세요. 그래야 입금확인 알림이 «입금마다 한 번»만 가고, 되돌린 입금을 자동 맞추기가 다시 잡지 않아요.

## 대표님이 하실 일
0. **국세청 열쇠(NTS_API_KEY)**: 이미 끝났어요. 할 일 없어요.
1. **SQL 14 실행**
   - 수파베이스 → SQL Editor를 열어요.
   - `서버/sql/14_체크_입금처리.sql` 내용을 붙여 넣고 Run을 눌러요.
   - 마지막 표의 두 줄이 모두 `t`(있음)면 끝이에요.
   - 여러 번 실행해도 안전하고, 지우는 자료는 없어요.
   - SQL 13을 아직 안 하셨다면 SQL 13 먼저 하고 SQL 14를 해 주세요.
2. **체크 서버 v40 올리기**
   - `서버/2_차곳간체크_서버_check-api_v40.ts`를 check-api에 올려요. 지금까지와 같은 방법이에요(Verify JWT 끔).
3. **체크 화면 v47 올리기** (체크 방이 알려 드리는 파일)

## v40에 새로 들어간 것 (v36과 비교)
- **단가 구간(v40)**: 화면에서 «○월 ○일부터 국산 ○원» 단가를 넣고 고치고 지울 수 있어요(대표만 · 하나는 남김).
- **보안 고침(v40)**: 남의 검사소 청구서 줄·배달 사진을 번호만 알아도 볼 수 있던 구멍을 막았어요.
- **v39 고침(10/18 TEST)**: 등록증 아래 «E-mail·전화» 작은 표도 읽어요. 국세청 열쇠를 두 가지 방식으로 보내 봐요(한쪽이 안 되면 다른 쪽).
- **사진 읽기 고침**: 길고 비스듬한 사업자등록증도 읽어요. 여백의 전화·이메일·개업일도 읽어요.
- **사업자번호 확인**: 국세청에 «영업 중 · 휴업 · 폐업 · 없는 번호»와 대표자·개업일이 맞는지 물어봐요. 대표만 쓸 수 있고, 하루 100번이에요.
- **입금 처리**
  - 손으로 청구서에 맞추기·되돌리기, 갈래 바꾸기, 휴지통 지우기·되살리기, 은행 엑셀 가져오기가 돼요.
  - 엑셀과 은행 자동 조회로 같은 입금이 두 번 들어오지 않게 막아요.
  - 맞추기·되돌리기·갈래는 직원도 할 수 있어요. 지우기·되살리기·엑셀은 대표만 할 수 있어요.

## 올린 뒤 TEST 검사소에서 한 번 해 볼 것
- **사업자번호 확인**: 거래처에서 사업자등록증 사진으로 상사를 채운 뒤 «국세청 확인»을 눌러 봐요.
  - «영업 중»이 보이면 열쇠가 잘 들어간 거예요.
  - «국세청 열쇠가 아직 등록 중이거나 맞지 않아요»가 보이면, 새 열쇠는 등록까지 1~2시간(길면 하루) 걸리니 조금 뒤 다시 눌러 봐요. 그래도 같으면 공공데이터포털 «마이페이지 → 활용신청 현황»에서 «승인»인지 봐 주세요.
  - «국세청에 연결하지 못했어요»가 보이면 잠시 뒤 다시 해 봐요.
- **입금**: 입금 하나를 손으로 맞췄다가 되돌려 봐요. 청구서 받은 금액이 같이 늘었다 줄어들면 돼요.

## SQL 14 전에 v40이 먼저 올라가면?
- 화면은 깨지지 않아요.
- 다만 두 가지가 빠져요.
  - 되돌린 입금을 자동 맞추기가 다시 잡을 수 있어요.
  - 되돌렸다가 다시 맞추면 입금확인 알림이 한 번 더 갈 수 있어요.
- 그래서 SQL 14를 먼저 해 주세요.
