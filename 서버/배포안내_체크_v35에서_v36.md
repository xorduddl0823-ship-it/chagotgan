# 체크 서버 v35 → v36 올리기 안내 (대표님용 · 2026-10-18)

## 결론
- 지금 올리시는 **v35는 그대로 쓰시면 돼요.** v36은 v35를 모두 담고 있어서, 나중에 v35 위에 v36을 올려도 문제없어요.
- v36 올리는 순서는 **① SQL 13 → ② 체크 서버 v36 → ③ 체크 화면 v46**이에요.
- 순서를 바꿔 v36을 SQL 13보다 먼저 올려도 **깨지지 않아요.** 새 칸만 숨겨져 있다가, SQL 13을 돌리면 그때 보여요.

## 대표님이 하실 일 (보안 통과 연락을 받은 뒤)
1. **SQL 13 실행**
   - 수파베이스 → SQL Editor를 열어요.
   - `서버/sql/13_체크_거래처_한화면.sql` 내용을 붙여 넣고 Run을 눌러요.
   - 마지막 표의 네 줄이 모두 `t`(있음)면 끝이에요.
   - 여러 번 실행해도 안전하고, 지우는 자료는 없어요.
2. **체크 서버 v36 올리기**
   - `서버/2_차곳간체크_서버_check-api_v36.ts`를 check-api에 올려요. 지금까지 올리던 방법과 같아요(Verify JWT 끔).
3. **체크 화면 v46 올리기** (체크 방이 알려 드리는 파일)

## SQL 13 전에 v36이 먼저 올라가면?
| 기능 | SQL 13 전 | SQL 13 뒤 |
|---|---|---|
| 지금까지 되던 것 전부(청구서·입금·도착 알림·사진 읽기 등) | 그대로 돼요 | 그대로 돼요 |
| 계산서 «나중에 정할게요» · 상사/딜러 이메일·업태·종목 칸 | 화면에서 **숨겨져요**(서버가 «아직 없음»이라고 알려 줘요) | 보여요 |
| 딜러 «마지막 거래일» | 보여요 | 보여요 |
| 입금 금액 더하기 | 예전 방식(아주 드물게 동시에 들어온 입금 하나가 빠질 수 있음) | 한 번에 더해서 빠지지 않아요 |

## 되돌리고 싶을 때
- v36에 문제가 있으면 v35 파일(`서버/2_차곳간체크_서버_check-api_v35.ts`)을 다시 올리면 돼요.
- SQL 13으로 생긴 칸은 v35가 쓰지 않으니, 그대로 두어도 괜찮아요.
