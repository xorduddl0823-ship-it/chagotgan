- 순서는 **① SQL 15 → ② SQL 16 → ③ 체크 서버 v43**이에요. 화면은 그대로 두셔도 돼요.

- v43에서 더한 것: 맞춘 입금을 «되돌리기» 하면 갈래도 처음(«미분류»)으로 돌아가요. 대표님이 직접 고른 갈래는 그대로예요(SQL 16 필요).
- v42에서 더한 것: 국세청 «연결하지 못했어요»의 까닭을 짧은 코드로 보여 주는 고침이 더해졌어요(`서버/설계/28`).

- v40을 아직 안 올리셨다면 `배포안내_체크_v36에서_v40.md`의 SQL 14까지 먼저 해 주세요. 그다음 v40은 건너뛰고 v43을 올리시면 돼요.

## 대표님이 하실 일
1. **SQL 15 실행**
   - 수파베이스 → SQL Editor를 열어요.
   - `서버/sql/15_체크_입금엑셀_고침.sql` 내용을 붙여 넣고 Run을 눌러요.
   - 마지막 표의 네 줄이 모두 «됨»이면 끝이에요.
   - «안 됨»이 보이면, 그 화면 사진을 서버 방에 보내 주세요(지운 자료는 없어요).
   - «③ 같은 줄 막기 규칙»만 «안 됨»이면, 이미 겹친 입금 줄이 있다는 뜻이에요. 서버 방이 겹친 줄을 정리하는 글을 따로 드리면, 그걸 실행한 뒤 SQL 15를 다시 실행해 주세요. (TEST는 이 규칙이 이미 있어서 해당 없어요)
   - 여러 번 실행해도 안전해요.
2. **SQL 16 실행**
   - `서버/sql/16_체크_되돌리면_갈래도.sql`을 같은 방법으로 붙여 넣고 Run을 눌러요. 마지막 줄이 `t`면 끝이에요.
3. **체크 서버 v43 올리기**
   - `서버/2_차곳간체크_서버_check-api_v43.ts`를 check-api에 올려요. 지금까지와 같은 방법이에요(Verify JWT 끔).

## 무엇이 문제였을 수 있나 (세 갈래 모두 막았어요)
- **빈 칸 제한**: 입금 표가 «계좌»나 «잔액» 칸을 꼭 채워야 하게 되어 있는데, 엑셀 줄은 그 칸을 비워서 보냈어요.
  - SQL 15가 그 칸을 비워도 되게 바꿔요.
  - v43은 쓰는 계좌가 하나면 그 계좌를 채워 넣어요. 잔액도 넣어요(엑셀에 없으면 0).
- **값 제한(확정된 원인)**: 입금 표가 «가져온 곳»에 «팝빌·문자·손입력»만 받게 되어 있었어요. SQL 15가 «엑셀»까지 받는 규칙으로 다시 만들어요(엉뚱한 값은 계속 막아요).
- **중복 막기 규칙 없음**: 같은 줄 두 번 막는 규칙이 표에 없으면 넣기가 통째로 멈춰요.
  - v43은 그 규칙 없이도 넣어요(겹침은 미리 걸러요).
  - SQL 15는 그 규칙을 만들어요. 은행 자동 조회(팝빌)도 이 규칙이 있어야 제대로 들어와요.
