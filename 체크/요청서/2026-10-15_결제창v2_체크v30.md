# 체크 방 → 결제 · 서버 · 보안 방 (2026-10-15) — 체크 결제창 v2 (체크 v30)

결제 방 요청 `결제/요청서/2026-10-15_체크_결제창v2.md` (가)만 했어요. 자동 결제는 넣지 않았어요(총괄 지시: 지금은 워시만).
운영 v21.2 · 준비된 v29 묶음은 그대로예요. 새 판: `체크/2_차곳간_체크_index_v30.html` (만드는 법 `체크/도구/만들기_체크_v30.py`, v29 와 바뀐 곳은 결제창 두 곳뿐).

## 한 것
- `loadToss(sdk)` — 서버 `payStart` 가 `sdk:"v2"` 를 주면 `https://js.tosspayments.com/v2/standard`, 아니면 예전 v1.
- v2 일 때 `TossPayments(clientKey).payment({customerKey})` → `requestPayment({method:"CARD", amount:{currency:"KRW", value}, orderId, orderName, customerName, successUrl, failUrl})`.
  `customerKey` 는 서버가 준 값, 없으면 `"ANONYMOUS"`. 비밀 열쇠는 화면에 없음(공개 clientKey 만 서버가 줌).
- 돌아온 뒤 `payConfirm(orderId, paymentKey, amount)` 은 그대로.
- 가짜 서버 + 가짜 토스 SDK 로 v2 · v1 두 갈래 모두 위 모양으로 부르는 것을 확인 (화면 오류 0).

## ⚠ 막힌 것 — 서버 방 결정 필요 (체크 화면만으로는 결제가 안 돼요)
1. **체크 서버(check-api v29)에 `cashInfo` · `payDue` · `payStart` · `payConfirm` 이 없어요.** 체크 화면의 「캐시 지갑 · 요금제 · 카드 결제」 칸은 워시에서 복사된 코드라, 지금 체크에서 누르면 서버가 모르는 창구라고 거절해요(운영 v21 도 같음).
2. 그 칸의 서버 부르기(`cwRpc`)는 체크 주소(check-api)로 가지만, 열쇠는 **워시 로그인 열쇠 이름**(`ccw_sid` · `ccw_shop`)을 읽어요. 체크 로그인 열쇠는 `cgg_key` · `cgg_shop` 이라 비어서 가요.
   - 추천: 결제 · 캐시 창구는 **워시 서버(wash-api) 한 곳**에만 두고, 체크 화면은 경비실(통합 로그인) 열쇠로 그 창구를 부르기 — 요금 · 캐시가 업체 하나에 한 지갑이 되게. 이 방법을 서버 · 결제 방이 정해 주시면 체크 화면을 맞출게요.
3. 그래서 결제 방의 「끝났다고 보는 기준」(테스트 모드에서 체크 결제 → 이용기간 반영)은 위 1 · 2 가 정해진 뒤에 확인할 수 있어요.

## 워시와 「100% 같게」(규칙 3-2)
- 워시 방의 (가)가 아직이에요(워시 최신 v119 는 v1). 이 v2 부분(`loadToss` · `cwPay` 안 결제창 부르는 곳)을 워시도 **그대로** 쓰면 둘이 같아져요. 워시 방이 다르게 만들면 체크가 워시 것을 다시 복사할게요.
