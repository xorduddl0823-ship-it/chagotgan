# 체크에서 문자 · 알림톡을 보내는 곳 (규칙 5-6 점검, 2026-10-15)

> 작성: 체크 방. 대조한 파일: 사무실 화면 `체크/2_차곳간_체크_index_v28.html`, 기사 화면 `체크/driver/index_v24.html`, 서버 `서버/2_차곳간체크_서버_check-api_v28.ts`
> 규칙 5-6: 안내는 **알림톡이 먼저**, 실패할 때만 솔라피가 문자로 대신 보냄. 문자만 보내는 기능을 새로 만들지 않음. 템플릿 코드가 비어 있으면 문자로.
> 서버 방의 전체 목록(`서버/설계/10`)과 맞춰 볼 때 쓰세요.

## 1. 실제로 나가는 곳 (서버가 솔라피를 부름)

| # | 무엇 | 누가 누르나 | 서버 | 지금 보내는 방식 | 규칙 5-6과 다른 점 |
|---|---|---|---|---|---|
| 1 | **차량 도착 알림** (딜러에게) | 기사 폰 「도착」(`api_arrive`), 사무실 · 기사 「다시 보내기」(`deliv_resend`) | `notifyOne` | 설정 `way` 가 `ata` 이고 `ata_tpl` 이 있으면 알림톡, 아니면 문자(사진 켜면 MMS · 아니면 LMS/SMS). 알림톡 실패 시 문자 대신 보내기는 `fallback` 을 켰을 때만 | ① 처음 값이 **문자(`sms`)**, 대신 보내기 **꺼짐** → 5-6은 알림톡 먼저 · 대신 보내기 늘 켜짐 ② 알림톡 보낼 때 대신 보낼 **문자 글(text)을 안 넣음** → 대신 보내기가 켜져도 문자가 빈 글이거나 실패할 수 있음 (서버 확인 필요) ③ 템플릿 코드 · 채널(pfId)이 **검사소마다** 설정에 있음 → 5-6은 관리 설정 칸 |
| 2 | **처음 비밀번호 확인 번호** (사무실 직원 본인에게) | 로그인 화면 (`login` → 확인 번호) | `login` 안 | **문자(SMS)만**. 보내는 번호는 비밀값 `SMS_FROM` → 없으면 검사소 `sms_from` | 알림톡 아님. 인증번호용 알림톡 템플릿을 만들지, 인증번호만은 문자로 둘지 **총괄 · 서버 방 결정 필요** |

## 3. 문자 설정 칸 (모두 사무실 화면)

| 칸 | 어디 | 서버에 저장 | 5-6 이후 |
|---|---|---|---|
| 보내는 방법 (문자 / 알림톡) | 차량 배달 알림 › 문구 · 발송 설정 | `check_deliv_conf.way` | 고르기 없애고 **늘 알림톡 먼저** |
| 알림톡이 실패하면 문자로 | 같은 곳 | `fallback` | 고르기 없애고 **늘 켜짐** |
| 사진 붙여 보내기 (MMS 110원 / LMS 45원) | 같은 곳 | `photo_on` | 알림톡은 사진을 못 붙임 → 사진은 「사진 보기」 링크로. 문자로 대신 갈 때만 의미 있음 |
| 보내는 번호 | 같은 곳 (`from_tel`) · 설정 › 팝빌 연동 › 우리 사업장(`sms_from`) | 둘 다 | 대신 보내는 문자의 발신번호. 두 칸이 겹침 → 하나로 |
| 알림톡 템플릿 문구 · 코드(`ata_tpl`, `ata_pf`) | 같은 곳 | `ata_tpl` · `ata_pf` | 관리 설정 칸으로 옮김 (5-6) |
| 문자 글(`sms_text`) | 같은 곳 | `sms_text` | 대신 보내는 문자 글로 계속 씀 |
| 문자 자동수집 (입금 문자 받기) | 설정 › 문자 자동수집 | — (보내는 기능 아님) | 해당 없음. 구글 Apps Script 카드는 대표님 결정으로 그대로 |

## 4. 기사 폰 화면
- 기사 화면이 직접 문자를 보내는 곳은 없어요. 「도착」 · 「다시 보내기」를 누르면 서버가 위 1번으로 딜러에게 보내요.
