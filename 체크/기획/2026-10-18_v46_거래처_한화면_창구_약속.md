# 체크 v46 «거래처 한 화면» — 서버 창구 약속 (체크 → 서버)

- 2026-10-18 · 요청서 08 A(총괄) · 시안 https://claude.ai/artifact/J6CqnRvhvefztsjWtqYH2Y
- **v46은 지금 서버 v34 그대로 돌아가요.** 아래 v35 약속은 «있으면 칸이 더 보이는 것»이에요. 없으면 그 칸만 숨겨요(화면이 깨지지 않음).
- 모양은 이 문서대로만 바꿔요. 두 방이 동시에 모양을 바꾸지 않아요(지난번 v33 엇갈림 교훈).

## 1. 지금 그대로 쓰는 창구 (서버 v34 · 바꾸지 말아 주세요)
| 창구 | 화면에서 쓰는 곳 |
|---|---|
| `dealers()` | 딜러 표. `bill_to_id` · `issuer_*` · `tax_issue` · `memo` 를 그대로 들고 있다가 저장할 때 그대로 돌려보내요 |
| `companies()` | 상사 표 (`id,name,biz_no,ceo,tel,dealerN`) |
| `dealerSave(row)` | 딜러 창 «저장». **모든 칸을 보내요**(빠지면 서버가 빈 값으로 덮으니까요). 계산서 고르기를 안 바꾸면 `issuer_kind · tax_issue` 도 예전 값 그대로 |
| `companySave(row)` | 상사 창 «저장» · 딜러 창에서 «처음 보는 상사» 같이 만들기 · 딜러 창에서 비어 있는 상사 사업자 정보 넣기(→ 그 상사 딜러 모두에게 쓰임) |
| `dealerDel({ids})` · `companyDel({ids})` | «선택한 줄 지우기» · 창 안 «지우기» (이름 확인 창 뒤) |
| `aiCard(b64)` · `aiBiz(b64)` | «명함 사진으로» · «사업자등록증 사진으로». JPEG 긴 변 1600 · `data:` 앞부분 뗌 · 답은 빈 칸에만 «미리 채우기» · 실패하면 «사진을 읽지 못했어요. 직접 적어 주세요» |

딜러 창의 계산서 네 가지 ↔ 서버 값
| 화면 | `issuer_kind` | `tax_issue` |
|---|---|---|
| 상사 이름으로 | `company` | true |
| 딜러 본인 사업자로 (+ 상호 · 사업자번호 · 대표자 · 주소 → `issuer_name/biz/ceo/addr`) | `dealer` | true |
| 안 끊어요 | `none` | false |
| 나중에 정할게요 | `later` ※ v35 | true |

«정보 필요»(표 위 «○명 · 모아 보기»)는 **계산서를 끊을 수 있는지**로 셈해요: 상사로 → 그 상사 사업자번호가 맞는 번호(검산) · 본인 → 상호 + 맞는 번호 · 나중에 → 늘 정보 필요. (서버 홈택스 `can` 과 같은 기준: 번호 10자리)

## 2. 서버 v35에 부탁하는 것 (요청서 C에 더해서)
1. **`partnerCaps()`** → `{later:true, more:true, last:true}` — 화면이 이걸 보고 칸을 켜요. 없으면(v34) 모두 꺼짐.
2. **`issuer_kind:"later"`** 받기 — 청구서 만들기(`invoiceBuild`)에서는 **지금 기본값과 똑같이 `company`로 처리**해 주세요(청구 결과가 바뀌지 않게). 홈택스 대상에서는 «계산서 정보가 아직 없어요»로.
3. **`more`** — 상사: `addr · email · upte · jongmok` 를 `companies()`가 돌려주고 `companySave`가 받기. 딜러: `issuer_email · issuer_upte · issuer_jongmok` 를 `dealerSave`가 받기(`dealers()`는 `select *` 라 그대로 나옴). 홈택스 발급 때 받는 쪽 이메일 · 업태 · 종목으로 쓰면 좋아요(지금은 `invoiceeAddr`만 상사 주소).
4. **`last`** — `dealers()` 줄마다 `last_date`(그 딜러 마지막 검사일 `YYYY-MM-DD`) — 표 «마지막 거래» 칸.
5. `aiCard · aiBiz` 오류 글에서 «번호판» 빼기(이미 v35 예정이라고 하셨어요). 화면은 지금도 쉬운 말로 바꿔 보여 줘요.
6. 지우지 않는 옮기기: 새 칸은 모두 빈 값 기본(옛 자료 그대로).

## 3. 화면이 지키는 것
- 넣기 · 고치기 · 지우기 · 사진 읽기 버튼은 **대표만** 보여요(서버도 `bossOnly`). 직원은 줄을 누르면 «보기만» 창.
- 사용자 글(딜러 · 상사 이름, 사진에서 읽은 값)은 모두 `esc` 하거나 `input.value` 로만 넣어요.
- 지우기는 고른 이름을 다 보여 주는 확인 창 뒤에만(30명 넘으면 «외 N명»).
- 계산서 규칙(검사비는 딜러별 · 성능보험료는 상사 앞으로)과 청구서 만들기는 손대지 않아요.

## 4. 덧붙임 (10/18 · 대표님 v46 시험 → 거래처 부품 cpt 1.1 · 체크 v47)
- `aiBiz` 답에 **`tel` · `email` · `start`(개업일 YYYY-MM-DD)** 를 더해 주세요(서버 v37 예정이라고 들었어요). 화면은 빈 칸에만 채우고, `start`는 국세청 확인에만 써요(저장하지 않음). `aiCard`의 `email`은 이미 있어요 → 딜러 본인 사업자 이메일 칸에 채워요.
- **`bizVerify({no, ceo, start})`** (새 창구 · 대표만 · 검사소 하루 상한 추천) → `{ready, state, since, match:{ceo, start}}`
  - `ready:false` = 국세청 열쇠가 아직 없음 → 화면은 «번호 모양 맞음»만
  - `state`: `"계속"`(영업 중) · `"휴업"` · `"폐업"` · `"없음"`(등록 안 된 번호) · `since`: 휴업/폐업 날짜(없으면 "")
  - `match.ceo` / `match.start`: 대표자 · 개업일이 국세청과 맞으면 true, 다르면 false, 안 보냈거나 모르면 null
  - 창구가 없으면(«지원하지 않는 기능») 화면이 `{ready:false}`로 봐요.
- 화면 표시: 영업 중 → «국세청 확인: 영업 중»(초록) · 다르면 «… — 국세청 등록과 대표자 · 개업일가 달라요»(빨강) · 휴업/폐업/없음 → 빨강 + **저장 전에 한 번 더 묻기**(막지 않음).
- **바로잡음 (10/18 · 보안 v47 덧붙임):** 서버 v37이 먼저 만든 모양에 **화면이 맞춰요**(서버는 바꾸지 않음). 부품(cpt)은 `{no, ceo, start}` 그대로 쓰고, 체크 이음새가 바꿔 보내요.
  - 보냄: `bizVerify({bizNo, ceo, openDate:"YYYYMMDD"})` · 받음: `{ready, state, closedAt, match:true|false|null, why}` → 부품에는 `since=closedAt` · `match={ceo:m, start:m}`
  - `aiBiz` 개업일은 `openDate`(YYYYMMDD) → 이음새가 `start`(YYYY-MM-DD)로 바꿔 넘김
  - 하루 한도(100) 아끼기: **창을 열기만 해서는 묻지 않음**. 번호를 고칠 때 · 사진으로 채운 뒤 · «국세청에 확인» 단추를 누를 때만 (cpt 1.2)
