# 입금 내역 «입금 처리 · 지우기 · 은행 엑셀 가져오기» — 서버 창구 약속 (초안 · 체크 → 서버)

- 2026-10-18 · 총괄 순서 ②(v46 거래처 다음 한 가지) · 가온 매일 쓰기
- **초안이에요.** 서버 방이 미리 볼 수 있게 먼저 드려요. 화면(체크 v47)은 v46 보안 · 올리기가 끝난 뒤 만들어요.
- 지금 서버(v35): `depositList({days})` · `depositMatch()`(입금자명 = 청구처 · 포함 딜러 · 상사 이름이면 «자동 반영» + 청구서 paid_amount 더하기 + 입금확인 알림톡) · 팝빌 계좌조회. **사람이 손으로 맞추기 · 되돌리기 · 지우기 · 엑셀 넣기 창구가 없어요.**

## 1. 새 창구 (모두 이 검사소 것만 · 섞이면 전체 거절 · 감사 기록)
| 창구 | 받는 것 | 하는 일 | 돌려주는 것 |
|---|---|---|---|
| `depositApply` | `{ids:[입금 id], invoiceId}` (≤50) | 고른 입금을 그 청구서에 맞춤 → `state:"입금 처리"` · `invoice_id` · `dealer_id` · 청구서 `paid_amount` 더하기 · `state` 완료/수금중. **«확인 대기»이고 아직 안 맞춘 것만**(depositMatch처럼 조건부로 먼저 잡기 — 두 번 더해지지 않게) | `{n, invoice:{id, paid, total, state}}` |
| `depositUnapply` | `{ids}` (≤50) | 맞춘 것 되돌리기 → 청구서 `paid_amount` 빼기 · 입금은 «확인 대기»로. 세금계산서 발급과는 상관없음 | `{n}` |
| `depositKind` | `{ids, kind}` (검사비 · 정비비 · 보험료 · 미분류 · 기타) | 갈래만 바꾸기 (청구서와 상관없음) | `{n}` |
| `depositDel` | `{ids}` (≤200) | **실제로 지우지 않고** `state:"지움"`(휴지통). 맞춘 것은 거절(«먼저 되돌려 주세요»). `depositList`는 «지움»을 빼고, `depositTrash()`로 따로 | `{n, kept:[{id, why}]}` |
| `depositRestore` | `{ids}` | 휴지통에서 «확인 대기»로 | `{n}` |
| `depositImport` | `{rows:[{tx_at, sender, amount, memo?}], bank?}` (≤1000) | 은행 엑셀에서 읽은 줄을 넣기(`src:"엑셀"`, `state:"확인 대기"`). `uniq_key = "x|" + tx_at(분까지) + "|" + amount + "|" + sender` 로 **같은 줄 두 번 안 들어가게**. 금액은 양의 정수만 · 날짜는 최근 400일 안 · 이름 40자 | `{got, dup, bad:[{row, why}]}` 다음에 `depositMatch()` 한 번 |

## 2. 권한 (추천 — 보안 방 확인 필요)
- `depositApply · depositUnapply · depositKind`: **대표 + 직원**(매일 하는 일). 단 하루 상한(예: 300건)과 감사 기록.
- `depositDel · depositRestore · depositImport`: **대표만**.
- 입금확인 알림톡: 손으로 맞춘 «입금 처리»에도 **자동 반영과 똑같이 한 번** 보냄(추천). 되돌린 뒤 다시 맞추면 다시 보내지 않음(입금 id별 한 번).

## 3. 화면이 지킬 것 (체크 v47 예정)
- 입금 내역 표: 고르기 → «청구서에 맞추기»(청구처를 고르는 창 · 금액 · 남은 금액 보여 주기) · «되돌리기» · «갈래 바꾸기» · «선택한 줄 지우기»(이름 · 금액 확인 창) · «은행 엑셀 가져오기»(엑셀은 브라우저에서 읽고 미리보기 → 확인 뒤 보냄, 파일은 보내지 않음)
- 은행마다 엑셀 칸 이름이 달라요 → 화면이 «거래일시 · 입금액 · 보낸 분(적요)» 칸을 자동으로 찾고, 못 찾으면 사람이 고르게.
- 모든 글 `esc` · 확인 창은 고른 줄 이름 · 금액을 다 보여 줌(1.5 규칙 ②).

## 4. 서버 방에 묻는 것
- `check_deposit.state` 에 «입금 처리» · «지움»을 더해도 되는지(지금 값: 확인 대기 · 자동 반영 · 맞음 …).
- 은행 엑셀 줄과 팝빌 줄이 같은 입금일 때(둘 다 들어옴) 겹침 막기 — 추천: 같은 날 · 같은 금액 · 같은 이름이면 `dup`으로.
