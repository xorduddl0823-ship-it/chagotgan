▶ 이 방에서 Claude 가 제안했지만 택영님이 아직 정하지 않은 것
 · (09-28 «예를 들어 업체가 직접 입력하면?» 질문에 대한 답) 누가 입력했느냐가 아니라 어디서 받았느냐가 기준 — 업체 직원이 카모두 화면을 보고 옮겨 적어도 출처는 카모두라서 안 된다는 것이 Claude 의 답이었습니다. 이 방향으로 기획서를 만들었습니다. 법률 자문은 아닙니다.
 · 기획서 9장의 네 가지: 같은 차 다시 들어올 때 지난 딜러를 제안하는 기간(제안 90일) / 카모두 출처 번호를 지울 날짜(예: 3개월 뒤) / 딜러 번호가 바뀔 때 본인 확인 방법 / 위치 공유 동의를 선택으로 둘지 필수로 둘지
 · 워시의 «명부 엑셀 올리기» 기능을 없앨지, «딜러에게 직접 받은 명단만» 으로 바꿀지
 · 옛 구글 드라이브 사진 폴더 공유를 끌지 (끄면 옛 사진이 앱에서도 안 보임)
 · 10-10 에 «로그인한 딜러에게 워시에 입고된 내 차만 보이게» 를 첫 목표로 하자고 제안했지만, 이 방에서는 답을 받지 못했습니다.

■ 4. 끝내지 못한 일 · 알려진 문제
 · 보안 수정(서버 v30.1 · 앱 v99.1 · 3번 SQL)을 실제로 올렸는지 확인하지 못했습니다.
 · 4번 확인 SQL 결과(표 보호 RLS 가 켜져 있는지, 보관함 규칙)를 받지 못했습니다 → 표 보호 상태는 아직 모릅니다.
 · 워시 «명부 엑셀 올리기» 는 화면 안내문부터 «카모두에서 받은 딜러 목록을 올려두면» 으로 되어 있습니다. 이미 올라간 명부 파일(회사명 · 딜러명 · 핸드폰)이 보관함에 있습니다.
 · 기획서의 «출처» 칸(직접 받음 / 카모두) · 딜러 계정 표 · 연결 표 · 서버 규칙은 아직 하나도 개발하지 않았습니다.
 · 옛 구글 드라이브 사진을 새 보관함으로 옮기는 도구는 만들지 않았습니다.
 · 개인정보처리방침의 «국외 이전» 문구는 초안만 있습니다 (Cloudflare 보관 기간 · 각 회사 연락처는 «확인 필요»). 홈페이지 파일은 고치지 않았습니다.
 · 보안 수정의 알려진 제약: 사진이 처음 뜰 때 잠깐 빈 칸 / 사진 주소가 1시간마다 바뀌어 데이터 사용이 조금 늘 수 있음 / wash_sessions 열쇠 칸에 글자 수 제한이 있는지 확인 못 함(그래서 48자로 맞춤) / 3단계 뒤 서버를 v30 으로 되돌리면 모든 기기가 다시 로그인해야 함.
 · 실제 수파베이스에 붙여 시험하지 못했습니다 (가짜 데이터베이스로 서버 29가지 · 화면 19가지 시험 통과, SQL 은 시험용 포스트그레스에서 실행).
 · 9월 28일 채팅에서 드린 두 줄짜리 확인 SQL 은 마지막 줄 결과만 보여서 쓰지 마세요 → 4번 파일로 바꿨습니다.

▶ 딜러 계정이 워시 · 체크 계정과 같은 로그인을 쓰나?
정하지 않았습니다. 기획서 안은 «딜러 계정을 따로» 두는 것입니다 — 딜러코드(D0001), 휴대폰 번호 + 인증번호. 워시 직원 계정(wash_users, 휴대폰 + 비밀번호)과 섞지 않는 이유는 딜러가 여러 업체와 거래하므로 한 업체에 속한 계정이 아니기 때문입니다. 다른 방에서 «사용자 페이지를 앱 하나로, 역할별 화면» 으로 정했다면 딜러는 그 안의 «딜러 역할» 로 다시 정해야 합니다.
