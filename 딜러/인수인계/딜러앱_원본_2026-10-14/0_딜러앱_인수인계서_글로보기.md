4\. 끝내지 못한 일 · 알려진 문제

끝내지 못한 일

- d2.3(C안) HTML 을 실제로 올렸는지 확인 (2장 상자 참고).

- 워시에서 만든 «시험 입고»(딜러 연락처 = 대표님 번호)를 지웠는지 확인.

- 기억해 둔 요청 미반영: «첫 딜러 응원메세지 및 개선사항 표출» (9/27,
  나중에 반영).

- 알림: 진짜 앱 알림(웹 푸시)은 아직 없음. 지금은 입고 기록을 모아 보여
  주는 것뿐. «앱 알림 받는 딜러는 문자 생략» 규칙도 아직.

- 청구서 · 일괄 결제: 화면 자리만. 결제사 지급대행(예: 토스페이먼츠)
  계약·확인 필요.

- 카히스토리: 화면 자리만. 보험개발원 제휴 또는 조회 대행(CODEF·하이픈
  등) 계약과 건당 원가 확인 필요.

- 스토어 앱(플레이스토어·앱스토어) 포장은 시작 전.

- 약관·개인정보 동의 글은 초안. 티와이컴퍼니
  상호·사업자번호·주소·개인정보 보호책임자 넣고 검토 필요.

- 관제센터에 딜러 계정 보기·정지 기능 없음 (지금은 DB 에서
  dealer_users.active 로만 멈출 수 있음).

알려진 문제 · 주의

- 단계 판단은 워시 입고 기록만으로 추정: 출고 전 + 작업 항목 없음 = 입고
  / 작업 항목 있음 = 작업 중 / 출고했는데 보낸 곳 이름이 차곳간 업체
  이름과 겹치면 = 출고(이동 중) / 그 밖 = 도착. 업체 이름이 비슷하면
  잘못 나올 수 있음.

- 금액은 업체가 입고 때 적은 금액 그대로 (부가세 규칙 미적용). 금액이
  없으면 «업체가 아직 금액을 넣지 않았어요».

- 차와 딜러는 입고 기록의 «딜러 연락처» 번호 하나로만 맞춤. 딜러가
  번호를 여러 개 쓰거나, 업체가 번호를 틀리게 적으면 안 보임.

- 사진은 워시 보관함(공개 주소) 그대로 씀 — 주소를 아는 사람은 열 수
  있음 (워시와 같은 방식).

- «내 정보»의 알림 스위치는 그 휴대폰에만 저장됨 (서버 저장 아님).

- 알림 목록의 «문자/기록» 꼬리표는 추정 표시 (실제 문자 발송 기록과 연결
  안 함).

- dealer-api 의 Verify JWT 를 켜면 로그인이 막힘 — 반드시 꺼 둘 것.

| 업체 기록에서 보여 주는 것 | 차량번호 · 차종 · 상사 이름 · 작업 이름 · 금액 · 사진 · 입고/출고 시각 · 보낸 곳 · 주차 칸 |
| 받지 않는 것               | 주민등록번호, 주소, 계좌·카드 번호, 비밀번호 — 없음                                        |

딜러 계정이 워시·체크와 같은 로그인인가?

아니요, 따로입니다. 표(dealer_users·dealer_sessions·dealer_otp)도,
서버(dealer-api)도 다릅니다. 비밀번호 없이 인증번호만 씁니다. 같은
번호가 워시 직원이면서 딜러일 수도 있지만 두 계정은 서로 영향을 주지
않습니다.

딜러 화면의 메뉴와 순서

아래 탭: ① 내 차 → ② 알림 → ③ 청구서 → ④ 카히스토리 → ⑤ 내 정보. 위쪽
남색 줄 오른쪽에 «알림» 단추(빨간 숫자). 차를 누르면 «차 상세».

가장 중요한 목록 하나

«내 차» 목록 — 내 번호로 맡겨진 차를 차량번호마다 최근 상태 하나씩
(차량번호 · 차종 · 단계 · 지금 위치 · 시각 · 4칸 진행 막대).

첫 화면에 보여 줄 숫자 4개

지금 화면에는 2개가 있습니다: **상품화 진행 중 대수**, **결제할 청구서
금액**(청구서가 열리기 전이라 0원).

4개로 늘린다면 제안 (대표님이 정한 것은 아님): ① 상품화 진행 중 대수 ②
오늘 출고·도착한 차 ③ 결제할 청구서 금액 ④ 재검사 다가오는 차(체크 연결
뒤).

딜러가 매일 하는 일 3가지 (제안 — 대표님 확인 필요)

- 내 차가 지금 어느 업체에 있는지, 작업이 어디까지 됐는지 확인한다.

- 출고·도착 알림을 보고 차를 받은 뒤 «상품화 완료»를 누른다.

- 청구서를 확인하고 여러 업체 대금을 한 번에 결제한다 (청구서가 열린
  뒤).
