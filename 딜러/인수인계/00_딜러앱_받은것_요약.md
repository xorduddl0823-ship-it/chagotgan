## 1. 한 줄 요약
딜러가 휴대폰 번호와 인증번호로 들어와서, 업체(워시 등)에 맡긴 **자기 차가 어디 있는지, 어떤 작업을 했는지** 보는 앱입니다.
1단계(로그인 · 약관 동의 · 내 차 · 차 상세)는 **실제로 운영 중**입니다. 알림 · 청구서 · 카히스토리는 화면 자리만 있습니다.

## 3. 추가로 물어본 것의 답

- **PC용 · 폰용 따로인가?** → **한 파일**입니다. 폰에서는 화면 가득, PC에서는 가운데에 휴대폰 모양으로 보입니다. 합치는 작업은 필요 없습니다.
- **dealer-api 최신본** → d2 (2026-10-11), 원본 묶음의 `2_…ts`.
- **개인정보 항목**
  - 딜러에게서 받는 것: 휴대폰 번호, 이름(선택), 광고 수신 동의 여부
  - 저절로 남는 것: 접속 기록(시각 · 기기 정보 · IP), 동의 · 철회 기록, 인증번호(암호화된 값, 5분)
  - 업체 기록에서 보여 주는 것: 차량번호, 차종, 상사 이름, 작업, 금액, 사진, 입고 · 출고 시각, 보낸 곳, 주차 칸
  - 받지 않는 것: 주민등록번호, 주소, 계좌 · 카드 번호, 비밀번호
- **워시 · 체크와 같은 로그인인가?** → **아니요, 따로입니다.** (dealer_users · dealer_sessions · dealer_otp 표와 dealer-api 서버를 따로 씀)
- **메뉴와 순서**: ① 내 차 → ② 알림 → ③ 청구서 → ④ 카히스토리 → ⑤ 내 정보
- **가장 중요한 목록**: «내 차» 목록 (차량번호 · 차종 · 단계 · 지금 위치 · 시각 · 4칸 진행 막대)
- **첫 화면 숫자 4개**: 지금은 2개뿐(진행 중 대수, 결제할 청구서 금액). 4개 안은 **예전 방의 제안이고 대표님이 정한 것 아님** — ① 진행 중 대수 ② 오늘 출고 · 도착 ③ 결제할 청구서 금액 ④ 재검사 다가오는 차
- **딜러가 매일 하는 일 3가지** (역시 제안, 대표님 확인 필요): 내 차 위치 · 진행 확인 / 출고 · 도착 보고 «상품화 완료» 누르기 / 청구서 확인 · 한 번에 결제

## 4. 비밀 열쇠 (이름만)
`SOLAPI_KEY`, `SOLAPI_SECRET`, `SMS_FROM`, `OTP_FROM`, `DEALER_OTP_MAX_IP_DAY`, `DEALER_OTP_MAX_ALL_DAY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`
→ 딜러 방이 파일을 다시 훑어봤고 **열쇠 값은 없었습니다.** 화면 파일의 수파베이스 주소와 차곳간 대표 번호는 공개된 값이라 열쇠가 아닙니다.
→ `DEALER_OTP_…`, `SMS_FROM`, `OTP_FROM` 이름은 규칙 장부 2장 목록에 아직 없습니다.

## 5. 공통 규칙과 어긋나는 곳 (대표님 · 총괄 · 서버 · 보안 방이 정할 일)

1. **딜러 전용 로그인이 따로 있습니다.** 딜러 방 안내문은 «딜러 전용 로그인을 따로 만들지 않고 통합 로그인(서버 방)을 씀»입니다. 이미 운영 중이라 바로 바꾸지 말고, 서버 방이 통합 로그인으로 옮길지 정해야 합니다.
2. **보안 방 검토 없이 개인정보 기능이 이미 운영 중입니다.** (규칙 2-5) 보안 방 검토를 먼저 받아야 합니다.
3. **차 사진이 공개 주소입니다.** 주소를 아는 사람은 누구나 볼 수 있습니다 (워시와 같은 방식). 보안 방 검토 대상입니다.
4. **dealer-api 는 Verify JWT(서버 입구 검사)를 꺼야 돌아갑니다.** 대신 함수 안에서 직접 로그인 표를 검사합니다. 보안 방 확인이 필요합니다.
5. **서버 코드와 SQL이 딜러 방에서 만들어졌습니다.** 앞으로는 서버 방이 맡아야 합니다 (철칙 2).
6. 약관 · 개인정보 동의 글은 **초안**입니다. 회사 이름 · 사업자번호 · 주소 · 개인정보 보호책임자가 빠져 있습니다.
