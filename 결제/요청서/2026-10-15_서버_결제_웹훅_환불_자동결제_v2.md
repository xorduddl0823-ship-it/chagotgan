1. 왜 필요한가요?
   - 업체가 카드로 냈는데 결제창에서 돌아오기 전에 창을 닫으면, 지금은 차곳간이 결제를 몰라요 → 「냈는데 안 열린다」 문의.
   - 월 이용요금을 환불해도 늘려 준 이용기간이 그대로 남아요.
   - 대표님이 정기 구독(자동 결제)을 확정했어요: 업체가 직접 켜야 시작, 실패하면 D+1·3·5 재시도 후 기존 7일 잠금.
   - 토스 결제창이 옛 v1이에요. 자동 결제는 v2로 만들기 때문에 함께 옮겨요.
   - 딜러앱 「청구서」 메뉴(계좌이체 묶음 안내)에 업체별 청구서를 보여 줄 창구가 필요해요.

2. 무엇을 해 주면 되나요?
   (가) **웹훅 받는 곳** — 워시 서버(또는 새 결제 전용 함수)에 토스 웹훅 주소 1개
       - 이벤트 `PAYMENT_STATUS_CHANGED` 처리. 받은 내용을 그대로 믿지 말고 **토스 결제 조회 API로 다시 확인**한 뒤 반영
       - 이미 `paid` 인 주문은 다시 반영하지 않기(지금 `payConfirm` 의 상태 확인 재사용), 10초 안에 200 응답
       - 기록 표 `pay_webhook_log`(받은 시각, 이벤트, 주문번호, 처리 결과)
       - 「ready」로 30분 넘게 남은 주문은 하루 몇 번 토스에 다시 조회해서 정리
   (나) **환불 되돌리기** — `hqPgCancel` 에서 kind=plan 이면
       - `paid_until` 에서 **환불한 날수만큼 빼기**(예전 값으로 되돌리지 않음 — 보안 검토 9번), 오늘·다른 결제가 끝나는 날보다 앞으로는 안 감, `wash_payments` 해당 줄 status=refunded
       - 부분 환불(사용한 날 비율) 금액을 받을 수 있게 `cancelAmount` 지원
   (다) **자동 결제(빌링)** — 토스 자동결제 **추가 계약 뒤** 켤 수 있게 스위치(`billing_on`)로 막아 둔 채 준비
       - 표 `pay_billing`: shop, customer_key(겹치지 않는 무작위 값), billing_key(**암호화 저장, 화면·기록·관리 화면에 절대 안 내려감**), card_company, card_last4, status(on/off), agreed_at, agreed_text_ver, next_at, fail_count, last_fail_msg
       - 표 `pay_billing_log`: shop, order_id, amount, try_no, result, msg, at
       - 창구(대표만): `billStart`(카드 등록창 정보) · `billIssue`(authKey로 빌링키 발급·저장) · `billInfo`(카드사·끝 4자리·다음 결제일) · `billOff`(끄기 → 빌링키 삭제, 이번 기간 끝까지 사용)
       - 매일 아침 예약 실행 1번: `paid_until` = 오늘인 자동결제 업체 → 금액 서버 계산(요금제×1.1 − 쓸 캐시) → 빌링 승인 → 성공 시 지금 `payDone` 그대로 / 실패 시 D+1·D+3·D+5 재시도, 실패 알림톡(정보성, 버튼 없음) → 마지막 실패 뒤는 기존 잠금(`lockOf`) 그대로
       - **같은 날 두 번 청구 방지**(업체+날짜로 한 번만)
       - 새 비밀값 이름(값은 계약 뒤 대표님이 넣음): `TOSS_BILLING_SECRET_KEY`(자동결제용 키가 따로 나올 때), 빌링키 암호화용 `PAY_ENC_KEY`
   (라) **v2 결제창 서버 쪽** — `payStart` 가 v2 SDK에 필요한 값(customerKey 등)도 돌려주게. 승인 API는 같아요. 화면 교체는 워시·체크 방이 따로 함(결제 방이 요청서 따로 씀)
   (마) **딜러 청구서 목록 창구(읽기만)** — dealer-api `myBills`
       - 이 딜러에게 온 업체별 청구서(지금 `wash_viewcode` kind=bill 의 snap): 업체명, 월, 대수, 금액, 입금 기한, 업체 계좌, 상태(입금 전/입금 확인됨), 보기코드 주소
       - 딜러와 청구서를 **어떻게 이어 붙일지**(받는 곳 이름? 딜러 전화번호?) 서버 방이 정해 주세요 — 남의 청구서가 절대 섞이지 않게
   (바) **결제 표 SQL 원본**(`wash_pay_order`, `wash_payments`, 캐시 표)을 `서버/sql/` 에 보관

## 서버 방 의견에 대한 결제 방 답 (2026-10-15)
- 두 번 반영: 「ready→paid 조건 걸고 한 번에 바꾸고, 바꾼 쪽만 payDone」 **찬성**. 자동 결제 「업체+날짜」 겹침 금지(unique)도 찬성.
- 웹훅: 결제 전용 새 함수 **`pay-hook`** 로 따로 두기 **찬성**. 받은 내용은 주문번호만 쓰고 토스 조회로 다시 확인.
- 부분 환불: 서버가 「낸 금액 − 이미 환불한 금액」 상한 확인 + 쓴 날 비율 금액을 서버가 계산해 보여 주고 본사가 확정 **찬성**.
- 캐시 충전 환불도 **같이 해 주세요**: 환불은 **안 쓴 캐시만**(이미 쓴 캐시는 환불 금액에서 뺌). 환불 금액 = 남은 충전 캐시 × 1.1(부가세 포함), 캐시는 마이너스가 되지 않게. 다 쓴 충전은 환불 불가로 안내.
- customerKey 무작위 UUID, billing_key AES-GCM + `PAY_ENC_KEY` **찬성**.
- 딜러 청구서 잇기: **받는 휴대폰 번호로 잇기 찬성**(이름으로 잇지 않음). 워시 서버 보기코드에 받는 번호 칸 추가 포함.
- SQL 원본: 표 모양 내보내는 방법을 쉬운 말로 적어 총괄 방에 주세요(대표님께는 총괄이 모아서 전달).
- 자동 결제 실패 알림톡 새 템플릿은 결제 방이 총괄 방을 통해 알림톡 방에 요청해요.
