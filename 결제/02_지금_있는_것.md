## 1. 카드 결제 흐름 (워시·체크 화면 공통)

```
업체 대표가 [카드로 결제] 누름
  → 화면: cwRpc("payStart", [종류, 금액, 캐시사용액])
  → 서버: 대표만 허용(ownerOnly), pg_on 꺼져 있으면 안내 문구만 돌려줌
          요금제 금액은 서버가 표에서 직접 읽음(화면 값 안 믿음) ✅
          주문서(wash_pay_order, status=ready) 만들고 주문번호(CGG+날짜+난수) 돌려줌
  → 화면: 토스 결제창(옛 v1 결제창 스크립트 js.tosspayments.com/v1/payment)
          성공하면 ?pay=ok 로 돌아옴
  → 화면: cwRpc("payConfirm", [주문번호, paymentKey, 금액])
  → 서버: 주문 주인·금액 확인 → 토스 승인 API(/v1/payments/confirm) 호출
          → wash_pay_order status=paid → payDone()
  → payDone: 캐시 충전이면 공급가액만큼 캐시 넣기(1년 유효)
             월 이용요금이면 paid_until +30일, 사용량 초기화, wash_payments 에도 한 줄
             업체 대표에게 결제완료/충전완료 알림톡, 사장님께 문자
```

- 체크 화면(`체크/올리기용/새판/index.html` 5838~)에도 **같은 결제 코드가 복사**돼 있어요(워시 서버를 같이 부름).
- 충전 한도: 1만 원 ~ 300만 원/회.

## 4. 빈 곳·위험한 곳 (설계에서 꼭 메울 것)

1. **결제 결과 통지(웹훅)가 없어요.** 손님이 결제는 끝냈는데 돌아오는 화면을 닫으면 `payConfirm` 이 안 불려요. 토스는 승인 API를 부르지 않으면 결제를 확정하지 않기 때문에 돈이 빠지진 않지만, 손님은 「결제했는데 안 됐다」고 느껴요. → 웹훅 + 「결제 중」 주문을 다시 확인하는 장치가 필요해요.
2. **월 이용요금 환불 때 이용기간·장부가 안 돌아가요.** `hqPgCancel` 은 캐시 충전만 되돌리고, 이용요금은 `paid_until` 과 `wash_payments` 를 그대로 둬요.
3. **결제창이 옛 버전(v1)이에요.** 토스는 지금 v2 결제창(결제위젯·결제창 통합 SDK)을 안내해요. 새로 만들 정기 결제·딜러 결제는 v2로, 기존 것도 함께 옮기는 게 좋아요. (계약 뒤 서버 방·각 제품 방 작업)
4. **「이번 달 냈나」 판단이 달력 월(period)인데, 기간 연장은 30일 단위**라서 달이 밀리면 어긋날 수 있어요(예: 1/31 결제 → 3/2까지, 2월분 표시 없음). 정기 구독에서 기준을 하나로.
5. **장부가 두 개**(`wash_pay_order`, `wash_payments`)예요. 관리 「결제 내역」에서 합쳐 보이게 하거나 하나로.
6. 정기 결제·딜러 결제는 **아예 없음** → 3번 설계.
7. 홈페이지 가입 결제(`payStart` 공개용)는 로그인 전이라 전화번호로만 주문을 남겨요. 실제로 켤 땐 보안 방 검토 필요.

## 5. 딜러 쪽

- 딜러앱은 **따로 로그인**(dealer-api, `dealer_users`·`dealer_sessions`). 메뉴 ③ 「청구서」, 첫 화면 「결제할 청구서 금액」은 **자리만** 있어요.
- 지금 청구서는 **업체가 워시에서 만들어 알림톡(`bill`)으로 보냄** → 딜러는 `app.cgg.co.kr/v.html?c=보기코드` 로 내역을 보고 **업체 계좌로 직접 이체** → 업체가 「입금 확인」 알림톡(`deposit_ok`).
- 체크는 팝빌 계좌조회로 입금 내역을 가져오는 기능이 있어요(건당 유료, 규칙 5-5).
- 결정 기록(2026-10-15): **여러 업체에 나눠 내는 결제는 차곳간이 돈을 받아 나눠 주지 않고, 토스가 각 업체에 직접 정산**하는 방식으로만.
- 알림톡 방 결론: 청구서 알림톡에는 결제 버튼을 달지 않고 「청구 내역 보기」 → 그 화면 안에 결제 단추.
