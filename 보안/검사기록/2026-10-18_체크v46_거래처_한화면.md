# 보안 검사 — 체크 v46 «거래처 한 화면» (f7d048e · 요청 c3de747)

- 결론: **통과.** 높음 0 · 중간 0 · 낮음 0, 참고 1(서버 쪽)
- 본 것
  - `체크/2_차곳간_체크_index_v46.html`과 v44의 차이 전부
  - `체크/부품/거래처_부품.js·.css`(cpt 1.0) 전부. v46 안에 글자 그대로 들어 있는지도 확인했어요.
  - 서버 `check-api_v35.ts`의 dealerSave

## 확인한 것
- **글 넣기:** 표의 칸, 줄 id, 고르기 칸 이름, 선택 상자(청구서 받는 사람), datalist, 상사 창의 소속 딜러 이름이 모두 `esc`를 거쳐요.
  - 확인 창(CGG.dialog 1.5)도 제목, 설명, rows를 모두 `esc` 해요.
  - 오류 글은 `textContent`로, 알림은 toast(`textContent`)와 bar(`esc`)로 보여 줘요.
- **사진으로 채우기:**
  - 고른 사진은 긴 변 1600px JPEG로 줄인 뒤 aiCard·aiBiz로만 보내요. 저장하지 않아요.
  - 답은 빈 칸에 `input.value`로만 넣어요. 잠긴 칸에는 넣지 않아요.
  - 실패하면 고정 문구를 보여 줘요. 서버(v35)도 대표만 쓸 수 있고, 한도와 6MB 상한이 있어요.
- **권한:**
  - 화면에서는 넣기, 고치기, 지우기, 사진 버튼이 대표에게만 보여요. 직원 창은 칸이 모두 잠기고 저장 버튼이 없어요.
  - save() 안에서도 `if(!own) return`으로 한 번 더 막아요.
  - 서버 dealerSave·companySave·dealerDel·companyDel은 bossOnly이고, office_id 범위 안에서만 동작해요. company_id, bill_to_id, id도 이 검사소 것인지 서버가 확인해요.
- **지우기:** 고른 줄의 이름을 모두 보여 주는 확인 창(30개를 넘으면 «외 N»)을 거친 뒤에만 지워요. 사라진 줄의 고른 표시는 다시 그릴 때 빼요(1.5 규칙 ②).
- **지워지지 않게:**
  - memo와 issuer_*는 예전 값을 그대로 다시 보내요.
  - 계산서 고르기를 바꾸지 않았으면 issuer_kind·tax_issue도 그대로예요.
  - tels는 보내지 않아서, 서버가 기존 값을 그대로 둬요.
- 미리보기 블록과 시험 고리: 운영판 0개. CSP는 v44와 같아요.

## 참고 (서버 방, 막지 않음)
- dealerSave가 issuer_kind를 아무 글자나 받아요(`S(row.issuer_kind) || "company"`). v46은 «none»·«later»도 보낼 수 있어요. 보안 문제는 아니고 자료가 어긋날 걱정이에요.
- 서버에서 company·dealer·none·later만 받게 정해 두면 좋아요. partnerCaps는 v35에 아직 없어서, 지금은 «나중에»와 더 많은 칸이 숨겨져 있어요.
