# 시험 뒤 설계 미리 보기 — 체크 청구서 보내기 · 재검사 알림 (2026-10-16 · 보안 방)
- 대상: `체크/기획/2026-10-16_청구서보내기_재검사알림_설계.md` «보안 검사 받을 것» 5칸 (코드 아님)

## 지금 운영 v32 `invoiceView` 판정 — **낮음 · 시험 중 안 고침 (v33 에서)**
- 로그인 없이 열쇠글로 열고, 청구서 칸 전부(`select("*")`)를 돌려줘요. 그래서 검사소 id, 청구처 id, 세금계산서 관리 칸, 입금액 같은 **내부 값**까지 나가요. 검사소 쪽은 이름·사업자번호·대표·전화·계좌만 나가요.
- 그래도 낮음인 까닭:
  - 열쇠는 무작위 9바이트(약 72비트)라 맞혀서 열 수 없어요.
  - 열쇠는 그 청구서를 받은 딜러에게만 보내요. 그 딜러는 원래 자기 청구서를 볼 사람이에요.
  - 나가는 값은 남을 조작하는 데 쓸 수 없어요. id 는 로그인 없이 쓸 창구가 없어요.
- v33 에서 고칠 것 (설계 63줄 그대로 동의): 돌려주는 칸을 정한 목록만으로 · IP별 `rateOk`.

## 5칸에 더할 것
6. **열쇠 끊기·바꾸기** — 대표가 «이 주소 끊기»를 할 수 있게, 다시 보낼 때 새 열쇠를 고를 수 있게. 딜러 전화가 바뀌거나 잘못 보낸 경우에 필요해요. 지금은 다시 만들어도 같은 열쇠를 써요(507줄).
7. **기한** — 청구서 주소는 발행 뒤 정한 날 수(예: 90일) · 입금 끝나면 짧게. 재검사 목록은 더 짧게. 기한이 지나면 «만료» 글만 보여 주고 내용은 안 줘요.
8. **열쇠가 새지 않게** — 보기 페이지는 `Referrer-Policy: no-referrer` · `noindex` · `Cache-Control: no-store`. 가능하면 열쇠를 주소 `#` 뒤에 둬요(서버 기록에 안 남게).
9. **재검사 차량 목록** — 검사소 id + 딜러 id 둘 다로 거르기(다른 딜러 차 섞임 없음) · 차대번호·전화번호 원문 없음 · 차량번호까지.
10. **열람 기록** — `view_n`·`view_at` 은 카카오 링크 미리보기도 올릴 수 있어요. 열람 확인 용도로만 쓰고, 결제·기한 판단에는 쓰지 않아요.
11. **두 번 누름·재발송** — 같은 청구서를 같은 번호로 다시 보낼 때 하루 상한 안에서만 · 기록에 번호 가림(4번과 같이).

## 판정
설계 방향 **좋아요.** 위 6~11 을 넣어 v33·v43 을 만들면 그때 코드 검사할게요.

## 총괄 급한 질문 답 — v32 invoiceView 운영 고침(v32.1) **필요 없음 · 낮음 그대로**
- 일부러 열어 둔 창구예요(딜러가 알림톡·문자 버튼으로 로그인 없이 보는 청구서, OPEN 목록 2871줄).
- 남의 청구서 보기: **안 돼요.** id 가 아니라 `view_key`(무작위 9바이트·약 72비트, 440줄)로만 찾아요. 추측할 수 있는 번호로 여는 길은 없어요.
- 나가는 칸을 실제로 확인했어요.
  - 청구서: 청구처·딜러 이름, 회사 이름·사업자번호, 금액·건수, 입금액·상태, 세금계산서 상태·관리번호·국세청 번호·오류 글, 검사소 id·청구처 id, 열람 횟수.
  - 내역 줄: 딜러 이름, 품목(정비 사유 글), 금액, 차 id.
  - 검사소: 이름·사업자번호·대표·대표 전화·입금 계좌.
  - 전화번호 원문(딜러·손님)·차대번호·메모는 청구서 표에 넣는 코드가 없어 안 나가요. 계좌는 입금받으려고 일부러 보여 주는 검사소 계좌뿐이에요.
- 그래서 내부 값(id·세금계산서 칸)은 «받은 딜러 본인»에게만 더 보이는 정도예요. 시험 뒤 v33 에서 줄여요(서버 방 받음).
