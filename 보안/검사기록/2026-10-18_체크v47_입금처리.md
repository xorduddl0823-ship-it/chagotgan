# 보안 검사 — 체크 v47 «입금 내역» (14e813a)

- 결론: **화면 통과.** 높음 0 · 중간 0 · 낮음 1(예전부터 있던 것). 서버 창구는 아직 없어요. 그래서 서버 쪽은 지킬 것만 아래에 적어 두고, 판이 오면 따로 검사해요.
- 본 것: v46과 v47의 차이 전부(206줄). 확인 창 ask·askPicked·tell, CGG.dialog 1.5, 엑셀 읽기 부품을 불러오는 줄

## 확인한 것
- **글 넣기**
  - 청구서 고르기 목록(이름·상사·라디오 value·data-name)이 모두 `esc`를 거쳐요.
  - 엑셀 미리보기(일시·보낸 분)와 칸 이름 선택 상자도 모두 `esc`를 거쳐요.
  - 확인 창은 askPicked가 `esc`, 기간·합계는 태그를 떼고 CGG.dialog가 다시 `esc` 해요.
  - 오류 글은 `textContent`로 보여 줘요. 그래서 엑셀 «적요»에 코드를 넣어도 글자로만 보여요.
- **권한(화면)**
  - 지우기 버튼과 엑셀 칸은 대표에게만 보여요. depDelGo 안에서도 `isOwner()`로 한 번 더 확인해요.
  - 맞추기·되돌리기·갈래 바꾸기는 직원도 써요. 약속 초안대로이고, 서버에서 하루 상한과 감사 기록이 필요해요.
- **실수 막기**
  - 맞춘 입금은 지우기 전에 «되돌리기»를 먼저 해야 해요.
  - 맞추기는 «확인 대기»이고 아직 안 맞춘 입금만 할 수 있어요.
  - 지우기와 되돌리기는 이름·금액을 모두 보여 주는 확인 창을 거쳐요(1.5 규칙 ②).
- **엑셀**
  - 파일은 이 기기에서만 읽어요. 서버로는 `{tx_at, sender(40자), amount}`만 보내요.
  - 8MB · 3,000줄 · 1,000건 상한이 있어요.
  - 출금 줄, 0원 줄, 날짜를 못 읽은 줄은 빼요.

## 서버 창구가 지킬 것 (약속 초안에 더함 · 서버 판이 오면 검사)
1. 모든 창구에서 ids와 invoiceId가 이 검사소(office_id) 것인지 확인하고, 섞이면 전체를 거절해요.
2. depositApply는 «확인 대기»이고 invoice_id가 비어 있는 입금만, 조건을 붙여 먼저 잡아요(b93d7d7과 같은 방식).
3. depositApply의 금액 더하기와 depositUnapply의 금액 빼기는 모두 rpc 한 번으로 해요. 0원 밑으로 내려가지 않게 해요.
4. depositUnapply도 조건을 붙여 먼저 잡아요. 그래야 두 번 빼지 않아요.
5. 손으로 맞춘 입금에 보내는 입금확인 알림톡은 **입금 id마다 평생 한 번**이에요. 되돌렸다 다시 맞춰도 다시 가지 않아요. 하루 상한은 bill:o 공용이에요.
6. depositDel · depositRestore · depositImport는 bossOnly예요. 직원이 쓰는 세 창구에도 하루 상한과 check_log를 둬요.
7. depositImport 확인할 것
   - rows ≤ 1000이에요.
   - 금액은 양의 정수예요.
   - 날짜는 최근 400일 안이에요.
   - sender는 40자로 자르고, 화면에 쓸 때는 esc를 해요.
   - kind는 정해진 5가지 중 하나만 받아요.
   - uniq_key로 같은 줄이 두 번 들어가지 않게 막아요.
   - 엑셀로 넣은 sender가 알림톡 변수에 들어가지 않는지 확인해요. 지금 depositNotice는 청구서 이름만 써요.

## 서버 check-api v38 + SQL 14 (a4936b5) — 2026-10-17 검사: **입금 처리 부분 통과** · 다만 v37에서 이어진 중간 1이 남아 있어요
- 본 것: v37과 v38의 차이 전부(206줄), `서버/sql/14_체크_입금처리.sql` 전부
- 앞서 낸 «지킬 것 7가지»와 하나씩 맞춰 봤어요.
  1. 범위: depMine이 이 검사소 입금인지 보고, 섞이면 전체를 거절해요. ids는 겹친 것을 지운 뒤 개수를 비교해요. 청구서도 office_id로 확인해요. ✅
  2. apply는 «확인 대기 · invoice_id null»일 때만 조건부 update로 먼저 잡아요. ✅
  3. 더하기와 빼기는 모두 check_invoice_add_paid rpc로 해요. 0원 이하가 되면 0으로 다시 맞추고 상태도 돌려놔요. ✅
  4. unapply는 «그 invoice_id · 그 state»일 때만 조건부로 먼저 잡아서, 두 번 빼지 않아요. 되돌린 입금은 hold가 켜져서 자동 맞추기가 다시 잡지 않아요. ✅
  5. 알림은 notice_at을 조건부로 먼저 잡아서 입금마다 평생 한 번이에요. 되돌렸다 다시 맞춰도 다시 가지 않아요. 하루 상한은 bill:o 공용 그대로예요. ✅ (SQL 14 전이면 예전처럼 «자동 반영 한 번»이에요.)
  6. del·restore·trash·import는 bossOnly예요. 직원이 쓰는 apply·unapply·kind에는 하루 300건 한도(depop)와 check_log가 있어요. ✅
  7. import 확인 ✅
     - 1000줄까지만 받아요.
     - 날짜는 400일 안이고, 내일보다 뒤는 막아요.
     - 금액은 양의 정수이고 100억 이하예요.
     - 보낸 분은 40자로 자르고, 제어 글자와 < >를 지워요.
     - kind는 «미분류»로 고정해요.
     - uniq_key와 onConflict로 같은 줄이 두 번 들어가지 않고, 팝빌 줄과 겹치면 dup으로 빼요.
     - 알림톡 변수에 보낸 분 이름이 들어가지 않아요. 청구서 이름만 써요.
