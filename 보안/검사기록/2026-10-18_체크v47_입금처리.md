  - 엑셀 미리보기(일시·보낸 분)와 칸 이름 선택 상자도 모두 `esc`를 거쳐요.
  - 확인 창은 askPicked가 `esc`, 기간·합계는 태그를 떼고 CGG.dialog가 다시 `esc` 해요.
  - 오류 글은 `textContent`로 보여 줘요. 그래서 엑셀 «적요»에 코드를 넣어도 글자로만 보여요.
- **권한(화면)**
  - 지우기 버튼과 엑셀 칸은 대표에게만 보여요. depDelGo 안에서도 `isOwner()`로 한 번 더 확인해요.
  - 맞추기·되돌리기·갈래 바꾸기는 직원도 써요. 약속 초안대로이고, 서버에서 하루 상한과 감사 기록이 필요해요.
- **실수 막기**
  - 맞춘 입금은 지우기 전에 «되돌리기»를 먼저 해야 해요.
  - 맞추기는 «확인 대기»이고 아직 안 맞춘 입금만 할 수 있어요.
  - 지우기와 되돌리기는 이름·금액을 모두 보여 주는 확인 창을 거쳐요(1.5 규칙 ②).
- **엑셀**
  - 파일은 이 기기에서만 읽어요. 서버로는 `{tx_at, sender(40자), amount}`만 보내요.
  - 8MB · 3,000줄 · 1,000건 상한이 있어요.
  - 출금 줄, 0원 줄, 날짜를 못 읽은 줄은 빼요.

## 서버 창구가 지킬 것 (약속 초안에 더함 · 서버 판이 오면 검사)
1. 모든 창구에서 ids와 invoiceId가 이 검사소(office_id) 것인지 확인하고, 섞이면 전체를 거절해요.
2. depositApply는 «확인 대기»이고 invoice_id가 비어 있는 입금만, 조건을 붙여 먼저 잡아요(b93d7d7과 같은 방식).
3. depositApply의 금액 더하기와 depositUnapply의 금액 빼기는 모두 rpc 한 번으로 해요. 0원 밑으로 내려가지 않게 해요.
4. depositUnapply도 조건을 붙여 먼저 잡아요. 그래야 두 번 빼지 않아요.
5. 손으로 맞춘 입금에 보내는 입금확인 알림톡은 **입금 id마다 평생 한 번**이에요. 되돌렸다 다시 맞춰도 다시 가지 않아요. 하루 상한은 bill:o 공용이에요.
6. depositDel · depositRestore · depositImport는 bossOnly예요. 직원이 쓰는 세 창구에도 하루 상한과 check_log를 둬요.
7. depositImport 확인할 것
   - rows ≤ 1000이에요.
   - 금액은 양의 정수예요.
   - 날짜는 최근 400일 안이에요.
   - sender는 40자로 자르고, 화면에 쓸 때는 esc를 해요.
   - kind는 정해진 5가지 중 하나만 받아요.
   - uniq_key로 같은 줄이 두 번 들어가지 않게 막아요.
   - 엑셀로 넣은 sender가 알림톡 변수에 들어가지 않는지 확인해요. 지금 depositNotice는 청구서 이름만 써요.

## 체크 v47 덧붙임 — 거래처 부품 cpt 1.1 (8df9786) — 2026-10-17 검사: **보안 통과** · 다만 서버와 «약속 모양»이 어긋나요(기능 문제 · 꼭 맞춰야 함)
- 보안
  - 1.1은 `체크/부품/거래처_부품_1.1.js`와 글자 그대로 같아요.
  - 사진에서 읽은 연락처·이메일은 빈 칸에 `input.value`로만 넣어요.
  - 국세청 결과는 `textContent`로만 보여 줘요.
  - 휴업·폐업 경고는 한 번 더 묻기만 하고, 저장을 막지는 않아요.
  - 직원 창에서 확인을 부르면 서버 bossOnly가 거절하고 catch로 넘어가요. 해 될 것 없어요.
- **어긋남 (기능 · 체크 방과 서버 방이 맞춰야 함)**
  - 화면은 `bizVerify({no, ceo, start})`로 보내는데, 서버(v37·v38)는 `{bizNo, ceo, openDate}`를 받아요.
    - 그래서 서버에는 번호가 비어 들어가요. 서버가 «10자리 아님 → ready:true, state:"없음"»을 돌려줘요.
    - 그러면 화면은 **모든 번호를 «국세청에 등록되지 않은 번호예요»로 보여 주고, 저장 전에 경고**해요.
    - 이 일은 열쇠가 없어도 생겨요. 서버는 10자리 검사를 열쇠 검사보다 먼저 하기 때문이에요.
  - 답 모양도 달라요. 서버는 `closedAt`과 `match: true|false|null`을 주는데, 화면은 `since`와 `match:{ceo,start}`를 기대해요.
  - 고칠 방법: 이음새(체크 v47 6241줄)에서 `{bizNo:q.no, ceo:q.ceo, openDate:q.start}`로 바꿔 보내고, 답의 closedAt→since, match→{ceo:match, start:match}로 바꿔 넘겨요. 아니면 서버가 두 모양을 다 받아도 돼요.
- 참고(한도): 번호가 들어 있는 창을 열 때마다 국세청 확인이 한 번 가요(같은 화면 안에서는 기억함). 하루 100번 한도라서, 상사를 많이 열어 보면 금방 쓸 수 있어요. «창을 열 때는 하지 않고, 번호를 고치거나 [확인]을 누를 때만» 하는 쪽을 추천해요.

  - 기록과 답에는 정해진 글만 나가요. 국세청에서 온 원문 오류는 남기지 않아요.
- **약속 모양 (f265a81):** {no, ceo, start}와 예전 {bizNo, openDate}를 둘 다 받아요. 답에는 since와 match:{ceo,start}가 들어 있어서 체크 v47 cpt 1.1과 맞아요.
- **순서 (698cce3):** 열쇠 확인을 10자리 확인보다 먼저 해요. 그래서 열쇠가 없으면 늘 ready:false이고, «등록 안 된 번호»라는 엉뚱한 경고가 나오지 않아요.

- 입금 처리(a4936b5)는 앞에서 통과했어요. SQL 14를 **v38보다 먼저** 넣어야 «알림은 입금마다 평생 한 번»이 지켜져요(서버 방이 배포 안내에 적기로 함).
