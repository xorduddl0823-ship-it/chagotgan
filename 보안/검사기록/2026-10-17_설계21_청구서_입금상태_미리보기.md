# 설계 21 미리 보기 — 청구서 입금 상태 그때그때 (2026-10-17 · 보안 방)
- 대상: `서버/설계/21_청구서_입금상태_그때그때.md` (811ff3b · 코드 아님)

## 판정
**방향 좋아요(② 추천 동의).** 높음·중간 없음. 만들 때 아래를 지켜 주세요.

1. **저장할 때 (viewBill · sb17)**
   - id 는 이 업체(`shop`)의 `intakes` 이고 `demo=false` 인 것만 남겨요.
   - **이 청구서의 받는 곳(딜러·상사)과 달(month)에 맞는 일감인지**도 확인하면 좋아요. 그래야 대표가 실수로 다른 딜러 일감 id 를 섞어 넣어도, 그 딜러의 금액·입금 상태가 남에게 보이지 않아요.
   - 한 청구서에 id 상한(예: 500개 · 40자)을 둬요. 같은 id 가 두 번 들어오면 하나로 줄여요.
2. **읽을 때 (d9 myBills · viewCar bill)**
   - 저장된 id 를 그대로 믿지 말고, 읽을 때도 `shop + intakes + demo=false` 로 다시 걸러요(설계대로).
   - 지워진 일감은 «입금 전 0원»이 아니라 빼고 셈하거나 찍어 둔 값을 쓰세요(합이 틀어지지 않게).
   - 돌려주는 것은 **줄별 상태(입금/미입금)·금액**과 합계뿐이에요. 일감 메모·전화·사진·작업자 같은 다른 칸은 내보내지 않아요.
   - 금액은 서버가 장부에서 셈한 값을 써요. 화면이 보낸 값은 쓰지 않아요.
3. **딜러 범위**: myBills 는 지금처럼 로그인한 본인 번호가 `to_phones` 에 있는 청구서만 봐요. 보기 주소는 열쇠·기한 규칙 그대로예요.
4. **기록**: 입금 상태가 바뀌어 보이는 것은 읽기만 하니 따로 기록하지 않아도 돼요. viewBill 저장 때 버린 id 수는 기록에 남기면 문제 찾기에 좋아요.

코드(sb17 · d9 · 워시 화면)가 오면 이 목록으로 검사할게요.

# 코드 검사 — 워시 sb17 · 딜러 d9 (57cbcf9 · SQL 없음)
**통과.** 높음·중간·낮음 없음. sb16·d8 과 풀어서 비교했어요(105줄 · 72줄).
- 저장(viewBill): `billRowId` 는 `[A-Za-z0-9_-]{1,40}` 만 받아요. `billKeepIds` 는 로그인한 업체(s2)의 intakes·demo=false 이면서 받는 곳(딜러·상사 이름)과 달이 맞는 것만 남겨요. 겹치면 하나로 줄이고, 버린 수는 서버 기록에만 남겨요. ✅
- 읽기(viewCar 청구서·myBills): shop 은 보기 코드 줄(`vc.shop`·`v.shop`)에서 읽어요(화면 값 아님). 다시 `shop+intakes+demo=false` 로 거르고, 지워진 일감이 있거나 id 가 없으면 찍어 둔 값을 써요. 금액은 장부 `total`·`status` 로 셈하고, 청구 금액을 넘지 않게 잘라요. ✅
- 내보내는 것: 줄별 `paid`(참/거짓) · 합계 `paid·due·paidAt` 뿐이에요. 줄의 `id` 는 지우고 보내요. 메모·전화는 안 나가요. ✅
- myBills 범위는 그대로 `to_phones` 에 본인 번호예요. ✅
