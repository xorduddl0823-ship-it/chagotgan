## 4. 최종 보안 판정 — **아직 «통과» 아님**
- 서버 · 워시 · 체크 방의 이번 마감 결과물(멱등 키 · 저장 뒤 발송 · 중복 발송 방지 diff)이 아직 보안 방에 오지 않았어요. 오면 diff 를 보고 이 문서에 판정을 덧붙여요.
- 출시 차단(보안 몫):
  1. A/B 시험 실제 실행 결과(필수 28개 통과) — 기록 · 청구서 · 사진 · 딜러 포함.
  2. 서버 방 고친 판 diff 의 보안 검사(멱등 키가 업체 단위로 묶이는지 — 다른 업체의 같은 키와 섞이지 않게 `업체 + 키` 유일).
  3. wash_sendlog 번호 · 본문 저장 정리(중간) — 출시 전 고침 권함, 안 되면 «RLS 켜짐 · 바깥 정책 0» 확인으로 대신.
- 중복 사업자번호 출시 차단 5가지(2차/보안방/보안방_2차.md §5)와 함께 봐야 해요.

## 7. 서버 방 고친 판 판정 (sb28 · v53 · SQL 26) — **통과 · 고칠 것 1(중간 · 워시 화면이 rid 를 보내기 전에)**
- rid 열쇠: 워시 = 업체 + 로그인한 사람 + 기능 + rid(로그인 없으면 안 씀) · 체크 = 검사소 id + 사람 + 기능 + rid · 기사 = 'drv' + 열쇠 sha256 앞 12바이트. rid 만으로 남의 답을 받는 길 없음(§5 조건 충족). cgg_idem RLS 켜짐 · 정책 없음.
- 실패하면 줄을 지워 다시 하기 · 처리 중이면 «처리 중이에요» · 24시간 지나면 새로.
- 체크 ataSend · 도착 알림: 빈 값(«-»)이면 알림톡 대신 대체 문자. wash_sendlog 새 줄: 번호 가림 · 본문 대신 «len:바이트» (§3 중간 → 닫힘, 옛 줄은 그대로 남음).
- **고칠 것(중간)**: idemRun 이 «어떤 기능이든» 답 전체(result)를 cgg_idem 에 24시간(이상) 남겨요. 워시 userAdd · userPw 는 답에 **임시 비밀번호(pw)** 를 돌려주므로, 화면이 여기에 rid 를 붙이면 평문 비밀번호가 표에 남아요. 지금 워시 화면(v142)은 rid 를 안 보내서 아직 안 일어나지만, 워시 화면이 rid 를 보내기 전에 ①rid 를 받는 기능을 «쓰기 목록»으로 정하고 ②답은 {ok · id} 같은 요약만 저장(비밀번호 · 열쇠 · 목록은 저장 안 함)으로 고쳐 주세요. 체크는 직원 · 기사 비밀번호를 답에 안 실어서 해당 없음.
- 낮음: 처리 중(run) 줄이 서버가 중간에 끊겨 남으면 같은 rid 가 24시간 «처리 중» — run 이 몇 분 넘게 남으면 낡은 것으로 보고 다시 하게 권함. 지운 줄 정리는 2% 확률이라 오래된 줄이 남을 수 있음(위 요약 저장이면 위험 낮음).
