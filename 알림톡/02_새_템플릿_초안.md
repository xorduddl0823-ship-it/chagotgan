# 손님 여정 지도 · 새 템플릿 초안 (알림톡 방 · 2026-10-15)

> 목표: 딜러·상사가 **알림톡만 보고** 「내 차가 어디 있고, 지금 어디까지 됐고, 얼마를 언제 어디로 내는지」 알 수 있게.
> 지킬 것: 정보성만(권유 문장·결제 버튼 없음) · 맨 아래 「누가 왜 보내는지」 밝히기 · 변수는 서버가 이미 가진 값만.
> 새 템플릿은 **통과 8개와 따로** 등록해요. 하나가 반려돼도 다른 안내는 그대로 나가요.

## 3. 딜러앱
- 딜러앱 인증번호는 **새 템플릿이 필요 없어요.** `차곳간_인증번호`(통과)를 같이 쓰면 돼요. 변수 `#{인증번호}` `#{유효시간}` (딜러 방 문서의 `#{분}` 이 아니에요). (서버 방 설계 10 표에도 같은 내용이 있어요.)
- 딜러앱 「알림」 탭은 위 ①~⑧ 기록을 모아 보여 주기만 해요. 같은 단계 이름(입고 · 작업 중 · 추가 작업 · 완료 · 출고 · 청구 · 입금 확인)을 쓰면 알림톡과 앱이 똑같이 읽혀요.
- 나중 것(재검사 다가옴 · 딜러가 여러 업체 대금 한 번에 결제)은 그 기능이 열릴 때 초안을 만들어요. 지금 등록하면 쓰지 않는 템플릿이 돼요.

## 새 F. 차곳간_자동결제실패 (업체 대표 · 결제 방 요청 · 서버 키 `bill_fail`)

※ 이 메시지는 차곳간 자동 결제를 신청하신 고객님께 자동 결제가 승인되지 않았을 때 발송됩니다.
문의: 010-9559-3663

대체 문구: `[차곳간] #{업체명} 이용요금 자동 결제 실패(#{사유}). 다음 시도 #{다음시도일}. 문의 010-9559-3663`
- 결제 방 예시에서 바꾼 곳: 「카드를 바꾸시려면 … 바꿀 수 있어요」→ 「등록된 결제 카드는 … 확인하실 수 있습니다」. 「바꾸시려면」은 행동 권유로 읽혀 반려될 수 있어서, **사실(어디서 볼 수 있는지)** 만 알려요. 금액·요금제·결제일을 넣어 「무슨 결제가 왜 안 됐는지」 한눈에 보이게 했어요.
- 변수 (서버 방과 맞출 이름 — 결제 요청서 v2 에는 아직 이름이 없어 알림톡 방이 정함, 요청서 `04_…` ⑧):
  | 변수 | 넣는 값 (예시는 가짜) |
  |---|---|
  | `#{업체명}` | `wash_shops.name` |
  | `#{결제일}` | 처음 결제하려던 날 (`paid_until`) 「10월 15일」 — 다시 시도한 날이어도 **처음 날** |
  | `#{요금제}` | 요금제 이름 (sb6 `planName`) |
  | `#{금액}` | 이번에 결제하려던 금액, 숫자와 쉼표만 「55,000」 |
  | `#{사유}` | 카드사·토스 오류를 **짧은 우리말**로 바꾼 것: 「잔액 부족」「카드 한도 초과」「카드 유효기간 지남」「카드사 승인 거절」, 모르면 「카드사 사정」. **카드 번호·영문 오류 코드는 넣지 않음** |
  | `#{다음시도일}` | 다음 시도 날 「10월 16일」 |
- 규칙 4-1: 오류 안내라 「~습니다」체.
