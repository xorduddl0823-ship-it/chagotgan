# [작업 요청서] 알림톡 — sb6 확인 결과와 남은 것

> 처음엔 「변수 이름을 확정본에 맞춰 달라」는 요청이었는데, 쓰는 사이 서버 방이 **sb6** 로 이미 맞췄어요.
> 알림톡 방이 sb6 `ATA_TPL` 을 확정본 13개 원문과 글자 단위로 대조했어요 → **통과 8개 변수·대체 문구 모두 일치**, 금액 숫자만(`won`), 실패하면 대체 문구로 문자(`disableSms:false` + `text`). 아래는 남은 작은 것만이에요.

```
[작업 요청서]
보내는 곳: 알림톡 방
받는 곳:   서버 방 (워시 방 참고)
제목:      알림톡 sb6 뒤 남은 것 7가지

1. 왜 필요한가요?
   업체 대표·딜러가 받는 안내가 정확해야(맞는 템플릿·맞는 값) 혼란이 없어요.

2. 무엇을 해 주면 되나요?
   ① hqPayMark(입금됨): 그 결제가 캐시 충전이면 "pay" 대신 "charge"(충전완료)로.
      지금은 늘 결제완료라, 충전 입금에도 「요금제·이용 기한」이 찍혀요.
   ② 빈 값: 지금 빈 칸을 "-" 로 채워요. 「-까지」「홍길동님(-)」이 되지 않게
      업체 대표 안내(서버가 채우는 것)에서는 빈 값이면 알림톡 대신 대체 문구 문자로,
      또는 상사명 빈 값은 「개인」으로.
   ③ 체크 차량도착: 새 템플릿 「차곳간체크_차량도착」 초안을 알림톡 방이 다듬었어요
      (알림톡/02_새_템플릿_초안.md 새 C). 서버 방 초안 ②와 변수 이름은 똑같아요.
      통과되면 check-api notifyOne 에 본사 채널 연결해 주세요.
   ④ 결제 버튼: 토스페이먼츠 승인 예정일, 「청구 건 하나를 로그인 없이 코드로 열어
      결제까지 가는 화면」을 만들 수 있는지 알려 주세요(알림톡/03_결제버튼_검토.md).
   ⑤ 「무료」는 카카오 금지어예요. 반려 5개의 #{무엇} 값 「무료 체험」→「체험 기간」,
      이용제한시작 꼬리말의 「무료 체험」→「체험 기간」(설계 09). 대체 문자도 같이.
   ⑥ 새 템플릿 「차곳간_접속주소안내」(워시 직원, 02 새 E): #{접속주소} 에는
      열쇠 없는 「직원용 주소」만. 열쇠가 섞인 주소면 보내지 않게 막아 주세요.
   ⑦ 인증번호 알림톡: 경비실(cgg-api)·딜러(dealer-api)·체크 첫 비밀번호(check-api)도
      차곳간_인증번호 하나로(변수 인증번호·유효시간). 체크 차량 도착은 알림톡 때도
      대체 문자 글(text)을 넣고 대신 보내기 늘 켜짐으로(체크 방 목록 1번 ①②).

3. 끝났다고 보는 기준
   ① 시험: 캐시 충전 결제를 입금됨으로 바꾸면 charge 템플릿으로 나감
   ② 시험: 상사명 없는 출고안내에 「(-)」가 안 찍힘
   ③④ 답 한 줄씩

4. 기다리는 다른 일
   대표님의 새 템플릿 등록(차량도착·캐시소멸예정) — 문안은 준비됨

5. 보안 검토 필요?  예 — ⑥ 접속 주소에 열쇠가 섞이지 않게 (나머지는 값 채우는 방식만)
```
