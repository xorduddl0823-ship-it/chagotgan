> 실제 전산에는 아무것도 저장하지 않았습니다. 실제 자동 저장은 아직 막혀 있습니다(아래 4장).

## 2. 대표님이 이미 정하신 것 (10/19 · 고정 결정 문서에 기록)

1. **세 전산 번호 순서**: 카인포에서 정확히 등록(저장해야 번호 생김) → 카모두 «수동입력» 체크 후 카인포 번호 손입력 → 엔트리 [간편 접수]가 **스스로 매긴 번호**를 그대로 불러와 등록.
2. **엔트리 번호 칸은 프로그램이 절대 고치지 않음.** 고쳐 쓸 수 있는 칸이지만, 잘못 넣으면 엔트리 번호가 꼬여 큰일이 남. → 방이 만들어 두었던 «번호 직접 넣기» 기능은 **아예 뺌**(번호 칸에 값을 넣는 코드가 없음을 시험으로 확인).
3. 엔트리 문자 인증은 매 로그인·접속이 끊길 때마다 사람이 함(프로그램은 우회·억지 연장 안 함).

## 3. 실제 화면에서 확인한 것과 프로그램 반영

### 카인포
| 확인한 것 | 반영 |
|---|---|
| [신규등록] → 차량조회 창(점검원 · 차량번호 · 개인간 거래 · 딜러 검색 → [선택] → [확인]) | 기존 신규등록 기능과 같음 — 흐름 안에 «카인포 신규등록» 단계로 넣음(한 작업에 한 번만, 다시 하지 않음) |
| [확인] 바로 뒤 «성능이 등록되었습니다» · 목록에 그 차 줄이 **바로 생김**(번호 빈칸 · «점검중») · 성능번호 칸 «자동발급» 대기 | **번호는 [저장]할 때 생김**(대표님 말씀과 같음) · 줄이 먼저 생기므로 저장 확인은 목록 «점검상태»가 **«점검완료»**일 때만 |
| 차대번호 뒷 6자리 · 현재주행거리는 신규등록 직후 빈칸 | 프로그램 «값 넣기» 단계에서 채움(기존 기능) · 넣은 뒤 되읽어 안 남아 있으면 저장 전에 멈춤 |
| 목록 칸: # · 점검일자 · 차량번호 · 성능점검번호(«재성능» 표시가 붙기도) · … · 점검상태 / **차대번호 칸 없음** | 번호는 숫자만 골라 읽음 · 차대번호는 **이번에 새로 생긴 그 줄 하나만** 눌러 위쪽 차량정보에서 읽어 17자리 비교 |
| 같은 차의 예전 «점검중(반환)» 줄이 번호 없이 여럿 | 번호 없는 줄은 새 번호 후보가 아님(시험으로 확인) |
| [차량사진] 창(앞면·뒷면·좌측면·우측면…) · 점검완료 차에도 사진이 올라가 있음 · [전체삭제]·칸별 ✕ 있음 | 사진은 **저장 뒤** 올림 · 지우기 단추는 누르지 않음 · 올린 칸을 기록해 다시 할 때 못 올린 칸만 |

### 카모두
| 확인한 것 | 반영 |
|---|---|
| «점검번호» 칸 기본 «자동입력»(잠김) + **«수동입력» 체크를 켜야** 칸이 열림 | 예전 짐작(«자동 부여»를 끔)을 버리고 **«수동입력» 켜기 → 카인포 번호 넣기**로 고침 · 이미 켜져 있으면 그대로 · 저장 전에 «수동입력 켜짐 + 번호 같음»을 다시 확인 |
| 접수차량 리스트: 성능번호 · 접수일 · 검사일 · 차량번호 · **차대번호 17자리** · … · 맨 끝 ✕(지우기) | 목록에서 차대번호까지 바로 비교 · ✕는 누르지 않음 |
| 탭 4개(④ 자동차사진) | 사진은 저장 전에 ④ 탭에서(기존 기능) |

### 엔트리
| 확인한 것 | 반영 |
|---|---|
| 로그인마다 문자 «본인확인»(3분) · 한동안 안 쓰면 끊김 | 카인포 저장 **전에** 엔트리 로그인부터 확인 → 끊겼으면 «문자 인증 로그인» 안내 후 멈춤(카인포만 저장되고 엔트리가 꼬이는 일 방지) |
| 목록: 성능번호 **«26-28-604413»(줄표)** = 카인포 «2628604413» · 차량번호 **«****5528»(앞을 가림)** | 번호는 숫자만 비교 · 가린 차량번호는 보이는 뒷자리(4자리 이상)로 맞춰 보고, **번호가 카인포와 같아야** 끝 · 그런 줄이 둘 이상이면 멈춤 |
| [간편 접수] → «불러올 성능번호» 창에 **다음 번호(카인포 마지막 + 1)가 미리 들어감** → [불러오기] | 미리 들어간 번호가 이 차 카인포 번호와 **같을 때만** 불러옴, 다르면 멈춤(번호 칸은 건드리지 않음) |
| 없는 번호면 «성능 불러오기가 실패하였습니다» | 카인포 기록이 아직 안 넘어온 것으로 보고 3초 간격 3번까지 다시 불러옴(보기만 하는 일이라 안전) → 그래도 안 되면 멈춤 |
| 불러온 화면: 차량번호·**차대번호 17자리가 가리지 않고** 보임 · 점검 내용·사진(«2/2»)도 카인포에서 채워짐 | 저장 전에 번호·차량번호·차대번호 17자리가 모두 같아야 저장 · 엔트리는 따로 사진을 올리지 않음 |
| 맨 아래 [저장]은 새 기록이면 켜지고, **이미 등록된 것은 꺼져 있음** | [저장]이 꺼져 있으면 누르지 않고 «이미 등록됨 의심»으로 멈춤(두 번 등록 막기) |

### 오류 안내 (7차 지시 4번)
- 번호가 어긋나면 «① 세 전산에서 실제 등록 상태 확인 ② 관리자 정정 절차 확인 ③ 대표님(관리자)께 알리기». **«지우고 다시 등록»은 기본 안내에서 뺌.**
- 이런 멈춤에는 [이어 하기]를 숨겨, 정정 절차를 건너뛰지 못하게 함.

## 4. 아직 모르는 것 · 자동 저장이 막혀 있는 까닭

화면 사진으로는 **«무엇을 누르면 어느 주소로 저장 요청이 가는지»**를 알 수 없습니다.
세 전산 모두 이 값(저장 단추·저장 요청 주소·조회 주소·신규등록/사진 요청 주소·화면 칸의 내부 이름)이 비어 있어 `confirmed: false` → **프로그램은 저장 전에 멈춥니다**(실제 프로그램 시험으로 확인).

**다음 차수(8차) 계획**: «저장 요청을 붙잡아 기록만 하고 보내지 않는 진단 기능»을 만들어, 대표님 PC에서 원격으로 함께 세 전산의 값을 확인 → 실제 저장 없이 «저장 직전까지» 시험 → 통과한 전산만 자동 저장을 켬.

## 5. 검수 때 봐 주셨으면 하는 점
1. 카인포 저장 확인을 «점검완료» 상태로만 하는 판단이 맞는지(신규등록 때 줄이 먼저 생기므로 «줄이 있다»는 증거가 못 됨).
2. 엔트리 가린 차량번호를 «보이는 뒷자리 + 번호 일치 + 줄 하나»로 판단하는 것이 충분한지.
3. 엔트리 «불러오기 실패» 때 3번까지 다시 불러오는 것이 안전한지(불러오기는 저장이 아님).
4. 엔트리 [저장]이 꺼져 있으면 멈추는 것으로 두 번 등록을 막는 판단.
5. 8차 진단 기능(저장 요청을 붙잡아 기록만) 순서가 적절한지.

※ 기관에 묻는 조건은 두지 않습니다(대표님 10/18 결정 — 가온 자체 판단으로 운영).
