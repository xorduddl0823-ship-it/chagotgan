## 2. 바뀐 것

### 2-1. 진단 중 데이터 변경 막기 (지시 1)
| 지시 | 반영 |
|---|---|
| GET 방식 변경 가능성 검토 · **안전한 조회만 허용** | 막는 방식을 «쓰기만 막기»에서 **«허용 목록»**으로 바꿈. 내보내는 것은 ① 그림·글꼴·모양·코드 파일 GET ② **그 전산 주소**로 가는 화면·조회 GET 중 주소와 물음표 뒤(이름·값)에 저장·등록·삭제·전송 같은 말이 없는 것 — 이 두 가지뿐. 나머지(POST·PUT·PATCH·DELETE, 저장처럼 보이는 GET, 다른 주소로 가는 화면·조회·iframe, 실시간 연결·신호)는 모두 막음 |
| 저장·신규등록·사진·전송이 서버에 안 가게 | **두 겹 막기**: ① 세션 거르개 — 그 전산 **세션 전체**(본 창·팝업·iframe·작업자)의 모든 요청이 지나는 곳에 진단 시작 «전»에 검 ② 창별 붙잡기(개발자 연결) — 같은 판단으로 한 번 더 |
| 팝업·iframe 이 준비 전에 조작되지 않게 | 세션 거르개는 세션 단위라 **팝업 첫 요청·iframe 요청부터** 걸림. 팝업의 창별 붙잡기가 정해진 시간(2초) 안에 안 붙으면 **진단 중단** |
| 차단 범위를 보장 못 하면 중단 | 다른 세션 창이 열리거나, 막는 장치가 붙지 않은 창이 남으면 **스스로 멈추고** 같은 세션 팝업을 닫은 뒤 막기를 풂. 창별 붙잡기를 못 켜면 **시작하지 않음**(세션 거르개도 풂) |
| 실제 차량 자료로 시험 안 함 | 모의 서버·가짜 값만 사용 |
| (따라 바뀐 것) 로그인 | 진단 중에는 로그인 요청도 막히므로 **로그인은 진단 전에**. 엔트리는 [엔트리 창 열기 (로그인용)] → 로그인(문자 인증) → [엔트리 진단 시작]. 카인포·경기조합은 맨 위 [창] 단추로 열고 로그인한 뒤 진단 시작 |

### 2-3. 기존 기능 유지 (지시 4)
- 자동 등록 엔진·입력 화면 그대로. 카모두(경기조합)는 [저장]만, 엔트리는 [저장]만·번호 칸 안 고침. 실제 자동 저장 계속 꺼짐.
- **엔트리 미구현 표시**: 자동 등록 확인 창에 «엔트리 자동 등록은 아직 준비 중이에요 — 카인포·경기조합(카모두)까지 하고 멈춰요. 엔트리는 직접 등록해 주세요.»(연결 모듈이 생기면 저절로 사라짐). 멈춤 보고에도 이미 «엔트리는 직접 등록».
- 진단 끝나면 막기가 모두 풀려 기존 기능이 예전처럼 동작(시험으로 확인).

## 4. 진단 도구 사용 범위와 한계
**쓸 수 있는 것**
- 로그인한 뒤(로그인은 진단 전) 화면을 열며 [지금 화면 칸 기록] → 단추·칸 이름·표 머리글·값 지운 화면 뼈대 확보.
- 화면을 여는 데 필요한 **조회** 요청의 경로·이름 확인.
- 화면에서 [저장]·[신규등록]·[사진]·[전송]을 눌렀을 때 «어느 주소로 무슨 칸 이름을 보내려 했는지»(서버로는 안 감) — 단, 아래 한계 3 때문에 **실제 전산에서 [저장] 누르기는 아직 하지 않음**.

**한계**
1. 화면을 그리는 데 쓰는 조회 GET 중 주소에 저장 같은 말이 들어간 것도 막으므로, 일부 화면이 덜 그려질 수 있음(안전 쪽 선택).
2. 사람 이름처럼 무늬 없는 글자는 무늬로 못 찾음 → 화면 뼈대에서 표·글 칸 글자를 통째로 지우고, 단추·머리글·이름표 글자만 남김. 단추 글자에 이름이 들어간 화면이면 남을 수 있음(«이름 (아이디)» 모양은 가림).
3. 막기는 모의 서버에서 검증했지만 **실제 전산에서는 아직 검증 전**. 지시대로 실제 차량 기록에 [저장]을 눌러 시험하지 않음. 실제 전산에서는 우선 «화면 칸 기록»만.
4. 사이트가 프로그램 밖(다른 브라우저·다른 세션)으로 연 창은 막을 수 없음 → 그런 창이 생기면 진단 중단.
5. 엔트리 주소는 대표님이 진단 창에 넣어야 함.

## 5. 실제 전산 연결 남은 작업 (우선순위)
1. 대표님 PC에서 **진단 1단계**: 세 전산 «화면 칸 기록»만([저장] 안 누름) → 기록 파일 받기
2. 기록 파일로 화면 구조·조회 방식 확인 → **엔트리 연결 모듈** 만들기([간편 접수] 열기 · 미리 들어간 번호 읽기 · [불러오기] · [저장] · 상세 확인) · 세 전산 설정 채우기
3. 실제 전산에서 막기가 되는지 **데이터가 바뀌지 않는 방법**으로 확인하는 절차를 검수받은 뒤에만 저장 요청 모양 확인
4. 모의 시험 → 실제 전산 «저장 직전까지» 확인
5. 대표님이 지켜보는 가운데 한 대로 첫 실제 자동 저장 → 통과한 전산만 `confirmed: true`
6. 처리 시간 측정 · 관리자 정리 화면 · 기본 경고창 정리
