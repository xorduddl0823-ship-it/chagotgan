## 2. 최종 운영 방식과 5차 설계의 차이 → 이번에 바꾼 것

| 5차 | 최종 지시 | 이번 변경 |
|---|---|---|
| 전산마다 사람이 [저장해도 돼요] → 사이트에서 [저장] | 정상이면 사람 조작 없음 | `runAll()`: 값 넣기 → 저장 전 확인 → 통제기 허락 → **프로그램이 [저장]** → 응답·목록으로 검증 → 다음 전산 |
| 단계마다 사람이 다음을 누름 | 한 번 시작 → 끝까지 | 한 번 호출로 세 전산 + 닫기, 진행은 화면 글로 |
| 엔트리 «다음 번호»는 참고 경보 | 엔트리 자체 번호 규칙도 검증 | 엔트리 값 넣기 전에 «다음 번호 = 카인포 번호» 확인, 다르면 멈춤 |
| 멈추면 까닭만 | 차량·전산·원인·단계·조치 출력 | `explain` 모양으로 «할 일» 한 줄까지 |
| 사진 흐름 밖 | 사진도 한 번 입력 | 값 넣기 단계 사진 주소 허용(fillAllow) 구조 — 실제 주소 확정 뒤 켬 |

## 3. 가온 프로그램 기존 입력 기능 재사용 방법
- 입력은 **기존 화면 그대로**: 121칸(`src/schema.js`) · 절개도 · 사진 8칸 · [신규등록 + 차량정보·차대번호 가져오기](원부·차대번호 자동).
- 값 넣기는 **기존 전송 함수 그대로**: `main.js sendToSite()`(예전 [카인포만]/[경기조합만]이 쓰던 것) → `filler.js` 그대로. 리콜 뒤집기 표 등 그대로.
- 딜러 동명이인도 **기존 고르기 창 그대로**(멈춤 → 고르기 → 이어 하기).
- 새로 더한 것은 **단추 하나(+이어 하기)와 결과 창 글**, 그리고 엔진(`src/core/register-flow.js runAll`)뿐. 설정 `flow` 를 끄면 예전 화면 그대로.

## 4. 완전 자동 등록을 위한 남은 우선순위
1. **실제 화면 자료 받기**(대표님 PC 화면 사진): 카인포 목록·저장 직후, 카모두 1번 페이지(«자동 부여»·번호 칸)·저장 단추·목록, 엔트리 로그인·다음 번호·불러오기·저장
2. `site-config.js` REAL 채우기 → 흉내 사이트를 실제 화면 모양으로 고쳐 모의 시험 다시
3. 엔트리 연결 모듈
4. 실제 전산에서 «저장 직전까지» 1대 → 이상 없으면 `confirmed:true` 하나씩
5. 사진 주소·[신규등록] 흐름 안으로
6. 차곳간 CHECK 새 화면(시안 A/B 고른 것) — 메인 입력 · 진행 · 완료 · 오류
7. 실제 걸린 시간 측정(손으로 할 때와 비교)
