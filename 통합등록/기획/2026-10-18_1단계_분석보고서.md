**번호 흐름 (확정 · 10/18 대표님 바로잡음)**
```
카인포 점검 입력 → 사람이 [저장] → 저장이 끝나야 점검번호 생김
      → 프로그램이 저장 끝난 것을 알아채고 목록(또는 저장 뒤 화면)에서 그 차의 번호를 읽어 옴
      ├→ 카모두 1번 페이지: «자동 부여» 끄기 → 그 번호 넣기
      └→ 엔트리: 그 번호로 불러와 등록
세 곳 모두 «같은 번호 하나»인지 마지막에 대조
```
- 카인포 저장 전에는 카모두·엔트리로 넘어가지 않아요(번호가 없으니까).
- 번호를 못 읽으면 멈추고 «카인포 목록에서 번호를 확인해 주세요» 알림 + 사람이 번호를 넣는 칸을 보여 줘요(대신 두 번 맞는지 확인).

**⚠ 자동 조작 허용 문제 (대표님이 정하실 것)**
- 세 곳 모두 «프로그램이 대신 조작해도 된다»는 허락이 없는 닫힌 전산이에요. 이용 규칙상 금지일 수 있고, 걸리면 **계정 정지·기관 제재** 위험이 있어요. 프로그램으로 막을 수 없는 위험이라 계속할지는 대표님이 정하실 일이에요.
- 계속한다면 위험을 줄이는 방식으로 만들어요:
  1. **가온 내부용으로만** 쓰고, 기관 허락 전에는 차곳간 상용 제품에 넣지 않아요(상용화 원칙 5번).
  2. 사람이 하는 속도로 한 대씩만 조작하고, 최종 [저장]은 언제나 사람이 눌러요.
  3. 로그인·문자 인증은 사람이 해요(우회 없음, 세션 억지로 늘리지 않음).
  4. 사이트에서 읽은 내용은 그 차 등록에만 쓰고 따로 모으지 않아요.
- 할 수 있으면 기관에 «입력 도우미 프로그램을 써도 되는지» 한 번 물어 두시길 추천해요. 상용화하려면 꼭 필요해요.

| 927~947행 카모두 딜러 칸 «진짜 엔터» | 창에 초점을 준 뒤 키를 보냄 | 키를 받으려고 창을 앞으로 끌어옴 | **이미 사진 올리기에 쓰는 «개발자 연결(debugger)»로 엔터를 보냄** — 창을 앞으로 내지 않아도 사이트가 «진짜 키»로 받아들여요. 가장 유력한 대안 |
| 1214행 `win.show()` | 엔터 누르기 바로 앞에서 창 보이기 | 앞으로 나옴 | 앞으로 오지 않는 «살짝 보이기»(`showInactive`)로, 또는 필요할 때만 |
| 149~158행 팝업 열기 | 사이트 팝업을 진짜 창으로 엶 (숨김 설정 없음 — 확인함) | 새 창은 기본으로 앞에 뜸 | 진짜 창은 그대로(405 오류 때문) 두되 «처음엔 숨긴 채» 열도록 설정 |
| 사이트의 경고창(alert·confirm) | 사진 올릴 때만 소리 없이 없앰, 나머지 때는 그대로 뜸 | 뜨면 프로그램 창을 앞으로 끌어올 수 있고, 없앤 경우엔 오류를 못 봄 | 개발자 연결로 경고창 내용을 앱이 받아 **차곳간 입력 화면 가운데 팝업으로 보여 주고**, 사람이 고른 답을 넘김 |

**창을 숨긴 채 일할 수 있나? — 단계별 예상**

| 단계 | 숨긴 채 가능? | 비고 |
|---|---|---|
| 화면 이동 · 기다리기 · 값 채우기 · 클릭 | 가능할 가능성 높음 | 숨긴 창에서 계산이 느려지지 않게 «뒤에서도 속도 유지» 설정 필요 |
| 사진 올리기 | 가능할 가능성 높음 | 이미 개발자 연결 방식이라 창이 안 보여도 됨 |
| 카모두 딜러 «진짜 엔터» | 대안으로 가능할 가능성 높음 | 위 «개발자 연결로 키 보내기» 시험 필요 |
| 카인포 목록 표·모달(Vue·DataTables) | ⚠ 시험 필요 | 화면 그리기를 «보일 때만» 하는 부분이 있으면 멈출 수 있음 → 그때는 **화면 밖 먼 곳에 살짝 보이게 두는 방법**으로 대신함(작업표시줄에도 안 뜨게) |
| 사람이 꼭 봐야 하는 때 (동명이인 딜러, 원부 차이, 최종 [저장], 엔트리 문자 인증) | 사람 차례 | 창을 끌어오지 않고 **작업표시줄 깜빡임 + 윈도우 알림 + 소리**로 부름. 대표님이 알림을 누를 때만 창이 앞으로 |

→ 결론: **대부분 단계는 창을 앞으로 내지 않고 할 수 있을 것으로 봐요.** 확실한 것은 2단계 첫날 «가짜 시험 화면»으로 확인해요(실제 전산 아님).

### 2-2. 문서와 코드가 다른 곳
- README «비밀번호를 저장하지 않는다» → 실제는 «암호화해서 저장 + 자동 로그인». README를 실제대로 고침.
- README «사진 업로드 미구현», «경기조합 차량번호 조회 미연동» → 실제는 둘 다 됨. 고침.

### 2-3. 기타 고칠 것

## 3. 새로 만들어야 할 기능

### 3-1. 3개 전산 순서대로 등록하는 구조 (설계)

차 한 대 = «작업 한 건». 작업은 아래 칸을 한 칸씩만 나아가고, **이상하면 그 자리에서 멈춰요.** 지우기·취소는 앱이 하지 않아요.

```
[0 대기]
  ↓
[0-1 번호판·계기판 사진 → 차량번호·주행거리 읽기 → 사람 확인] (3-5 참고)
  ↓
[1 엔트리 로그인 확인] ── 로그아웃이면 → [1-1 문자 인증 기다림] (대표님 알림, 인증 끝나면 계속)
  ↓
[2 카인포 신규등록] → [2-1 값 채우기] → [2-2 사고 부위: 사람이 직접 누름(1차)] → [2-3 사람 확인 후 저장] → [2-4 저장 끝 알아채기 → 점검번호 읽기(새로 만듦)]
  ↓
[3 카모두 등록 → «자동 부여» 끄기 → 카인포 번호 넣기 → 값 채우기] → [3-1 사람 확인 후 저장] → [3-2 저장된 번호 다시 읽어 대조]
  ↓
[4 엔트리 로그인 다시 확인] (2·3번 하는 사이 30분이 지났을 수 있음)
  ↓
[5 엔트리 안전문 3중 확인: ① 엔트리 «다음 번호» = 이 차 카인포 번호 ② 불러온 차량번호 = 이 차 ③ 불러온 차대번호 = 이 차] → 하나라도 다르면 ⛔ 즉시 멈춤 · 엔트리 저장 단추 잠금
  ↓
[6 사람 확인 후 엔트리 저장]
  ↓
[7 세 곳 저장 결과 다시 읽어 최종 대조] → ✅ 끝  /  ❌ «복구 안내» 화면
```

**지켜야 할 규칙**
- 번호가 하나라도 다르면 **즉시 멈추고**, 무엇이 다른지(어느 전산, 기대 번호, 실제 번호) 보여 줌. 앱은 고치거나 지우지 않음.
- 한 번에 **한 대씩만** 진행. 대기열에 여러 대를 쌓아 두는 것은 가능.
- ⛔ **앞 차의 엔트리 등록이 끝나기 전에는 다음 차의 카인포 저장을 하지 않아요.** 카인포 번호가 엔트리 다음 번호보다 앞서 나가면 엔트리 순서가 어긋나기 때문이에요. (프로그램이 다음 차 카인포 저장 단계를 잠가 둠)
- 앞 차가 엔트리에서 멈추면(번호 다름·로그아웃 등) 대기열 전체가 멈추고, 대표님이 정리하신 뒤에만 다시 움직여요.

**엔트리 안전문 — 3중 확인 (가장 중요)**
| 확인 | 무엇과 무엇을 | 다르면 |
|---|---|---|
| ① 번호 | 엔트리가 보여 주는 «다음 번호» ↔ 이 차의 카인포 점검번호(저장 뒤 읽은 것) | 즉시 멈춤 · 저장 잠금 · «엔트리 다음 번호 ○○○, 이 차 번호 ○○○ — 다른 차 기록이 들어갈 수 있어요» |
| ② 차량번호 | 엔트리가 끌어온 차량번호 ↔ 이 차 차량번호 | 즉시 멈춤 · 저장 잠금 |
| ③ 차대번호 | 엔트리가 끌어온 차대번호 ↔ 이 차 차대번호 | 즉시 멈춤 · 저장 잠금 |
- 셋 다 맞을 때만 «엔트리 저장» 확인 창을 띄워요(«12가3456 · 카인포 번호 ○○○ 를 엔트리에 등록할까요?»). 최종 저장은 사람이 눌러요.
- 번호만 맞고 차량번호·차대번호를 못 읽으면 «맞음»으로 치지 않고 멈춰요(모르는 것은 통과 아님).
- 앱은 엔트리에서 지우기·고치기를 하지 않아요. 멈춘 뒤 정리는 대표님이 해요.
- 엔트리 확인을 **카인포 저장 직전에 한 번 더** 하는 것도 검토 — 카인포 저장 뒤에 엔트리가 끊겨 있으면 되돌리기가 어려우므로. (엔트리 문자 인증 횟수 답에 따라 정함)
- 단계마다 «언제 · 어느 단계 · 결과»를 기록(차량번호 뒤 4자리 정도만, 이름·전화·로그인 정보는 기록 안 함).
- 엔트리 세션을 일부러 늘리는 기능(가짜 클릭으로 깨워 두기 등)·문자 인증 건너뛰기는 **만들지 않음.** 대신 «마지막 사용 뒤 몇 분 지났는지»만 보여 주고, 25분이 넘으면 «다시 로그인해야 할 수 있어요» 안내.

### 3-2. 엔트리 새 모듈 — 필요한 것 (⚠ 엔트리 화면을 아직 못 봄)

| 항목 | 내용 | 확인 방법 |
|---|---|---|
| 로그인 상태 확인 | 로그인 됐는지 «화면에 무엇이 보이면 로그인 상태인지» 기준 | 대표님 로그인 후 화면 조사 |
| 문자 인증 | 앱은 **인증 화면만 띄우고 사람이 번호 입력** — 앱이 문자를 읽거나 넣지 않음 | 정책 |
| 로그아웃 시간 | 약 30분 미사용 — 정확한 시간, «사용»으로 치는 동작 | 대표님 확인 |
| 번호 입력 칸 | «성능점검번호만 넣으면 내용이 자동으로 맞춰진다»(대표님 말씀) — 그 칸 위치, 넣은 뒤 무엇이 채워지는지 | 화면 조사 |
| 번호 기준 | 엔트리가 카인포 점검번호를 끌어와 등록 · **엔트리의 «다음 번호»가 이 차 번호와 같아야 함** (대표님 10/18) | 화면 조사: «다음 번호»가 보이는 자리, 끌어온 차량번호·차대번호가 보이는 자리, 번호를 사람이 바꿀 수 있는지 |
| 저장 결과 확인 | 저장 뒤 목록에서 그 차가 보이는지, 번호가 맞는지 | 화면 조사 |
| 필요한 입력값 | 번호 외에 사람이 넣는 값(사진, 가격 등)이 있는지 | 화면 조사 |

→ 엔트리 화면 조사는 **대표님이 로그인(문자 인증)해 주셔야** 할 수 있어요. 조사할 때도 실제 등록은 하지 않고 «화면 모양만» 읽어요.

### 3-5. 사진 먼저 → 차량번호·주행거리 자동 입력 (대표님 10/18 두 번째 규칙)

**순서**: 점검 입력 전에 ① 번호판 사진 ② 계기판 사진을 먼저 올림 → 프로그램이 차량번호·주행거리를 읽어 칸에 넣음 → **사람이 숫자를 확인하고 «맞아요»를 눌러야** 다음으로 넘어감.

| 항목 | 내용 |
|---|---|
| 읽는 곳 | 차곳간 CHECK 서버에 **이미 있는 «사진 읽기»**를 씀 — 번호판 읽기(`aiPlate`)는 지금도 체크에서 쓰는 중, 주행거리는 같은 방식으로 «계기판 읽기»를 하나 더 만듦 → **서버 방 일**(철칙 2) |
| 읽은 값이 들어가는 칸 | 차량번호(지금 앱의 첫 칸, 카인포 [신규등록]에 바로 쓰임) · 주행거리(`mileage` → 카모두 `#uc_mileage`, 카인포 `#distance`) |
| 사진 다시 쓰기 | 계기판 사진은 사진 8칸 중 «계기판사진» 칸(`schema.js` 83행)에 그대로 들어가 카인포·카모두에도 올라감 → 두 번 찍을 필요 없음 |
| 틀릴 때 | 숫자를 못 읽거나 흐리면 칸을 비워 두고 «직접 적어 주세요». 읽은 값이 카인포 원부(되읽기) 차량번호와 다르면 알림 |
| 꼭 지킬 것 | 주행거리는 **성능기록부에 그대로 찍히는 중요한 숫자**라 자동으로 넘기지 않고 항상 사람 확인. 사진 읽기 열쇠는 서버에만(프로그램에 넣지 않음). 사진은 읽은 뒤 서버에 남기지 않음 |
| 필요한 것 | 사진 읽기 횟수 한도(지금 체크 한도와 같이 쓸지) · 인터넷 연결 |
| 7일 안에 | 번호판 읽기는 이미 있어 **3~4일차에 붙일 수 있음**. 계기판 읽기는 서버 방이 새 창구를 만들어 줘야 해서 **서버 방 일정에 달림** |

### 3-3. 새 화면 (차곳간 CHECK·워시와 같은 모양)
필수 화면 9개: **사진 먼저(번호판·계기판) 읽기** / 통합 점검 입력 / 세 전산 로그인 상태 / 등록 진행 상황 / 차량별 작업 대기열 / 엔트리 문자 인증 알림 / 점검번호 일치 여부 / 오류·복구 안내 / 최종 저장 확인.
- 대표님 취향 반영: 짧은 안내 한두 줄, 확인 창은 화면 가운데 팝업(기본 경고창 안 씀), 되돌리기 어려운 일은 «어느 차·어느 전산·무엇을» 한 번 더 보여 주고 확인, 날짜는 달력, 표는 정렬·검색·보기 개수(5/10/20/30/50)·이름 칸 고정.
- **파일부터 만들지 않고 시안(미리보기)을 먼저** 보여 드려요(2단계).

### 3-4. 차곳간 CHECK 웹페이지 ↔ PC 프로그램 잇는 방법 (가장 큰 설계 숙제)

먼저 사실: **웹페이지만으로는 카인포·카모두·엔트리에 등록할 수 없어요.** 로그인된 사이트 화면을 조작하는 일은 대표님 PC의 이 프로그램이 켜져 있어야만 돼요.

| | A. PC 프로그램 안에 CHECK 화면 담기 | B. PC 프로그램이 서버 대기열을 가져가기 | C. PC 안에서만 열리는 연결 |
|---|---|---|---|
| 쉬운 설명 | 프로그램을 켜면 그 안에 CHECK 화면이 뜸. 화면에서 «등록»을 누르면 같은 프로그램이 바로 처리 | CHECK(폰이든 다른 PC든)에서 «등록 요청»을 누르면 서버에 쪽지가 쌓이고, 대표님 PC 프로그램이 몇 초마다 쪽지를 가져가 처리 | 대표님 PC의 크롬에서 CHECK를 열면, 같은 PC의 프로그램에 «안쪽 문»으로 바로 말을 검 |
| 장점 | 가장 단순·빠름. 서버 고칠 것 거의 없음. 차곳간 철칙 «앱은 화면을 담는 액자»와 같음. 외부에서 들어올 문이 없어 안전 | **폰에서도 요청 가능**, 프로그램이 다른 방에 있어도 됨, 진행 상황을 어디서나 봄 | 평소 쓰는 크롬 그대로 |
| 단점 | 그 PC 앞에서만 요청 가능 | 서버 방 일이 큼(대기열 표, 기기 인증, 상태 기록). 점검 내용이 서버를 거침(이미 CHECK가 저장하는 자료면 문제 적음). 몇 초 늦음 | 크롬이 «인터넷 페이지 → 내 PC 안쪽» 연결을 점점 막는 중(허락 창 뜸). 다른 웹사이트가 그 문을 두드릴 위험 → 열쇠 검사 필수. 고장 원인 찾기 어려움 |
| 7일 안에 | ✅ 가능 | △ 서버 방과 함께 해야 해 빠듯 | △ 크롬 정책 때문에 시험 많이 필요 |
| 추천 | **1차 추천** | **2차(출시 뒤)로 추천** | 비추천 |

**결정: A안 (대표님 10/18 «모바일로 등록할 일 전혀 없음»).** B안은 여러 점검장 상용화 때 다시 검토.
- A로 만들어도 화면은 CHECK와 같은 파일이라, 나중에 B로 바꿀 때 화면은 다시 만들 필요가 없어요.
- 프로그램 안에서 CHECK 화면이 쓸 수 있는 기능은 «등록 시작 · 상태 보기 · 사람 확인 답» 몇 개로만 좁히고, CHECK 주소(check.cgg.co.kr)에서만 쓰게 막아요.
- CHECK 로그인·서버 연결은 차곳간 철칙대로 **서버 방**이 맡아요.

## 5. 가장 위험한 부분 (차질 가능성 높은 순)

0. ⛔ **엔트리 다음 번호 어긋남 = 다른 차 점검기록부 등록 (대형 사고)** — 카인포에서 번호가 하나라도 건너뛰거나(저장했다 취소한 차, 엔트리에 안 올린 차 등) 순서가 바뀌면 엔트리 다음 번호가 우리 차와 달라져요. → 안전문 3중 확인 + 앞 차 엔트리 끝나기 전 다음 차 카인포 저장 잠금. 하나라도 모르면 통과 아님.
1. **한 번도 실제 등록까지 간 적이 없음** (대표님 답 1) — 특히 카인포 사고 부위 체크가 불안정. → 1차는 사고 부위를 사람이 누르는 반자동으로 가고, 2일차에 «저장 직전까지» 실제 화면에서 대표님과 확인. 실제 첫 완주는 7일차.
2. **카인포 저장 뒤 번호 읽기** (새로 만듦) — 저장 뒤 화면이 어떻게 바뀌는지(목록으로 가는지, 안내 창이 뜨는지)를 아직 몰라요. 2일차에 실제 화면을 봐야 해요. 못 읽으면 사람이 넣고 두 번 확인.
3. **카모두 번호 손입력 실수** — «자동 부여»를 안 끄거나 번호를 잘못 넣으면 카인포와 번호가 달라져요. → 앱이 끄고 넣고, 저장 전·후 두 번 대조. 다르면 멈춤.
4. **엔트리 30분 로그아웃** — 혼자 쓰셔서 다른 사람 때문에 밀릴 걱정은 없지만, 카인포·카모두 저장 뒤 엔트리가 끊겨 있으면 문자 인증을 기다려야 해요. → 시작 전·엔트리 차례 직전 두 번 확인, 끊겼으면 알림.
5. **외부 전산 허락 없음** — 세 곳 모두 닫힌 전산이고 자동 조작 허락이 없어요(대표님 10/18). 계정 정지·제재 위험. → 가온 내부용으로만 · 사람 속도·사람 저장 · 계속할지는 대표님 결정(0-1 «⚠ 자동 조작 허용 문제»).
6. **숨긴 창에서 카인포 화면이 안 움직일 가능성** — 그러면 «화면 밖 살짝 보이기» 방법으로 바꿔야 해서 하루 더 걸릴 수 있어요.
7. **사이트가 바뀌면 멈춤**
8. **주행거리 잘못 읽기** — 계기판 반사·흐림으로 숫자를 틀리게 읽을 수 있어요. → 항상 사람 확인, 자동으로 넘기지 않음. — 카인포·카모두가 화면을 고치면 칸 찾기가 틀어져요. 공개 API(정식 연결 통로)가 없어서 피할 수 없는 위험이에요. → 단계마다 «찾지 못하면 멈추고 알림»으로 피해를 줄여요.

### 보안 위험 (보안 방 검사 요청할 것)
- 로그인 정보는 Windows 암호화(DPAPI)로 저장 — 좋은 방식이지만 **같은 Windows 계정으로 켠 프로그램은 풀 수 있어요.** PC에 Windows 로그인 비밀번호를 꼭 걸어 두세요.
- 기록 파일(`records.jsonl`)에 입력 전체(고객명 포함)가 기한 없이 쌓임(확인함) → 보관 기간을 정하고 꼭 필요한 칸만 남김.
- «두 곳 전송» 때 사이트 주소를 확인하지 않고 비밀번호를 넣음(확인함) → 주소가 진짜 카인포·카모두일 때만 넣게.
- 코드 설명글에 실제 딜러 이름·전화·사업자번호가 적혀 있었음(확인함) → 원본 코드에서도 지울 것(2단계).
- 값 넣는 방식(JSON으로 감쌈)과 창 안전 설정(Node 기능 꺼짐)은 문제없음(확인함).
- CHECK 화면을 프로그램에 담을 때(A안) CHECK 주소에서만 등록 기능을 쓰게 막기.
- 이 보고서와 대화 어디에도 로그인 정보·쿠키·개인정보를 적지 않았어요.

## 8. 상용화를 생각한 제품 구조 (대표님 10/18 추가 원칙 반영)

### 8-2. 세 칸으로 나누기
```
① 점검기록부 자료 틀   — 차 한 대의 점검 내용(전산과 무관한 차곳간 표준 모양)

③ 전산별 연결 모듈      — 카인포 / 카모두 / 엔트리 각각 «①을 그 전산 칸에 넣고, 번호를 읽어 오는» 일만
```
- ③은 ①·②를 모르고, ①은 ③을 몰라요. 그래서 전산이 하나 늘거나(다른 지역 조합) 바뀌어도 ③만 새로 끼우면 돼요.
- 7일 시제품에서는 **폴더·파일 이름만 이렇게 나누고**, 안의 코드는 지금 것을 옮겨 담아요(새로 짜지 않음).

### 8-3. 여러 성능점검장이 쓸 때를 위한 준비 (지금은 칸만)
- 모든 작업·기록에 **사업장 표시**를 붙여 둬요(지금 값 = 가온 하나). 나중에 사업장별로 자료·사용자·권한을 나눌 때 다시 짤 필요가 없어요.
- 사용자·권한·로그인은 차곳간 철칙대로 **서버 방**이 CHECK 서버(이미 «사업장별» 구조)에 붙여요. 7일 안에는 하지 않아요.
- 전산 로그인 정보는 **각 사업장 PC에만** 두고 차곳간 서버에는 올리지 않는 쪽을 추천해요(남의 전산 비밀번호를 우리가 보관하는 위험을 피함).

### 8-4. 내부용 / 상용으로 나누기
| 내부용(가온만) | 상용 후보(조건 충족 뒤) |
|---|---|
| 전산 자동 조작 전부(카인포·카모두·엔트리) — **운영기관의 명시적 허용 + 개인정보 처리 조건이 확인될 때까지** | 점검기록부 입력 · 대기열 · 진행 상황 · 번호 대조 · 기록 · 알림 |
| 진단·학습 도구, 절개도 맞추기 도구 | 차곳간 CHECK 정산과 이어지는 기능 |
- 프로그램 안에 «내부용 기능 켜기» 스위치를 두고, 상용 판에서는 기본으로 꺼 둬요.

### 8-5. EXE에 묶이지 않는 최종 구조 (제안)
```
차곳간 CHECK 웹(화면 · 자료 · 사용자 · 권한)  ←→  차곳간 서버(대기열 · 기록)
                                                      ↕
                                       각 점검장 PC의 «차곳간 연결 도우미»
                                       (작은 프로그램 · 전산 연결 모듈만 담음)
```
- 화면과 자료는 웹(차곳간)에, PC 프로그램은 «외부 전산 손발» 역할만. 3-4의 **B안**이 이 모양이에요.
- 7일 시제품은 **A안(프로그램 안에 CHECK 화면 담기)**으로 가되, 화면·자료 틀을 위 모양대로 만들어 두면 나중에 B안으로 옮길 때 화면을 다시 만들 필요가 없어요.
