## 0. 맨 먼저 — 백업 상태와 이 보고서의 한계

### 백업: ❌ 아직 못 했어요 (대표님이 직접 하셔야 해요)
이 작업방은 인터넷 속 작업 공간이라 **대표님 PC의 `C:\Users\admin\Documents\carcheck-dual` 폴더에 손이 닿지 않아요.**
차곳간 저장소(chagotgan)에도 이 프로그램 코드는 들어 있지 않아요. 그래서 백업도, 코드 직접 읽기도 못 했어요.

**대표님이 하실 백업 (5분)**
1단계. 바탕화면 아래 노란 폴더 모양(파일 탐색기)을 눌러요.
2단계. 왼쪽 «문서»를 눌러요. `carcheck-dual` 폴더가 보여요.
3단계. `carcheck-dual` 폴더를 마우스 오른쪽 단추로 한 번 누르고, «복사»를 눌러요.
4단계. 같은 «문서» 화면의 빈 곳을 마우스 오른쪽 단추로 누르고, «붙여넣기»를 눌러요. `carcheck-dual - 복사본` 폴더가 생겨요.
5단계. 새 폴더를 오른쪽 단추로 누르고 «이름 바꾸기»를 눌러 `carcheck-dual_백업_20261018` 로 바꿔요.
6단계. (선택) 그 폴더를 오른쪽 단추로 누르고 «압축(ZIP) 폴더로 보내기»를 누르면 압축 파일도 하나 더 생겨요.

> `node_modules` 폴더 때문에 복사가 몇 분 걸릴 수 있어요. 정상이에요.
> git 기록(지금 상태를 첫 기록으로 남기기)은 코드가 이 작업방에 들어온 뒤 작업방이 해 드릴게요(아래 «코드 넘겨주는 법»).

### 이 보고서는 «설명을 바탕으로 한 1차 분석»이에요
- 대표님 지시서 2·3번(파일 목록, 줄 번호, 함정 목록)과 Electron(이 프로그램을 만든 도구)의 원래 동작을 바탕으로 썼어요.
- **코드를 직접 본 뒤 맞는지 다시 확인해야 하는 곳은 「⚠ 코드 확인 필요」**로 표시했어요.
- 실제 카인포·카모두·엔트리에는 아무것도 하지 않았고, 로그인 정보·쿠키도 보지 않았어요.

### 코드 넘겨주는 법 (다음 단계 전에 한 번만)
가장 쉬운 방법: **압축 파일을 이 대화에 올려 주기**
1단계. `carcheck-dual` 폴더를 열어요.
2단계. 안에 있는 `node_modules` 폴더를 **뺀** 나머지(main.js, src, renderer, tools, package.json, README.md, bat 파일들)를 마우스로 끌어서 모두 고르세요. (Ctrl 키를 누른 채 하나씩 눌러도 돼요.)
3단계. 고른 것 위에서 오른쪽 단추 → «압축(ZIP) 폴더로 보내기»를 눌러요.
4단계. 생긴 압축 파일을 이 대화창에 끌어다 놓아요.
- ⛔ `%APPDATA%\carcheck-dual` 폴더(로그인 정보·기록이 든 곳)는 **절대 넣지 마세요.** 코드 폴더 밖에 있어서 위 방법이면 들어가지 않아요.

### 2-1. 창이 앞으로 튀어나오는 문제 (대표님 가장 큰 불편) — 원인과 해결 방법

**원인 (지시서에 적힌 줄 기준, ⚠ 코드 확인 필요)**

| 자리 | 하는 일 | 앞으로 튀어나오는 까닭 | 바꿀 방법 |
|---|---|---|---|

| 927~947행 카모두 딜러 칸 «진짜 엔터» | 창에 초점을 준 뒤 키를 보냄 | 키를 받으려고 창을 앞으로 끌어옴 | **이미 사진 올리기에 쓰는 «개발자 연결(debugger)»로 엔터를 보냄** — 창을 앞으로 내지 않아도 사이트가 «진짜 키»로 받아들여요. 가장 유력한 대안 |

**창을 숨긴 채 일할 수 있나? — 단계별 예상**

| 단계 | 숨긴 채 가능? | 비고 |
|---|---|---|
| 화면 이동 · 기다리기 · 값 채우기 · 클릭 | 가능할 가능성 높음 | 숨긴 창에서 계산이 느려지지 않게 «뒤에서도 속도 유지» 설정 필요 |

| 카인포 목록 표·모달(Vue·DataTables) | ⚠ 시험 필요 | 화면 그리기를 «보일 때만» 하는 부분이 있으면 멈출 수 있음 → 그때는 **화면 밖 먼 곳에 살짝 보이게 두는 방법**으로 대신함(작업표시줄에도 안 뜨게) |

→ 결론: **대부분 단계는 창을 앞으로 내지 않고 할 수 있을 것으로 봐요.** 확실한 것은 2단계 첫날 «가짜 시험 화면»으로 확인해요(실제 전산 아님).

### 2-3. 기타 고칠 것
- 진단·학습용 단추 4개(사고체크 구조 조사, 카인포 절개도 학습, 팝업 진단, 사진 화면 조사)가 일반 화면에 보임 → **«관리자 도구»로 숨김**(지우지 않음).

## 3. 새로 만들어야 할 기능

### 3-1. 3개 전산 순서대로 등록하는 구조 (설계)

차 한 대 = «작업 한 건». 작업은 아래 칸을 한 칸씩만 나아가고, **이상하면 그 자리에서 멈춰요.** 지우기·취소는 앱이 하지 않아요.

```
[0 대기]
  ↓
[1 엔트리 로그인 확인] ── 로그아웃이면 → [1-1 문자 인증 기다림] (대표님 알림, 인증 끝나면 계속)
  ↓
[2 카인포 신규등록 + 값 채우기] → [2-1 사람 확인 후 저장] → [2-2 카인포 점검번호 읽기]
  ↓
[3 카모두 등록 + 값 채우기 + 카인포 점검번호 넣기] → [3-1 사람 확인 후 저장] → [3-2 저장된 번호 다시 읽어 대조]
  ↓
[4 엔트리 로그인 다시 확인] (2·3번 하는 사이 30분이 지났을 수 있음)
  ↓
[5 엔트리 «다음 번호» 확인 → 예상 번호와 같은지 대조] → 다르면 ⛔ 멈춤
  ↓
[6 엔트리 연계 등록] → [6-1 사람 확인 후 저장]
  ↓
[7 세 곳 저장 결과 다시 읽어 최종 대조] → ✅ 끝  /  ❌ «복구 안내» 화면
```

**지켜야 할 규칙**
- 번호가 하나라도 다르면 **즉시 멈추고**, 무엇이 다른지(어느 전산, 기대 번호, 실제 번호) 보여 줌. 앱은 고치거나 지우지 않음.
- 한 번에 **한 대씩만** 진행(번호가 차례로 매겨지므로 두 대를 섞으면 순서가 꼬임). 대기열에 여러 대를 쌓아 두는 것은 가능.
- 엔트리 확인을 **카인포 저장 직전에 한 번 더** 하는 것도 검토 — 카인포 저장 뒤에 엔트리가 끊겨 있으면 되돌리기가 어려우므로. (5번 질문에서 대표님 답에 따라 정함)
- 단계마다 «언제 · 어느 단계 · 결과»를 기록(차량번호 뒤 4자리 정도만, 이름·전화·로그인 정보는 기록 안 함).
- 엔트리 세션을 일부러 늘리는 기능(가짜 클릭으로 깨워 두기 등)·문자 인증 건너뛰기는 **만들지 않음.** 대신 «마지막 사용 뒤 몇 분 지났는지»만 보여 주고, 25분이 넘으면 «다시 로그인해야 할 수 있어요» 안내.

### 3-2. 엔트리 새 모듈 — 필요한 것 (⚠ 엔트리 화면을 아직 못 봄)

| 항목 | 내용 | 확인 방법 |
|---|---|---|
| 로그인 상태 확인 | 로그인 됐는지 «화면에 무엇이 보이면 로그인 상태인지» 기준 | 대표님 로그인 후 화면 조사 |
| 문자 인증 | 앱은 **인증 화면만 띄우고 사람이 번호 입력** — 앱이 문자를 읽거나 넣지 않음 | 정책 |
| 로그아웃 시간 | 약 30분 미사용 — 정확한 시간, «사용»으로 치는 동작 | 대표님 확인 |
| 번호 입력 칸 | «성능점검번호만 넣으면 내용이 자동으로 맞춰진다»(대표님 말씀) — 그 칸 위치, 넣은 뒤 무엇이 채워지는지 | 화면 조사 |
| 자동 채번 | «엔트리가 매기는 다음 번호»가 무엇이고 어디에 보이는지, 카인포 번호와 어떤 관계인지 | **대표님 확인 필요(가장 중요)** |
| 저장 결과 확인 | 저장 뒤 목록에서 그 차가 보이는지, 번호가 맞는지 | 화면 조사 |
| 필요한 입력값 | 번호 외에 사람이 넣는 값(사진, 가격 등)이 있는지 | 화면 조사 |

→ 엔트리 화면 조사는 **대표님이 로그인(문자 인증)해 주셔야** 할 수 있어요. 조사할 때도 실제 등록은 하지 않고 «화면 모양만» 읽어요.

### 3-3. 새 화면 (차곳간 CHECK·워시와 같은 모양)
필수 화면 8개: 통합 점검 입력 / 세 전산 로그인 상태 / 등록 진행 상황 / 차량별 작업 대기열 / 엔트리 문자 인증 알림 / 점검번호 일치 여부 / 오류·복구 안내 / 최종 저장 확인.
- 대표님 취향 반영: 짧은 안내 한두 줄, 확인 창은 화면 가운데 팝업(기본 경고창 안 씀), 되돌리기 어려운 일은 «어느 차·어느 전산·무엇을» 한 번 더 보여 주고 확인, 날짜는 달력, 표는 정렬·검색·보기 개수(5/10/20/30/50)·이름 칸 고정.
- **파일부터 만들지 않고 시안(미리보기)을 먼저** 보여 드려요(2단계).

### 3-4. 차곳간 CHECK 웹페이지 ↔ PC 프로그램 잇는 방법 (가장 큰 설계 숙제)

먼저 사실: **웹페이지만으로는 카인포·카모두·엔트리에 등록할 수 없어요.** 로그인된 사이트 화면을 조작하는 일은 대표님 PC의 이 프로그램이 켜져 있어야만 돼요.

| | A. PC 프로그램 안에 CHECK 화면 담기 | B. PC 프로그램이 서버 대기열을 가져가기 | C. PC 안에서만 열리는 연결 |
|---|---|---|---|
| 쉬운 설명 | 프로그램을 켜면 그 안에 CHECK 화면이 뜸. 화면에서 «등록»을 누르면 같은 프로그램이 바로 처리 | CHECK(폰이든 다른 PC든)에서 «등록 요청»을 누르면 서버에 쪽지가 쌓이고, 대표님 PC 프로그램이 몇 초마다 쪽지를 가져가 처리 | 대표님 PC의 크롬에서 CHECK를 열면, 같은 PC의 프로그램에 «안쪽 문»으로 바로 말을 검 |
| 장점 | 가장 단순·빠름. 서버 고칠 것 거의 없음. 차곳간 철칙 «앱은 화면을 담는 액자»와 같음. 외부에서 들어올 문이 없어 안전 | **폰에서도 요청 가능**, 프로그램이 다른 방에 있어도 됨, 진행 상황을 어디서나 봄 | 평소 쓰는 크롬 그대로 |
| 단점 | 그 PC 앞에서만 요청 가능 | 서버 방 일이 큼(대기열 표, 기기 인증, 상태 기록). 점검 내용이 서버를 거침(이미 CHECK가 저장하는 자료면 문제 적음). 몇 초 늦음 | 크롬이 «인터넷 페이지 → 내 PC 안쪽» 연결을 점점 막는 중(허락 창 뜸). 다른 웹사이트가 그 문을 두드릴 위험 → 열쇠 검사 필수. 고장 원인 찾기 어려움 |
| 7일 안에 | ✅ 가능 | △ 서버 방과 함께 해야 해 빠듯 | △ 크롬 정책 때문에 시험 많이 필요 |
| 추천 | **1차 추천** | **2차(출시 뒤)로 추천** | 비추천 |

**추천: 먼저 A로 시작하고, 나중에 B를 붙이기.**
- A로 만들어도 화면은 CHECK와 같은 파일이라, 나중에 B로 바꿀 때 화면은 다시 만들 필요가 없어요.
- 프로그램 안에서 CHECK 화면이 쓸 수 있는 기능은 «등록 시작 · 상태 보기 · 사람 확인 답» 몇 개로만 좁히고, CHECK 주소(check.cgg.co.kr)에서만 쓰게 막아요.
- CHECK 로그인·서버 연결은 차곳간 철칙대로 **서버 방**이 맡아요.

## 5. 가장 위험한 부분 (차질 가능성 높은 순)

1. **엔트리 번호 순서** — «자동 채번된 다음 번호»가 무엇과 맞아야 하는지 아직 모름. 잘못 이해하면 세 곳 번호가 어긋나 **등록 취소·재등록**이 생길 수 있어요. → 대표님 확인 전에는 엔트리 자동 등록을 켜지 않아요.
2. **엔트리 30분 로그아웃** — 카인포·카모두 저장 뒤에 엔트리가 끊기면, 문자 인증을 기다리는 동안 다른 사람이 엔트리에 등록하면 번호가 밀릴 수 있어요(같은 회사 계정을 여러 명이 쓰는지 확인 필요).
3. **외부 전산 이용약관** — 세 곳 모두 자동 조작을 허용하는지 아직 확인 안 됨. 금지라면 계정 정지 위험. → 대표님이 각 기관에 문의 또는 약관 확인(6번).
4. **숨긴 창에서 카인포 화면이 안 움직일 가능성** — 그러면 «화면 밖 살짝 보이기» 방법으로 바꿔야 해서 하루 더 걸릴 수 있어요.
5. **사이트가 바뀌면 멈춤** — 카인포·카모두가 화면을 고치면 칸 찾기가 틀어져요. 공개 API(정식 연결 통로)가 없어서 피할 수 없는 위험이에요. → 단계마다 «찾지 못하면 멈추고 알림»으로 피해를 줄여요.
6. **실제 끝까지 저장한 기록이 없음** — 지금 기능이 정말 다 되는지 모르는 채로 새로 쌓으면, 고장 원인을 찾기 어려워요. → 지시서대로 **고치기 전에 지금 상태로 1건 확인**부터.

### 보안 위험 (보안 방 검사 요청할 것)
- 로그인 정보는 Windows 암호화(DPAPI)로 저장 — 좋은 방식이지만 **같은 Windows 계정으로 켠 프로그램은 풀 수 있어요.** PC에 Windows 로그인 비밀번호를 꼭 걸어 두세요.
- 기록 파일(`records.jsonl`)에 차주 이름·전화 같은 개인정보가 들어가는지 ⚠ 확인 필요 → 들어가면 줄이거나 가림.
- 사이트에 값을 넣을 때 글자를 «코드 안에 그냥 이어 붙이는» 방식이면, 특이한 글자(따옴표 등)에 오작동할 수 있어요 ⚠ 확인 필요.
- 사이트 창·팝업이 PC 파일에 손댈 수 있는 설정(Node 기능)이 꺼져 있는지 ⚠ 확인 필요.
- CHECK 화면을 프로그램에 담을 때(A안) CHECK 주소에서만 등록 기능을 쓰게 막기.
- 이 보고서와 대화 어디에도 로그인 정보·쿠키·개인정보를 적지 않았어요.


### 8-5. EXE에 묶이지 않는 최종 구조 (제안)
```
차곳간 CHECK 웹(화면 · 자료 · 사용자 · 권한)  ←→  차곳간 서버(대기열 · 기록)
                                                      ↕
                                       각 점검장 PC의 «차곳간 연결 도우미»
                                       (작은 프로그램 · 전산 연결 모듈만 담음)
```
- 화면과 자료는 웹(차곳간)에, PC 프로그램은 «외부 전산 손발» 역할만. 3-4의 **B안**이 이 모양이에요.
- 7일 시제품은 **A안(프로그램 안에 CHECK 화면 담기)**으로 가되, 화면·자료 틀을 위 모양대로 만들어 두면 나중에 B안으로 옮길 때 화면을 다시 만들 필요가 없어요.
