## 1. 검수 보완 (3차 검수 4가지)
| # | 요청 | 한 것 | 시험 |
|---|---|---|---|
| 1 | 4xx·5xx 를 실패 확정으로 보지 말 것 | 서버 오류 = `uncertain`(저장했는데 오류를 돌려줬을 수 있음). 2xx·3xx 도 «저장 확정»이 아니라 `reached`(서버에 닿음) — 확정은 언제나 목록 다시 읽기 | 단위 + Electron(서버가 저장하고 500 → 불확실 → 목록으로 확인, 두 번 등록 없음) |
| 2 | 별도 도메인·팝업 저장이 통제에서 빠지지 않게 | 그 전산 주소가 아닌 곳으로 가는 쓰기 요청 = **알 수 없는 저장 경로** → 붙잡고 `unknownPath`(멈춤). 팝업은 생기자마자 통제기를 붙이고, 붙지 않은 창이 있으면 `unknownPath`. `coverage()` 로 통제 범위(주소·무늬·창·모르는 주소)를 드러냄. 설정이 확정 안 된 전산은 저장을 허락하지 않음 | 단위 + Electron(다른 주소 팝업 저장 → 실제로 막힘, 서버에 안 닿음, 멈춤) |
| 3 | 강제 종료 뒤 다음 차 허용 = 수동 절차 명시·기록 | `releaseAfterForce` 는 **사람이 세 전산 목록을 직접 확인한 수동 절차**로 기록: `method:'manual-list-check'`, `auto:false`, 관리자(PIN 확인), 까닭, **전산별 확인 시각**. 자동 검증과 구분 | 단위 |
| 4 | jsdom 포함 전체 재실행 | `npm test` 앞에 시험 도구 자동 설치(`pretest`). 시험 도구 폴더를 지운 상태에서 `npm test` → 자동 설치 → **전체 통과** 확인 | 아래 결과 |

## 2. 실제 프로그램 연결 구현 (새로)
| 부품 | 칸 | 하는 일 |
|---|---|---|
| `src/core/register-flow.js` | 공통(상용화 고려) | 카인포 → 카모두 → 엔트리를 한 단계씩(전산이 끝나면 그 창의 저장 통제를 풀어 기존 단추가 평소처럼 쓰이게, 멈추면 통제 유지): 시작(예전 번호 찍기) → 엔트리 사전 확인 → 값 넣기(넣은 뒤 저장 통제 걸기) → [저장해도 돼요](번호 확인·작업 기록·허락) → 저장 뒤 확인(통제기 결과 + 목록 다시 읽기) → 끝. 순서 어기기 금지 · 설정 미확정이면 저장 허락 안 함 |
| `src/sites/save-hold.js` | 가온 내부용 | 개발자 연결(Fetch)로 본 창 + 팝업의 요청을 붙잡아 통제기에 묻고 continue/fail. 응답·끊김을 통제기에 알림. 붙이기가 끝나야 «통제 안»으로 인정 |
| `src/sites/quiet-window.js` + `main.js` | 가온 내부용 | **창 튀어나옴 개선**: `quietWindows` 설정을 켜면 프로그램이 일할 때 사이트 창·팝업을 보이거나 초점을 주지 않음, 사람이 창 열기 단추를 누를 때만 앞으로. 카모두 딜러 «진짜 엔터»는 개발자 연결 키(초점 없음, isTrusted). 숨긴 창 속도 유지. **기본 꺼짐 = 예전 그대로** |
| `src/sites/flow-adapters.js` | 가온 내부용 | 흐름이 부르는 전산 연결 — 값 넣기는 **기존 기능 그대로**(main.js `sendToSite` = 예전 site:send 를 함수로 옮김, 동작 같음), 목록·번호·«자동 부여»·엔트리 칸은 `site-config` 선택자로 |
| `src/sites/site-config.js` | 가온 내부용 | 전산별 화면 설정. **실제 값(REAL)은 모두 `confirmed:false`**(목록 칸·저장 주소·«자동 부여»·엔트리 칸 모름) → 흐름이 저장을 허락하지 않음. 모의 설정(MOCK)은 시험용 |
| `main.js` | — | `flow:*`·`admin:*` IPC 추가(설정 `flow:true` 일 때만), 작업 기록 파일은 PC 마다(`jobs-<PC>.jsonl`), 관리자 PIN 은 메인에서만 확인. `preload.js` 에 `api.flow`·`api.admin` |
