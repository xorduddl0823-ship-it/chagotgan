### 2-3. 전산 진단 도구 (새로 만듦 · 설정 `diagnose: true` 일 때만 보임)
- 입력 화면 [전산 진단 (저장 안 함)] → 전산 고르기 → 그 전산 창에서 평소처럼 눌러 보기 → [지금 화면 칸 기록] → [진단 끝] → 기록 파일.
- **진단 중에는 그 전산 창과 팝업의 쓰기 요청(POST·PUT·DELETE…)을 하나도 서버로 보내지 않음.** 주소에 «save·insert·update·delete·upload·send…»가 들어간 GET 도 막음. 다른 주소로 가는 쓰기도 막음.
  신규등록 [확인] · 사진 올리기 · [저장] · [전송] 모두 해당.
- 기록에는 **값이 없음** — 주소 경로, 물음표 뒤 «이름», 보내려던 자료의 «칸 이름»만. 화면 기록도 단추 글자·칸의 id/name/종류·표 머리글만(입력된 값은 안 읽음).
- 진단 중에는 자동 등록과 그 전산의 기존 단추(전송·신규등록·사진 등)를 막음 — 저장이 안 되는데 된 것처럼 보이지 않게. 아래 단추에 «전산 진단 중 (카인포)»로 표시. 한 번에 한 전산만.
- 엔트리는 기존 프로그램에 창이 없어 진단 때만 엶 — **엔트리 주소(entryUrl)를 설정에 넣어야 함**.

### 2-3-1. 로그인한 뒤 화면 구성·코드 검토 (대표님 10/19 요청)
- 대표님이 프로그램 안 엔트리 창에서 **직접 로그인(문자 인증)** → 보고 싶은 화면(성능점검 현황 · [간편 접수] 창 · 불러온 화면 등)을 열 때마다 [지금 화면 칸 기록].
- 저장되는 것: 단추·칸 목록 + **값을 지운 화면 뼈대**(표 칸·이름·번호·입력 값·선택지 글자 지움, 머리글·단추 글자·칸 이름만) + **사이트 코드 파일**(같은 사이트 것). 페이지 안 코드의 따옴표 글자도 지움.
- 방은 이 파일로 화면 구성·[간편 접수]·[불러오기]·[저장]이 어떻게 움직이는지(어느 주소로 무엇을 보내는지)를 코드로 확인 → 엔트리 연결 모듈을 만듦.
- 진단 창에 «엔트리 주소» 칸 — 넣으면 설정에 저장(파일을 직접 고치지 않아도 됨).
- 진단 켜기·끄기는 더블클릭 파일 **`7_전산진단_켜기.bat` / `8_전산진단_끄기.bat`** (다른 설정은 그대로 · 프로그램을 다시 켜면 반영).
- 시험: 이름·아이디·번호·차량번호·입력 값·메모·선택지·코드 속 글자가 남지 않고, 머리글·단추·칸 이름은 남는지(통과).

## 5. 실제 자동 저장을 켜기까지 남은 일 (우선순위)

1. **엔트리 주소 받기** (대표님 — 주소창의 주소만 알려 주시면 됨)
2. **진단 1단계 — 저장 단추를 누르지 않는 진단** (대표님 PC · 원격): 세 전산 화면을 열어 [지금 화면 칸 기록]만. 칸 id·표 모양·단추 글자 확보. 쓰기 요청은 서버로 안 감.
3. **진단 2단계 — 막기 확인** (지시서 4-⑤): 실제 차량 기록에 [저장]을 누르기 전에, 실제 전산에서도 막기가 되는지 **데이터가 바뀌지 않는 방법**으로 먼저 확인하는 순서를 검수받은 뒤에만 진행. (모의 전산에서는 0건 도착을 확인함)
4. 엔트리 연결 모듈 완성 + 세 전산 설정 채우기 → 모의 시험 → 실제 전산에서 **저장 직전까지만** 확인
5. 대표님이 지켜보는 가운데 **한 대**로 첫 실제 자동 저장 → 세 전산 결과 확인 → 통과한 전산만 `confirmed: true`
6. 실제 처리 시간 측정 · 관리자 정리 화면(멈춘 작업 정리 단추) · 기존 화면의 기본 경고창 정리
