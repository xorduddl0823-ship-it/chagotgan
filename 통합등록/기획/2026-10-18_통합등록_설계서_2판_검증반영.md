## 2. 번호 안전장치 (2판)

### 2-1. 원칙
1. **예상은 안전장치가 아니다.** «카인포 마지막 번호 + 1 = 엔트리 다음 번호»는 저장 전에 보여 주는 **참고 경보**일 뿐이다(다르면 저장 전에 멈추고 대표님께 물음 — 미리 알 수 있는 어긋남을 줄이는 용도).
2. **안전은 «실제 번호 확인»으로 지킨다.** 저장된 뒤 실제로 붙은 번호를, 다음 전산에 넣기 **직전마다** 다시 확인한다.
3. 번호는 «목록 맨 위 줄» 같은 자리로 읽지 않는다. **우리 차의 차량번호·차대번호가 같은 줄**의 번호만 우리 차 번호로 인정한다.
4. 다르거나 **읽지 못하면 멈춘다.** 모르는 것은 통과가 아니다.
5. 프로그램은 지우기·취소·다시 등록을 하지 않는다.

### 2-2. 실제 번호 확인 4곳
| 확인 | 무엇을 | 다르거나 못 읽으면 |
|---|---|---|
| A. 카인포 저장 뒤 | 카인포 목록에서 **우리 차 줄**을 차량번호+차대번호로 찾아 실제 발급 번호를 읽음 | 멈춤 · 카모두로 넘어가지 않음 |
| B. 카모두 저장 직전 | 카모두 번호 칸에 들어간 값 = A의 번호 · «자동 부여» 꺼짐 확인 | 카모두 저장 단추 잠금 |
| C. 카모두 저장 뒤 | 카모두에 저장된 번호를 다시 읽어 = A의 번호 | 멈춤 · 엔트리로 넘어가지 않음 |
| D. 엔트리 저장 직전 | ① 엔트리가 끌어온 번호 = A ② 끌어온 차량번호 = 우리 차 ③ 끌어온 차대번호 = 우리 차 | 엔트리 저장 단추 잠금 |
| (마무리) | 세 곳에 남은 번호·차량번호를 마지막으로 한 번 더 | 다르면 «확인 필요»로 남김 |

### 2-3. 번호가 밀리는 경우와 대책
| 경우 | 가능성 | 대책 |
|---|---|---|
| 우리 PC 두 대가 동시에 카인포 저장 | 있음(PC 최대 2대) | 등록(카인포 저장 → 카모두 → 엔트리)은 **한 PC만**. 1차는 등록 PC 1대 |
| 가온의 다른 사람이 브라우저로 카인포에 직접 등록 | **지금은 있음**(직원) · 대표님이 1인 기업으로 바꿀 예정(10/18) | 바뀌기 전까지: 프로그램을 쓰는 동안 직원의 카인포 직접 등록 금지(운영 규칙) + 2-2 A·D 확인. 1인이 된 뒤에도 2-2 확인은 그대로 함 |
| 앞 차가 엔트리에서 멈춤 | 있음 | 앞 차 엔트리가 끝나기 전에는 다음 차 카인포 저장 잠금 · 대기열 전체 멈춤 |
| 번호 건너뜀·초기화·취소 번호 | ⚠ 10/19 확인 | 번호 규칙(1장 ①)을 본 뒤 «참고 경보» 규칙을 정함. 실제 확인(2-2)은 규칙과 상관없이 늘 함 |
| 외부 전산 자체의 오류 | 알 수 없음 | 2-2 확인으로 잡음 |

### 2-4. 한계 (꼭 적어 둠)
- 세 전산에는 **번호를 미리 잡아 두는 기능도, 동시에 저장하는 것을 막는 기능도 없다.** 그래서 프로그램이 번호 충돌을 **완전히 막을 수는 없다.** 프로그램이 할 수 있는 것은 «어긋남을 저장 전에 알아채고 멈추는 것»까지다.
- 특히 카인포는 저장하는 순간 번호가 붙으므로, 카인포 저장과 엔트리 등록 사이에 다른 경로로 카인포 등록이 일어나면 막을 방법이 없다 → 운영 규칙(다른 경로 등록 금지)이 함께 필요하다.

## 3. 로그인·세션
1. 엔트리 로그인을 **두 번** 확인: 맨 처음(카인포 저장 전) · 엔트리 차례 직전.
2. «로그인 화면이 아님»만 보지 않고, **실제로 번호를 읽을 수 있는 상태인지**(목록이나 다음 번호가 실제로 읽히는지)까지 확인.
3. 세션이 끊겨 다시 문자 인증을 했으면, **번호·차량번호·차대번호를 처음부터 다시 확인**(2-2 D).
4. 문자 인증 우회, 세션 억지 연장(가짜 클릭 등)은 만들지 않음. 마지막 사용 뒤 시간만 보여 주고 25분이 넘으면 «다시 로그인해야 할 수 있어요».
5. 엔트리 문자 인증 하루 10번쯤 → 끊기면 소리 + 윈도우 알림으로 부르고, 인증 끝날 때까지 그 차만 기다림.

## 4. 창 튀어나옴 · 백그라운드 (시험 후 결정)

**먼저 고칠 것 (안전 문제)**
1. 사진 올릴 때 사이트 경고창을 몰래 없애는 코드(`src/photo-upload.js` 339·431행) → 경고창 내용을 받아 화면 가운데 팝업으로 보여 주고 사람이 답하게 바꿈.
2. 비밀번호를 넣기 전 **주소와 출처 확인**(`main.js` 366행 전송 중 자동 로그인) — 진짜 카인포·카모두 주소의 로그인 화면일 때만.

**시험할 것 (사이트별로)**
| 방식 | 시험 내용 | 실패하면 |
|---|---|---|
| 숨긴 창 + 뒤에서도 속도 유지 | 카인포(Vue·DataTables)·카모두(팝업+iframe) 각각 값 채우기·클릭이 되는지 | 그 단계만 «작업 창 보기» |
| 개발자 연결로 엔터 보내기 | 카모두 딜러 칸에서 사원선택이 열리는지 | 그 단계만 «작업 창 보기» |
| 팝업 숨긴 채 열기 | 사원선택·사진등록 팝업이 숨긴 채 동작하는지 | 그 단계만 «작업 창 보기» |

- 1판의 «화면 밖에 띄우기» 대안은 **쓰지 않음.**
- **«작업 창 보기»**: 숨긴 창으로 안 되는 단계에서는 프로그램이 «이 단계는 창을 띄워야 해요 — [작업 창 보기]»라고 알리고, **대표님이 누를 때만** 창이 나옴(저절로 튀어나오지 않음).
- 사람이 봐야 할 때(딜러 고르기·원부 차이·최종 저장·문자 인증)는 작업표시줄 깜빡임 + 알림 + 소리.

## 5. 화면과 구조 (A안, 내부용)
- **A안 확정**: PC 프로그램 안에 차곳간 CHECK 화면을 담음(모바일 등록 없음).
- **화면 ↔ 엔진 창구**: 화면은 «등록 시작 / 상태 보기 / 사람 확인 답 / 멈춘 작업 이어하기» 같은 **정해진 창구 몇 개**로만 엔진을 부름. 화면이 Electron 기능을 직접 쓰지 않음 → 나중에 B안(서버 대기열)으로 바꿀 때 화면은 그대로.
- **제한**
  - 출처: 차곳간 주소에서 온 화면만 창구를 쓸 수 있음
  - 이동: 프로그램 안 CHECK 화면은 차곳간 주소 밖으로 이동 못 함
  - 팝업: 사이트 창은 그 사이트 주소의 팝업만 허용
  - 권한: 카메라·위치 등 브라우저 권한 요청은 기본 거절
  - IPC: 보내는 값의 모양을 검사하고, 사이트 창에서는 창구를 아예 못 씀
- **나눔**: ① 점검기록부 자료 틀 ② 업무 관리(대기열·단계·번호 확인·기록·복구) ③ 전산별 연결 모듈(카인포/카모두/엔트리 따로).
- **상용 판 대비**: ③ 전산 연결 모듈은 별도 폴더로 두고, **설치 파일을 만들 때 아예 넣지 않을 수 있게** 함(단순히 꺼 두는 것이 아님).
- 화면 모양은 차곳간 워시·체크와 같게, **시안 먼저**.

## 6. 작업 기록과 멈췄을 때 되살리기 (새 필수)

### 6-1. 작업 ID와 단계
- 차 한 대마다 **고유 작업 ID**(예: 날짜-순번). 모든 기록·알림·복구 안내에 이 ID를 씀.
- 전산마다 단계를 따로 기록:

| 단계 | 뜻 |
|---|---|
| 입력 완료 | 프로그램이 값을 다 채움 |
| 저장 요청 | 사람이 [저장]을 누름 |
| 저장 확인 | 프로그램이 저장된 것을 화면에서 확인함 |
| 번호 확인 | 실제 번호를 읽어 맞는지 확인함 |
| 끝 | 이 전산은 끝 |
| ❓ 불확실 | 저장을 눌렀는데 결과를 확인하지 못함 |

- 기록은 PC에 단계가 바뀔 때마다 바로 남김(꺼져도 남도록). 이름·전화·로그인 정보는 남기지 않음.

### 6-2. 다시 켰을 때
- PC가 꺼지거나 인터넷이 끊긴 뒤 다시 켜면 **처음부터 다시 하지 않음.** 기록을 보고 «○○○ 차, 카인포 끝 · 카모두 저장 요청에서 멈춤»처럼 보여 줌.
- **❓ 불확실**인 전산은 **다시 저장하지 않음**(두 번 등록 위험). 먼저 그 전산 목록에서 우리 차가 저장됐는지 확인하고(프로그램이 읽어 보거나 사람이 확인), 확인된 뒤에만 다음 단계로.

### 6-3. 번호가 어긋났을 때 안내
- 프로그램은 지우지 않음.
- 복구 안내 화면에 보여 줄 것:
  1. 무엇이 어긋났는지(어느 전산, 기대 번호, 실제 번호, 차량번호)
  2. **먼저 확인할 것**: 세 전산 목록에서 이 차가 지금 어떤 번호로 저장돼 있는지
  3. **대표님이 정한 복구 절차**(10/18): «카인포·카모두 둘 다 지우고 다시 등록» — 단, 기관에 정정 절차가 있으면 그것을 먼저(1장 ③ 답에 따라 문구를 바꿈)
- 대표님이 정리를 마쳤다고 누르기 전까지 대기열은 멈춤.

## 7. 외부 전산 이용 권한 — ⚠ 대표님 다시 결정 필요
