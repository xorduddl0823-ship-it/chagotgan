## 3. 지금 프로그램 상태 (코드로 확인)

### 3-1. 만들어진 것
- 카모두·카인포 로그인 유지(창마다 따로 저장) + 자동 로그인(Windows 암호화 DPAPI로 비밀번호 저장)
- 카인포: 성능점검 목록 → [신규등록] → 차량번호 → 딜러 검색 → [선택] 실제 클릭 → 원부 조회까지 자동
- 카인포 원부 정보(차명·연식 등) 되읽기, 입력값과 다르면 알림
- 카모두: 접수차량 목록에서 [접수등록]으로 열기 · 딜러(사원) 선택 · 동명이인은 사람이 고름
- 카모두 차량번호 조회 → 차대번호 전체 → 카인포 뒤 6자리 채우기
- 통합 항목 121개 + 두 사이트 값 바꾸기 표(`src/schema.js`). 리콜 코드가 두 사이트에서 정반대라 뒤집는 표 있음(지우면 안 됨)
- 사진 8칸 올리기(파일 고르는 창 없이 개발자 연결로 바로 넣음)
- 최종 [저장]은 사람이 누름(autoSubmit=false)
- 모든 기다림에 시간 제한
- 지금 «두 곳 동시 전송»은 실제로는 **경기조합 → 카인포 차례로 하나씩** 함(`renderer/app.js` 472행)

### 3-2. 안 되거나 확인 안 된 것
- 실제 차 1건을 끝까지 저장한 적 없음
- 카인포 사고 부위 자동 표시가 불안정(필러 A·B·C, 외판 일부 수리 부호 비어 있음)
- **카인포 저장 뒤 점검번호를 읽어 오는 기능 없음** — 지금은 [신규등록] 뒤 번호 칸을 읽어 보지만 비어 있으면 그냥 넘어감(`src/carinfo-prepare.js` 492행)
- 카모두 «자동 부여» 체크를 끄는 기능 없음. 번호 칸(`#j_assocNumber`)이 그 칸이 맞는지 화면 확인 필요
- 엔트리 기능 전부 없음
- 자동 테스트 없음
- README가 코드와 다름(«비밀번호 저장 안 함», «사진 업로드 미구현», «차량번호 조회 미연동»이라 적혔지만 실제로는 셋 다 됨)

## 4. 창 튀어나옴 해결 방향

| 단계 | 숨긴 창에서 가능? | 방법 |
|---|---|---|
| 화면 이동·기다리기·값 채우기·클릭 | 가능할 가능성 높음 | 창을 숨긴 채(show:false) 두고, 숨긴 창이 느려지지 않게 «뒤에서도 속도 유지»(backgroundThrottling:false) |
| 사진 올리기 | 가능할 가능성 높음 | 이미 개발자 연결(debugger) 방식 |
| 카모두 딜러 «진짜 엔터» | 대안 시험 필요 | `sendInputEvent` 대신 이미 쓰는 개발자 연결로 키 보내기(Input.dispatchKeyEvent) → 창 초점 없이 «진짜 키»로 받아들여질 것으로 예상 |
| 사이트 팝업 | 가능 | 팝업도 숨긴 채 열기 |
| 사이트 경고창 | 가능 | 개발자 연결로 경고창 내용을 받아 차곳간 입력 화면 가운데 팝업으로 보여 주고, 사람이 고른 답을 넘김(몰래 없애지 않음) |
| 카인포 목록 표·모달(Vue·DataTables) | 시험 필요 | 숨긴 창에서 안 그려지면 «화면 밖에 살짝 띄우기»(작업표시줄에도 안 뜸)로 바꿈 |
| 사람이 봐야 할 때 | 사람 차례 | 창을 끌어오지 않고 작업표시줄 깜빡임 + 윈도우 알림 + 소리. 대표님이 알림을 누를 때만 앞으로 |

## 5. 등록 순서와 번호 안전장치 (핵심)

### 5-1. 차 한 대의 순서
```
[0] 번호판·계기판 사진 → 차량번호·주행거리 읽기 → 사람 확인
 ↓
[1] 엔트리 로그인 확인 + 엔트리 «다음 번호» 읽기   (끊겼으면 문자 인증 알림 → 기다림)
 ↓
[2] 카인포 [신규등록] → 값 채우기 → 사고 부위는 사람이 직접 누름(1차)
 ↓
[3] ⛔ 사전 확인: «카인포 마지막 번호 + 1» = «엔트리 다음 번호» ?   다르면 카인포 저장 잠금
 ↓
[4] 사람이 카인포 [저장] → 저장 끝 알아채기 → 실제 붙은 점검번호 읽기 → 엔트리 다음 번호와 다시 대조
 ↓
[5] 카모두 [접수등록] → «자동 부여» 끄기 → 카인포 번호 넣기 → 값 채우기 → 사람이 [저장] → 저장된 번호 다시 읽어 대조
 ↓
[6] 엔트리 로그인 다시 확인 (그사이 30분 지났을 수 있음)
 ↓
[7] ⛔ 엔트리 3중 확인: ① 다음 번호 = 이 차 카인포 번호 ② 끌어온 차량번호 = 이 차 ③ 끌어온 차대번호 = 이 차
 ↓
[8] 셋 다 맞을 때만 «12가3456 · 카인포 ○○○번을 엔트리에 등록할까요?» → 사람이 [저장]
 ↓
[9] 세 곳 저장 결과 다시 읽어 최종 대조 → 끝
```

### 5-2. 꼭 지킬 규칙
1. **번호 확인은 카인포 저장 전에** 한다. 저장 뒤에 알면 두 곳을 지우고 다시 해야 하므로.
2. 하나라도 다르거나 **읽지 못하면 통과가 아니다.** 즉시 멈추고 저장 단추를 잠근다.
3. **한 번에 한 대만.** 앞 차의 엔트리 등록이 끝나기 전에는 다음 차의 카인포 저장을 잠근다.
4. 앞 차가 멈추면 기다리는 차들도 모두 멈춘다. 대표님이 정리한 뒤에만 다시 움직인다.
5. **PC 두 대라도 등록(카인포 저장 → 카모두 → 엔트리)은 한 PC만.** 1차는 등록 PC 1대, 둘째 PC는 사진·입력까지만. 엔트리는 계정이 하나라 두 PC 로그인 시 서로 끊길 수도 있음.
6. 프로그램은 **지우기·취소·고치기를 하지 않는다.** 어긋나면 «카인포 ○○○번 · 카모두 ○○○번을 지우고 다시 등록해 주세요»를 차 정보와 함께 보여 주고, 지우기는 대표님이 직접 한다.
7. 최종 [저장]은 세 곳 모두 사람이 누른다.
8. 엔트리 문자 인증을 우회하거나 세션을 억지로 늘리지 않는다. 마지막 사용 뒤 시간만 보여 주고 25분이 넘으면 «다시 로그인해야 할 수 있어요».
9. 기록에는 «언제 · 어느 단계 · 결과»와 차량번호 뒤 4자리 정도만. 이름·전화·로그인 정보는 남기지 않는다.

### 5-3. 아직 모르는 것 (10/19 엔트리 화면 볼 때 확인)
- 카인포 번호가 정말 «앞 번호 + 1»인지, 해·달이 바뀌면 처음부터 다시 시작하는지
- 엔트리 «다음 번호»가 어디에 보이고 카인포 번호와 같은 모양인지
- 엔트리에서 끌어온 차량번호·차대번호가 화면 어디에 보이는지
- 사전 확인용 «카인포 마지막 번호»를 어디서 읽을지(성능점검 목록 맨 위 줄 등)
- 카인포 저장 뒤 화면이 어떻게 바뀌는지(목록으로 가는지, 안내 창이 뜨는지)

## 6. 사진 먼저 → 차량번호·주행거리 자동 입력
- 순서: 번호판 사진 → 계기판 사진 → 프로그램이 읽어서 칸에 넣음 → **사람이 «맞아요»를 눌러야** 다음으로
- 읽는 곳: 차곳간 체크 서버(check-api)에 이미 있는 «사진 읽기». 번호판 읽기(`aiPlate`)는 지금도 체크에서 쓰는 중. 계기판 주행거리 읽기는 같은 방식으로 새 창구가 필요 → **서버 방 일**(차곳간 규칙: 서버 코드는 서버 방만)
- 읽기용 열쇠는 서버에만 둠(프로그램에 넣지 않음). 사진은 읽은 뒤 서버에 남기지 않음
- 계기판 사진은 사진 8칸의 «계기판사진» 칸에 그대로 들어가 두 전산에도 올라감
- 주행거리는 성능기록부에 그대로 찍히는 숫자라 **항상 사람 확인**. 못 읽으면 비워 두고 «직접 적어 주세요»

| | A안 (결정) | B안 (나중) | C안 (비추천) |
|---|---|---|---|
| 방식 | PC 프로그램 안에 차곳간 CHECK 화면을 담음 | CHECK에서 요청 → 서버 대기열 → PC 프로그램이 가져감 | 크롬의 CHECK가 같은 PC 프로그램에 «안쪽 문»으로 연결 |
| 장점 | 가장 단순, 서버 일 거의 없음, 바깥에서 들어올 문 없음 | 다른 PC·폰에서 요청 가능 | 평소 크롬 그대로 |
| 단점 | 그 PC에서만 | 서버 일이 큼 | 크롬이 막는 추세, 다른 사이트가 문을 두드릴 위험 |
| 판단 | 모바일 등록 없음(대표님) → 결정 | PC 2대가 자료를 나눌 때·상용화 때 검토 | — |
- 프로그램 안 CHECK 화면이 쓸 수 있는 기능은 «등록 시작 · 상태 보기 · 사람 확인 답» 몇 개로 좁히고, 차곳간 주소에서만 쓰게 막음

### 7-2. 새 화면 (차곳간 워시·체크와 같은 모양, 시안 먼저)
사진 먼저 읽기 / 통합 점검 입력 / 세 전산 로그인 상태 / 등록 진행 상황 / 차량별 대기열 / 엔트리 문자 인증 알림 / 점검번호 일치 여부 / 오류·복구 안내 / 최종 저장 확인
- 안내는 짧게, 확인 창은 화면 가운데 팝업, 되돌리기 어려운 일은 «어느 차·어느 전산·무엇을» 한 번 더 보여 주고 확인, 날짜는 달력, 표는 정렬·검색·보기 개수(5/10/20/30/50)·이름 칸 고정

### 7-3. 상용화를 생각한 나눔 (7일 안에는 폴더만 나누고 코드는 옮겨 담기)
```
① 점검기록부 자료 틀 — 차 한 대의 점검 내용(전산과 무관한 차곳간 표준 모양)
② 업무 관리         — 대기열 · 단계 · 번호 대조 · 기록 · 알림 · 사람 확인
③ 전산별 연결 모듈   — 카인포 / 카모두 / 엔트리 각각 «①을 그 전산에 넣고 번호를 읽어 오는» 일만
```
- 다시 씀: `schema.js`(리콜 뒤집기 포함), `filler.js`, `photo-upload.js`, 함정 목록
- 손봐서 씀: `main.js`(작업 엔진/창 관리 분리), `carinfo-prepare.js`, 딜러 선택, `credentials.js`
- 새로 만듦: 엔트리 모듈, 대기열, 저장 뒤 번호 읽기, 사진 읽기 연결, 새 화면
- 모든 작업·기록에 «사업장 표시»(지금은 가온 하나)를 붙여 둠
- 자동 조작 기능은 «내부용 켜기» 스위치 뒤에 두고 상용 판에서는 꺼 둠

## 8. 위험 (차질 가능성 높은 순)
0. ⛔ **엔트리 다음 번호 어긋남 = 다른 차 점검기록부 등록** → 5-2의 규칙 1~6
1. **실제 등록까지 가 본 적 없음**, 카인포 사고 부위 불안정 → 1차는 사고 부위를 사람이 누르는 반자동. 2일차에 «저장 직전까지» 실제 화면 확인, 실제 첫 완주는 7일차
2. **카인포 저장 뒤 번호 읽기**(새로 만듦) — 저장 뒤 화면 변화를 아직 모름. 못 읽으면 사람이 넣고 두 번 확인
3. **카모두 번호 손입력 실수** — 앱이 «자동 부여» 끄기·번호 넣기, 저장 전후 대조
4. **엔트리 30분 로그아웃·문자 인증 하루 10번** — 시작 전·엔트리 차례 직전 확인, 끊겼으면 알림
5. **전산 허락 없음** — 계정 정지·제재 위험. 가온 내부용 · 사람 속도로 한 대씩 · 사람 저장 · 읽은 내용은 그 차 등록에만
6. **숨긴 창에서 카인포 화면이 안 움직일 가능성** — «화면 밖 띄우기»로 대체(하루 더 걸릴 수 있음)
7. **사이트 개편 시 칸 찾기 실패** — 찾지 못하면 멈추고 알림
8. **주행거리 잘못 읽기** — 항상 사람 확인

보안: 비밀번호 넣기 전 주소 확인 추가 · 기록 파일 보관 기간과 칸 줄이기 · 주석 속 개인정보 지우기 · PC에 Windows 로그인 비밀번호 필수(같은 Windows 계정이면 저장된 비밀번호를 풀 수 있음) · CHECK 화면을 담을 때 차곳간 주소에서만 등록 기능 허용

## 10. 검증해 주셨으면 하는 점
1. **번호 안전장치(5-2)가 충분한가?** 특히 «카인포 마지막 번호 + 1 = 엔트리 다음 번호»를 저장 전에 확인하는 방식에 빈틈이 있는지(예: 저장 직전 사이에 번호가 바뀌는 경우)
2. 등록 순서(5-1)에서 엔트리 로그인 확인을 맨 앞과 엔트리 직전 두 번 하는 것이 맞는지
3. 창 튀어나옴 해결 방향(4장)이 Electron에서 현실적인지 — 특히 개발자 연결로 키 보내기, 숨긴 창에서 Vue·DataTables 동작
4. A안(프로그램 안에 CHECK 화면 담기) 결정이 맞는지
5. 7일 계획이 무리하지 않은지, 빠진 위험이 있는지
6. 자동 조작 허락이 없는 전산에 대해 위험을 줄이는 방법(8장 5번)이 충분한지
