# 세 전산 입력 항목 대응표 (7차 · 2026-10-19)

> 가온 입력 화면(121칸)의 값이 카인포·카모두·엔트리 어디로 가는지 한 줄씩 정리했어요.
> 표는 프로그램의 자료 틀(`src/schema.js`)에서 바로 뽑았어요(`node tools/field-map.js`). 자료 틀을 고치면 표도 다시 뽑으면 돼요 — 사람이 따로 적어 어긋나는 일이 없어요.

## 변환이 필요한 항목 (프로그램이 이미 바꿔서 넣음)

| 항목 | 어떻게 바꾸나 |
|---|---|
| 리콜 대상 · 리콜 이행 | 카인포와 카모두의 값 번호가 **정반대** → 카모두로 보낼 때 뒤집음(`RECALL_TO_CM`) |

| 사고이력 · 단순수리 | 직접 넣지 않고 부위 표시로 자동 계산 |
| 조합 성능번호 | 흐름에서는 카모두 «자동 부여»를 끄고 **카인포 점검번호**를 넣음 |
| 차명·연식 등 차량정보(16칸) | 카인포 신규등록 때 원부 조회로 채워진 값을 입력 화면으로 되읽어 씀 |

## 누락 의심 · 확인 필요 (대표님 화면 확인 때 같이 봄)

1. **카인포에 연결 안 된 칸 9개** — 주행거리 상태 · 특별이력 구분(침수/화재) · 용도변경 구분(렌트/영업용) · 색상 · 도색 이력 · 주요옵션 · 옵션 구분 · 조합 성능번호(카모두 전용이라 정상) · 승차정원.
   성능점검기록부 서식에는 있는 항목들이라 카인포 화면에 칸이 있는데 연결을 못 한 것일 수 있어요.
2. **카모두에 연결 안 된 칸 5개** — 접수일 · 현재주행거리 · 차종구분(국산/외산) · 매매상사 · 연락처.
   매매상사·연락처는 카모두에서 딜러를 고르면 자동으로 채워지는 칸이라 정상이에요. 나머지 3개는 확인 필요.
3. **사진** — 카모두로는 1번(전면)·2번(후면)만 보내요. 3번 계기판 사진이 카모두에 필요한지 확인 필요.
   카인포는 3번 계기판 사진을 «좌측면» 자리에 넣고 있어요(기존 기능) — 자리가 맞는지 확인 필요.
4. **카인포 화면에 있는데 가온 입력 화면에 없는 칸 (10/19 화면 사진)** — «점검원»(신규등록 창 · 지금은 카인포 기본값 사용) · «적재정량(화물)» · «특기사항 및 점검자의 의견». 화물차·의견 문구를 자동으로 넣으려면 입력 화면에 칸을 더해야 해요(지금은 카인포 기본값 그대로).
5. **엔트리** — 엔트리에서 따로 넣어야 하는 칸이 있는지(사진 포함), 카인포에서 끌어오면 다 채워지는지 확인 필요.
