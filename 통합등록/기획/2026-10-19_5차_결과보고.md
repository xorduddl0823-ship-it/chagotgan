## 1. 4차 검수 결함 수정

| # | 지적 | 고친 것 | 확인한 시험 |
|---|---|---|---|
| 1 | 통제기 설치 순서 | `register-flow.fill()`: **통제기 설치 → 본 창이 붙었는지 확인 → (카모두·엔트리) 저장 전 목록 찍기 → 값 넣기.** 설치 실패·창 미부착이면 값 넣기·저장 모두 안 함. Electron 쪽은 `hold.ready` 가 실패하면 오류 | 모의: 설치 실패 시 값 넣기 안 함 · 값 넣는 중 저장 클릭 막힘 / Electron: 값 넣는 중 [저장] 클릭이 서버에 안 닿음 |
| 2 | 완료 후 중복 저장 | `release()` 대신 **봉인(seal)**: 끝난 전산 창의 쓰기 요청은 모두 막고 허락도 받지 않음(다음 차가 새 통제기를 걸 때까지). **기존 단추 우회 막기**: 흐름 작업이 그 전산을 쓰는 중이면 main.js 의 `site:send`(카인포만·경기조합만·두 곳 동시)·`photo:send`·`carinfo:prepare`·`vin:sync`·`dealer:pick`·`dealer:carinfo` 가 거절(`legacyBlocked`). 흐름이 꺼져 있으면 예전 그대로 | 모의: 끝난 뒤 저장 클릭 막힘 · 봉인 통제기 허락 거절 · 흐름 중 기존 단추 막힘/작업 없으면 그대로 / Electron: 끝난 뒤 다시 저장 클릭이 서버에 안 닿음 |
| 3 | 카모두·엔트리 저장 번호 조회 | «목록 첫 줄» 방식 삭제. 값 넣기 전에 그 전산 목록에서 **이 차 예전 번호들을 찍어 두고**(작업 기록에 보관 — 다시 켜도 유지), 저장 뒤에는 그 목록에 없고·지운 줄 아니고·차량번호 같고·(차대번호가 보이면 17자리 일치) **정확히 한 줄**만 이번 저장으로 인정(`findNewSavedRow`). 없으면 불확실, **둘 이상이면 멈춤** | 모의: 작년 점검·지운 재등록 줄 무시 · 이번 줄 둘이면 멈춤 |
| 4 | 팝업 첫 요청 | ① Electron 실측: 팝업의 **첫 요청이 바로 저장(POST)** 인 경우도 잠긴 동안 서버에 **0건** 도착(10번 반복 같음) ② 그래도 보장으로 보지 않음 → **저장 단계(허락 뒤)에 팝업이 열리면 `manualCheck`** — 자동으로 끝내지 않고 사람이 목록에서 확인 표시(`manualChecked`)를 해야 이어 감. 값 넣기 중 팝업(딜러 고르기 등)은 세지 않음 | 모의 2개 + Electron 1개 |
| 5 | 엔트리 미구현 표시 | 실제 엔트리 화면 설정이 없으면 연결 모듈 `implemented=false` → 흐름이 **«미구현» 으로 멈추고**(«이 단계는 사람이 직접 — 끝난 것으로 표시하지 않음»), 작업은 닫히지 않음(`finish` 가 `notImplemented:['entry']`) | 모의 1개 |

## 4. 남은 문제
1. **실제 전산 화면 설정이 비어 있음**(카인포 목록 칸·저장 주소, 카모두 «자동 부여» 체크·번호 칸, 엔트리 전부) → 흐름은 저장 허락을 하지 않음. 대표님 화면 사진 필요
2. **엔트리 연결 모듈 없음** — 미구현으로 표시·멈춤
3. 흐름에서는 **사진을 같이 보내지 않음**(통제기가 사진 올리기 쓰기 요청도 막기 때문) — 저장 경로 확인 뒤 «사진 올리기 허락» 단계 필요
4. **카인포 [신규등록]**(차 한 대를 카인포에 만드는 단계)은 흐름 밖 — 흐름 시작 전에 기존 단추로 함. 이 단계의 쓰기 요청 처리도 실제 화면 확인 뒤 흐름 안으로
5. 조용한 창·저장 붙잡기는 **흉내 사이트에서만** 확인 — 실제 카인포(Vue)·카모두(팝업+iframe)에서는 대표님 PC 확인 필요
6. 회색 «기다림» 상태 칩은 시안 전용 CSS — 공통 부품(디자인 방)에 추가 요청 필요 · «전산 등록 = 체크 전용»을 규칙(SKILL 5-2 제품 전용 목록)에 넣도록 총괄 방에 요청 필요
