## 4. 엔트리 로그인·문자 인증 처리 (필수 개발 조건 1~7)
| # | 조건 | 반영 |
|---|---|---|
| 1 | 통합등록 시작 전 엔트리 로그인 확인 | 카인포를 저장하기 «전»에 확인(기존) — 끊겨 있으면 아무것도 저장하지 않고 재인증 요청 |
| 2 | 엔트리 작업 직전에도 다시 확인 | 엔트리 번호 확인 직전 · 값 넣기 직전 · [저장] 허락 직전 · **저장 뒤 목록 확인 직전**(새로 추가 — 끊긴 화면의 빈 목록을 «저장 안 됨»으로 읽지 않음) |
| 3 | 만료 시 자동등록 일시 중단 + 직원에게 재인증 요청 | 멈추고 «엔트리 문자 재인증이 필요해요» 안내 · 엔트리 창을 앞으로 · 작업표시줄 깜빡임. 기다리는 동안 엔트리 **저장 통제기를 풀어** 직원의 로그인·문자 인증 요청이 막히지 않게(저장 허락은 없음 — 실제 창 시험으로 확인: 통제기가 걸린 동안은 로그인 요청도 막히고, 풀면 닿음) |
| 4 | 직원이 인증하면 로그인 상태 재확인 | 3초마다 **화면 글자만** 읽어 확인(서버 요청·새로 고침 없음) — 확인되면 저절로 이어 감. 최대 15분(부탁할 때마다 새로 셈) · [기다리기 그만] → 나중에 [이어 하기] |
| 5 | 재인증 뒤 완료 단계는 건너뛰고 미완료부터 | 작업 기록으로 이어 감 — 시험: 카모두까지 끝난 뒤 끊김 → 엔트리만 이어서, 저장은 전산마다 정확히 한 번 |
| 6 | 불확실한 단계는 재시도 없이 실제 등록 여부부터 | 엔트리 [저장] 직후 끊긴 경우: 다시 저장하지 않고 재인증 뒤 목록·상세로 확인 — 시험: 엔트리 [저장] 한 번만 |
| 7 | 인증 우회·문자 자동 탈취·강제 세션 연장 없음 | 로그인·문자 인증은 직원이 직접 · 기다리는 동안 전산 화면 조작 0번(시험으로 확인) · 코드 검사 시험(인증번호 넣기·세션 유지 코드 없음) |
| 참고 | «약 30분»은 사전 경고에만 | 로그인을 확인한 지 25분이 넘으면 «곧 끊길 수 있어요»라고 알리기만 — 멈출지는 실제 로그인 상태로만 정함 |
