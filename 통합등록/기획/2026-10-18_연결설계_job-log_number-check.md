# 연결 설계 — 작업 기록(job-log) · 번호 확인(number-check)을 실제 등록 흐름에 붙이는 자리

- 작성: 2026-10-18 · Claude Code (통합등록 작업방) · ChatGPT 2차 검수 3·5번 반영
- ⚠ **지금 상태: 두 모듈은 모의 시험만 통과했고, 실제 등록 흐름(`main.js`·`renderer/`)에는 연결하지 않았다.**
  연결은 10/19 화면 사진(카인포 목록·저장 직후·카모두 1번 페이지·엔트리)을 본 뒤 한다.
- 이 문서는 «어디에 무엇을 붙일지»만 정한다. 실제 외부 전산 저장은 하지 않는다.

## 2. 사이트 [저장] 잠금 — 가장 중요한 새 부품

지금 코드는 사람이 사이트 창에서 언제든 [저장]을 누를 수 있어, `beginSubmit()` 를 거치지 않은 저장이 생길 수 있다. 이것을 막아야 두 번 등록 막기가 의미가 있다.

| 방법 | 내용 | 판단 |
|---|---|---|
| ① 폼 보내기 막기 | 이미 있는 `noSubmit()`(딜러 고를 때 쓰는 것)처럼 form submit 을 막음 | 사이트가 AJAX 로 저장하면 못 막음 → 단독으로는 부족 |
| ② 저장 단추 가리기 | 저장 단추 위에 «앱에서 [저장해도 돼요]를 먼저 눌러 주세요» 덮개 | 화면이 다시 그려지면 덮개가 사라질 수 있음 → 보조 |
| ③ **저장 요청 자체를 붙잡기** | 이미 쓰는 개발자 연결(debugger)로 저장 주소로 가는 요청만 잠시 붙잡아 두었다가(Fetch 가로채기), 잠금이 풀리면 보내고 아니면 «앱에서 먼저 확인» 안내 | **추천** — AJAX·form 모두 막힘. 저장 주소는 10/19 화면에서 확인 |

→ 추천: ③을 기본, ②를 함께(사람이 왜 안 되는지 알 수 있게). 저장 주소를 모르는 동안에는 연결하지 않는다.

## 3. 기록 파일 위치

- `%APPDATA%\carcheck-dual\jobs-<PC표시>.jsonl` — **PC 마다 자기 파일** (PC 표시 = 컴퓨터 이름 영문·숫자 8자)
- 기존 `records.jsonl`(전송 이력)은 그대로 두고, 작업 기록은 따로.
- 보관: 닫힌 작업은 90일 뒤 정리(작업 기록 정리 기능은 연결 때 함께 — 닫히지 않은 작업은 지우지 않음).

- 작업 줄(작업 ID · 차량번호 · 전산별 단계 · 번호)

## 5. 여러 PC · 여러 프로세스가 함께 쓸 때

| 경우 | 문제 | 방안 | 상태 |
|---|---|---|---|
| 한 PC 안에서 프로그램이 두 번 켜짐 / 두 프로세스가 같은 기록 파일 | 동시에 읽고 판단하고 쓰면 «한 번에 한 대»가 엇갈리거나 같은 작업 ID 가 나올 수 있음 | **잠금 파일**(`<기록파일>.lock` 을 «없을 때만 만들기») 안에서 읽기-판단-쓰기를 한 번에 · 오래된 잠금(30초)은 치움 · 기다리다 못 잡으면 저장을 풀지 않음 | ✅ `job-log.js` 반영 · 시험(프로세스 6개 동시 30개 작업 · 동시 저장 풀기 경쟁 5회) |
| 프로그램 두 번 켜기 자체 | 창이 두 벌 | Electron «하나만 켜기»(`app.requestSingleInstanceLock`) — 두 번째는 첫 창을 보여 주고 끝남 | 연결 때 `main.js` 에 추가 |
| PC 두 대가 기록을 합칠 때 | 작업 ID 겹침 | 작업 ID 에 PC 표시(`YYYYMMDD-PC-순번`) | ✅ 반영 · 시험 |
| PC 두 대가 동시에 등록 | 카인포 번호가 섞여 엔트리 다음 번호가 어긋남(대형 사고) | 1차: **등록은 한 PC(등록 PC)만** — 다른 PC 의 프로그램은 «입력만» 모드. 2차: PC 사이 «등록 중» 잠금을 **차곳간 체크 서버**에 둠(빌려 쓰는 잠금, 10분마다 연장, 프로그램이 꺼지면 시간이 지나 풀림) → 서버 방 요청 | 1차 규칙만 · 서버 잠금은 설계만 |
| 네트워크 공유 폴더에 기록 파일 하나 | 파일 잠금이 PC 사이에서 믿기 어려움 | **쓰지 않음** | — |

4. 7~8번(카모두) → 같은 방식
5. 9번(엔트리) → 10·11번(닫기·이어 하기)
