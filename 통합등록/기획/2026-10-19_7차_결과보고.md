## 1. 구현 · 미구현 항목표

| 지시 | 한 일 | 상태 |
|---|---|---|
| 1 입력 데이터 완전성 | 121칸 대응표를 자료 틀에서 바로 뽑는 도구(`tools/field-map.js`) + 문서. 둘 다 70 · 변환 27 · 카모두만 9 · 카인포만 5 · 사진 8 · 가온만 2. 누락 의심 칸(카인포 쪽 7 · 카모두 쪽 3 · 카모두 사진 3~8번 · 엔트리 전부)을 따로 표시 | ✅ 표 완료 / ⏳ 누락 의심 칸은 실제 화면으로 확인 필요 |
| 2 카인포 신규등록 | 흐름 안에 «카인포 신규등록» 단계. 입력 화면 [신규등록]으로 미리 했으면 그 화면을 이어 씀, 안 했으면 흐름이 **한 번만** 함. 다른 차 화면이 열려 있으면 멈춤. 하다 멈췄으면 **다시 하지 않고** 목록 확인 부탁(같은 차 두 번 생김 막기). 딜러 동명이인이면 고른 뒤 이어 감 | ✅ 모의 시험 통과 / ⏳ 실제 요청 주소 확인 필요 |
| 2 (발견) 신규등록 때 목록 줄이 먼저 생기는 경우 | 기존 코드에 «[확인] 뒤 '성능이 등록되었습니다' + 목록 새로 고침» 경우가 있었어요. 그러면 «목록에 줄이 있다»가 저장 증거가 못 돼요. → 그 경우 목록 «상태» 칸이 «저장 끝»일 때만 저장됨으로 봄, 모르면 사람 확인 | ✅ / ⏳ 실제 상태 글자 확인 필요 |
| 2 사진 올리기 | 흐름 안에 «사진 올리기» 단계. 전산 설정대로 저장 **전**(카모두 흉내) 또는 저장 **뒤**(카인포 흉내). 올린 칸을 작업 기록에 남겨 이어 하기 때 **못 올린 칸만**. 사진 주소는 «사진» 단계 동안만 열림(저장 주소는 그래도 막힘). 언제 올리는지 모르면 사진이 있을 때 저장 전에 멈춤 | ✅ 모의 시험 통과 / ⏳ 실제 시기·주소 확인 필요 |
| 3 엔트리 실제 연동 준비 | 로그인 · 다음 번호 · 불러오기 · 저장 · 결과 조회에 필요한 화면 정보와 프로그램의 확인 방법을 정리. 번호 규칙은 정하지 않고 «화면 값과 카인포 번호가 같은지 비교»만 | ✅ 정리 완료 / ❌ 엔트리 연결 모듈 자체는 화면을 본 뒤 만듦 |
| 4 오류 안내 수정 | 번호 어긋남: «① 세 전산에서 실제 등록 상태 확인 ② 관리자 정정 절차 확인 ③ 대표님(관리자)께 알리기» 순서. «지우고 다시 등록»은 기본 안내에서 뺌. 시안 A·B 문구도 같이 고침. 이런 멈춤에는 [이어 하기]를 숨김(정정 절차 건너뛰기 막기) | ✅ |
| 5 실제 화면 연결 준비 | 대표님께 받을 화면 사진 10장 목록. 설정이 비어 있는 동안 자동 저장 막힘(실제 프로그램 시험으로 확인) | ✅ / ❌ «저장 요청을 붙잡아 기록만 하는» 진단 기능은 다음 차수 |
| 6 실사용 UI | 기존 입력 화면 그대로 + 진행 칸(카인포 · 카모두 · 엔트리, 지금 하는 곳 파랑 · 끝난 곳 ✓ 초록). 끝 보고는 세 번호가 실제로 같을 때만 «같아요». 정상이면 시작 확인 한 번 뒤 직원 조작 없음. 화면 검사 일꾼 검사 → 지적 고침 | ✅ |

- 엔트리 연결 모듈(실제 화면 보고 만듦).
- 관리자 정리 화면(작업 강제 닫기 · 확인 표시)은 엔진(IPC)만 있고 입력 화면에 단추가 아직 없어요 → 그래서 안내는 «대표님(관리자)께 알려 주세요»로 했어요.

**새로 확인한 장면**
- 완전 자동 1대: 신규등록(줄 먼저 생김) → 값 넣기 → [저장] → 번호 확인 → 카인포 사진(저장 뒤) / 카모두 사진(저장 전) → 엔트리 → 닫기. 세 번호 T-0201 같음, 저장 각 1번, 카인포 줄 1개 «완료», 사진 칸 모두. 흉내 사이트 기준 약 0.7초.
- 단추로 미리 신규등록 → 흐름이 다시 안 함, 같은 번호로 끝.
- 다른 차 등록 화면이 열려 있음 → 시작 안 함.
- 신규등록 하다 멈춤 → 이어 하기에서 다시 안 하고 목록 확인 부탁 → 사람이 그 줄을 열어 두면 끝까지.
- 사진 한 칸 실패 → 멈춤(«기록은 이미 저장») → 이어 하기에서 그 칸만, 저장은 다시 안 함.
- 줄이 먼저 생기는 경우 + 저장 결과 모름 → «작성중»이면 저장됨으로 안 봄, «완료»면 확인.
- 단계 문: 통제기가 걸린 뒤 신규등록 문 밖의 신규등록 요청은 서버에 안 닿음 · 사진 문이 열려 있어도 저장은 안 나감.
- 엔트리 다음 번호 다름 → «왜 다른지 확인» 안내, 엔트리 저장 0번.

## 3. 바뀐 파일
- `src/core/register-flow.js` — 신규등록·사진 단계, 저장 확인 규칙, 새 안내 문구
- `src/core/save-guard.js` — «단계 문»(신규등록·사진 동안만 그 주소 통과)
- `src/core/job-log.js` — 신규등록 표시·올린 사진 칸 기록
- `src/sites/flow-adapters.js` · `site-config.js` — 신규등록 화면 읽기·사진 올리기 연결, 새 설정 칸(모두 «모름»으로 둠)

- `renderer/` — 진행 칸, 끝·멈춤 보고 정리, 카인포 딜러 고르기 이어 가기
- `tools/field-map.js` — 대응표 만들기
- `test/` — 새 시험 12 + Electron 2
- `00_고정결정_먼저읽기.md` — 번호 어긋남 안내 순서(7차) 반영
- `시안/` — 멈춤 안내 문구
