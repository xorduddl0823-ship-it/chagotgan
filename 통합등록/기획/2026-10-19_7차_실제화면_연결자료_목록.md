# 실제 화면 연결에 필요한 자료 목록 (7차 · 2026-10-19)

> 프로그램이 실제 카인포·카모두·엔트리에서 «저장까지» 하려면, 각 전산 화면의 몇 가지 위치를 알아야 해요.
> 지금은 이 값이 비어 있어서 **자동 저장이 막혀 있어요**(설정이 확정되기 전에는 저장 전에 멈춤 — 실제 프로그램으로 확인함).
> 아래 자료를 받으면 실제 저장 없이 «저장 직전까지» 확인한 뒤 설정을 확정해요.

## 대표님이 하실 일 — 최소한으로 줄였어요

**준비물**: PC 화면 사진(캡처). 시험용 차 한 대면 돼요.
**찍지 말 것**: 로그인 비밀번호 화면, 문자 인증번호. 고객 전화번호는 가려도 괜찮아요.

| 순서 | 전산 | 찍을 화면 | 왜 필요한가 |
|---|---|---|---|
| 1 | 카인포 | 성능점검 목록(차가 여러 대 보이게) | 목록의 칸 순서(번호·차량번호·차대번호·날짜·상태)를 읽으려고 |
| 2 | 카인포 | [신규등록] → [확인]을 누른 **바로 뒤** 목록 | 신규등록만 해도 목록에 줄·번호가 먼저 생기는지(생기면 «상태» 칸으로만 저장을 확인해야 함) |
| 3 | 카인포 | 점검 등록 화면을 [저장]한 **바로 뒤** 목록 | 저장하면 «상태» 칸 글자가 무엇으로 바뀌는지(예: 완료) |
| 4 | 카인포 | [사진등록] 창 | 사진을 저장 **전**에 올리는지 **뒤**에 올리는지 |
| 5 | 카모두 | 접수등록 1번 페이지(«성능점검번호» 칸과 «자동 부여» 체크가 보이게) | 번호 칸·자동 부여 체크 위치 |
| 6 | 카모두 | 접수 목록(저장한 차가 보이게) | 목록의 칸 순서 |
| 7 | 엔트리 | 로그인한 뒤 첫 화면 | 로그인됐는지 알아보는 표시 |
| 8 | 엔트리 | «다음 번호»가 보이는 화면 | 다음 번호를 읽을 자리 |
| 9 | 엔트리 | 카인포 기록을 불러온 화면(차량번호·차대번호가 보이게) | 불러온 차가 맞는지 비교할 자리 |
| 10 | 엔트리 | 저장한 뒤 목록 또는 결과 화면 | 저장됐는지·번호 확인 자리 |

> 화면 사진만으로 안 보이는 «저장 주소»(저장할 때 어느 주소로 가는지)는 사진으로 알 수 없어요.
> 저장 요청을 «붙잡아 기록만 하고 보내지 않는» 진단 기능을 다음 차수에 만들어, 대표님 PC에서 원격으로 함께 확인할 예정이에요(지금은 아직 없음).

## 방(개발)이 받은 자료로 채울 설정 — `src/sites/site-config.js`

| 전산 | 채울 값 | 지금 |
|---|---|---|
| 카인포 | 목록 칸 순서(`list.cols`) · 저장 끝 상태 글자(`list.savedStatus`) | 비어 있음 |
| 카인포 | 신규등록 때 줄이 생기나(`prepare.createsRow`) · 신규등록 요청 주소(`phaseAllow.prepare`) | 모름 |
| 카인포 | 사진을 언제 올리나(`photoPhase`) · 사진 올리기 주소(`phaseAllow.photo`) | 모름 |
| 카인포 | 저장 단추(`saveButton`) · 저장 주소(`savePatterns`) · 조회 주소(`readAllow`) | 비어 있음 |
| 카모두 | «자동 부여» 체크(`autoAssign`) · 번호 칸(`numberField` — 지금 `#j_assocNumber`로 짐작, 확인 필요) | 일부 |
| 카모두 | 목록 칸 · 저장 단추·주소 · 사진 시기·주소 | 비어 있음 |
| 엔트리 | 아래 «엔트리 연동 준비» 전부 | 비어 있음 |

다 채우고 «저장 직전까지» 확인한 전산만 `confirmed: true`로 바꿔요. 그 전에는 프로그램이 저장 단계로 가지 않아요.

## 엔트리 연동 준비 — 화면에서 확인할 것

엔트리는 카인포에 저장된 기록을 **«다음 번호»로 끌어와** 등록해요. 다음 번호가 이 차 카인포 번호와 다르면 **다른 차 기록이 끌려와** 대형 사고가 나요.
그래서 프로그램은 **번호 규칙을 스스로 정하지 않아요**(«카인포 번호 + 1» 같은 짐작 금지). 화면에 보이는 값을 읽어 **같은지 비교만** 해요.

| 단계 | 화면에서 알아야 할 것 | 프로그램이 하는 확인 |
|---|---|---|
| 로그인 | 로그인됐을 때만 보이는 표시(이름·로그아웃 단추 등) · 로그인 화면의 모양 | 로그인이 끊겼으면 카인포 저장 **전에** 멈추고 «문자 인증 로그인» 안내. 로그인·문자 인증은 사람이 함(우회·억지 연장 없음) |
| 다음 번호 | 다음 번호가 화면 어디에 보이는지 · 새로 고쳐야 바뀌는지 | 화면을 새로 고친 뒤 **한 번만** 읽어 이 차 카인포 번호와 **완전히 같을 때만** 진행. 다르면 멈추고 «왜 다른지 확인» 안내(엔트리에는 저장 안 함) |
| 차량 불러오기 | 불러오기 단추 · 불러온 뒤 차량번호·차대번호가 보이는 자리 | 불러온 차량번호·차대번호가 이 차와 같아야 저장 허락(17자리 일부만 같으면 사람 확인) |
| 저장 | 저장 단추 · 저장 주소 · 저장 뒤 나오는 안내 | 저장 요청을 한 번만 허락 · 응답이 이상하면 «불확실»로 두고 다시 저장하지 않음 |
| 결과 조회 | 저장된 목록(번호·차량번호 칸 순서) | 저장 전 목록과 비교해 **이번에 새로 생긴 이 차 줄 하나**의 번호가 카인포 번호와 같은지 확인 |

**대표님께 여쭐 것(화면 볼 때 함께)**
1. 엔트리 «다음 번호»는 카인포에 저장하자마자 바뀌나요, 아니면 시간이 걸리나요?
2. 엔트리에서 따로 넣어야 하는 칸(사진 포함)이 있나요, 아니면 불러오면 다 채워지나요?
3. 엔트리 저장 뒤 결과를 어디서 확인하나요(목록 / 조회 화면)?

## 지금 프로그램이 지키는 것 (자료가 오기 전까지)
- 실제 화면 설정이 확정되지 않은 전산은 **저장하지 않고 저장 전에 멈춤**(실제 프로그램 시험으로 확인: «카인포 목록 칸 설정이 아직 없습니다»).
- 실제 전산 저장 없이 **모의 사이트 시험**과 **저장 직전 검증**만 함.
- 기관에 묻는 일은 하지 않음(대표님 10/18 결정 — `00_고정결정_먼저읽기.md`). 여기서 «확인»은 가온 PC 화면으로 하는 확인이에요.
