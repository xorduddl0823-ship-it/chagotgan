# 성능점검 이중등록 (carcheck-dual)

성능점검 결과를 **한 번만 입력**하면 두 사이트에 자동으로 채워 넣는 PC 프로그램입니다.

- 경기자동차매매사업조합 — `ck.carmodoo.com`
- 한국자동차공정정보협회 — `ai.carinfo.co.kr`

---

## 설치 — 배치 파일 더블클릭

Node.js가 필요합니다. 없으면 <https://nodejs.org> 에서 **LTS** 버전을 먼저 설치하세요.

| 파일 | 하는 일 | 언제 |
|---|---|---|
| `1_준비.bat` | 필요한 파일 내려받기 | **최초 1회만** (몇 분 소요) |
| `2_실행.bat` | 프로그램 실행 | 쓸 때마다 |
| `3_설치파일_만들기.bat` | **exe 설치파일 생성** | exe가 필요할 때 |

`3_설치파일_만들기.bat` 을 돌리면 프로그램 폴더 **바깥**의 `carcheck-dual-build` 폴더에 두 개가 만들어집니다.

> 만들기 결과를 프로그램 폴더 밖에 두는 이유: 편집기(Claude 데스크톱 등)가 프로그램 폴더를 지켜보면서
> 이전에 만든 `app.asar` 을 붙잡고 있어, 다시 만들 때 「다른 프로세스가 사용 중」 오류로 멈췄습니다.
> 폴더를 밖으로 빼면 그 손이 닿지 않아 그냥 만들어집니다.

- **`CarCheckDual-Setup-0.1.0.exe`** — 설치형. 실행하면 설치되고 바탕화면 아이콘이 생깁니다.
- **`CarCheckDual-Portable-0.1.0.exe`** — 무설치형. 파일 하나만 있으면 어디서든 실행됩니다. USB로 옮겨 다른 PC에서 써도 됩니다.

한 번 만들어두면 그 exe는 Node.js 없는 PC에서도 그대로 돌아갑니다.

> 터미널을 쓰신다면 `npm install` → `npm start`, exe는 `npm run dist` 로도 동일합니다.

## 사용법

### ① 로그인 (앱 실행 후 최초 1회)

상단 `경기조합 창` / `카인포 창` 을 눌러 각 사이트에 로그인합니다.
로그인 세션은 앱 안에 저장되어 다음 실행 때도 유지됩니다.

> 로그인 후 HOME 으로 떨어져도 괜찮습니다. 전송 버튼을 누르면 앱이 알아서
> `성능점검 관리 > 성능점검` 화면으로 이동하고, 공지 팝업이 떠 있으면 닫습니다.

### ② 차량번호 + 딜러명만 입력

`차량번호` 와 `딜러명` 두 개만 채웁니다.
딜러명 칸에는 **상사명이나 연락처를 넣어도 검색**됩니다.
개인간 거래면 `거래유형` 을 바꾸고 `고객명` 을 넣으세요.

### ③ [카인포 신규등록 + 차량정보 가져오기]

버튼 하나로 카인포에서 사람이 하던 순서를 그대로 밟습니다.

```
[신규등록] → 차량번호 입력 → 딜러 검색·선택 → [확인] → 원부 조회 → 등록 화면 진입
```

그리고 **카인포가 원부에서 끌어온 차량정보를 앱으로 되읽어 자동 반영합니다.**
차명·연식·최초등록일·차대번호·변속기·연료·원동기형식·배기량·검사유효기간 등을
다시 타이핑할 필요가 없습니다. 가져온 값은 **파란 테두리 + `가져옴` 표시**로 구분됩니다.

딜러는 카인포 목록의 `[선택]` 버튼을 **실제로 클릭**합니다.
값만 채워 넣으면 모달이 검색 모드에 머물러 `[확인]` 이 통하지 않습니다. (`carinfo-prepare.js` 주석 참고)

- 동명이인이 있으면 **선택 창**이 뜹니다. 자동으로 고르지 않습니다.
  실제로 "신동민" 은 *판다카* 와 *솔카* 두 명이 검색됩니다 — 상사명·연락처를 보고 고르세요.
- 이미 입력해 둔 값이 카인포 값과 다르면 **입력값을 그대로 두고** 결과창에 차이를 알려줍니다.

### ④ 점검 항목 입력 후 [두 곳 동시 전송]

남은 것은 점검원이 판정하는 항목뿐입니다. 채운 뒤 전송하면 두 창의 폼에 값이 들어갑니다.

### ⑤ 확인 후 저장

> **프로그램은 값만 채우고 저장은 하지 않습니다.**
> 각 사이트 창에서 내용을 확인한 뒤 직접 `저장`을 누르세요.
> 잘못된 성능점검 기록이 등록되는 사고를 막기 위한 의도적인 설계입니다.

결과창에서 **입력됨 / 입력 실패 / 이 사이트에 없는 항목** 을 확인할 수 있습니다.

## 구조

```
main.js            Electron 메인. 사이트 창 관리, 값 주입 실행
preload.js         화면 ↔ 메인 통신 다리
src/schema.js         ★ 통합 스키마 + 두 사이트 필드 매핑 (단일 진실 원천)
src/filler.js         앱 → 사이트 : 주입 스크립트 생성
src/scraper.js        사이트 → 앱 : 역방향 읽기 (원부 정보 가져오기)
src/carinfo-prepare.js 카인포 신규등록 자동 진행 (딜러 조회 포함)
renderer/          입력 화면 (index.html / app.js / style.css)
```

**사이트가 개편되면 `src/schema.js` 의 선택자만 고치면 됩니다.** 다른 파일은 건드릴 필요 없습니다.

매핑 형식:

```js
{ k: 'carNo', label: '차량번호', type: 'text', req: true,
  cm: { sel: '#j_carNumber' },   // carmodoo — CSS 선택자
  ci: { sel: '#carNo' } }        // carinfo  — CSS 선택자 또는 { name: '라디오이름' }
```

`vmap` 을 주면 통합값을 사이트값으로 변환합니다.

## 주의사항 (읽어주세요)

### 리콜 항목은 두 사이트 코드값이 정반대입니다

| 항목 | 통합값 | carmodoo | carinfo |
|---|---|---|---|
| 리콜대상 | 1=해당없음, 2=해당 | **1=해당, 2=해당없음** | 1=해당없음, 2=해당 |
| 리콜이행 | 1=미이행, 2=이행 | **1=이행, 2=미이행** | 1=미이행, 2=이행 |

`schema.js` 의 `RECALL_TO_CM`, `RECALL_DONE_TO_CM` 이 이걸 뒤집습니다. **지우지 마세요.**

### 차대번호 분리

carinfo는 차대번호를 `vin1` / `vin2` 두 칸으로 나눠 받습니다.
현재 앞 11자리 / 뒤 6자리로 자릅니다. 실제 규칙이 다르면
`%APPDATA%\carcheck-dual\config.json` 의 `vinSplit` 값을 고치세요.

### 경기조합 절개도 지우기 — 왜 목록을 먼저 보는가

앱에서 지운 표시를 경기조합에서도 지우려면 그 부위의 팝업을 열어 체크를 풀고
저장해야 합니다. 처음에는 **표시가 없는 자리 35곳을 전부 열어** 확인했습니다.
확실하지만 한 곳에 1~2초씩 걸려 전송이 1분 넘게 걸렸습니다.

부위 목록의 체크칸은 표시가 있으면 `value` 가 부호(`X`·`W`…)로 바뀌고 체크됩니다
(표시가 없으면 `value="on"`·해제). 그래서 목록만 읽으면 **표시가 남은 부위**를
팝업 없이 알 수 있습니다. 지금은 그 부위에 딸린 자리만 열어 봅니다 — 보통 2~3곳.

목록을 읽지 못하면(구조가 바뀌면) 예전처럼 전부 열어 확인합니다. 느려도 맞게.
목록과 도면이 어긋나 표시가 안 지워지는 일이 생기면
**설정 → 절개도를 꼼꼼히 확인**을 켜세요. 항상 전부 열어 확인합니다
(`config.json` 의 `thorough`).

팝업은 반드시 닫고 끝냅니다: 닫기(×·취소) → 저장 → Esc 순서로 시도하고,
그래도 남으면 결과에 알립니다. 예전에는 닫기 단추를 못 찾으면 마지막 팝업이
열린 채로 남았습니다.

### 카인포 부호 바꾸기 — 지우고 다시 찍는다

카인포 절개도의 점에는 **어떤 부호로 찍혔는지가 적혀 있지 않습니다.**
표시된 점의 class 는 `status status-x status-w part-168 selected-status` 처럼
"이 자리는 X·W 를 받을 수 있다"는 뜻일 뿐, 지금 찍힌 부호는 담고 있지 않습니다.

그래서 예전에는 이미 표시된 점을 그냥 건너뛰었고, 교환(X)으로 찍은 것을
판금(W)으로 고쳐도 사이트에는 X 가 그대로 남았습니다.

지금은 이미 표시가 있으면 **표기삭제로 지운 뒤 원하는 부호로 다시 찍습니다.**
같은 부호였다면 결과는 그대로이므로 손해가 없습니다. 순서가 중요합니다 —
부호를 고를 수 있는지 **먼저 확인한 뒤** 지웁니다. 반대로 하면 부호 선택이
실패했을 때 있던 표시만 날아갑니다.

### 딜러를 바꾸면 셋이 함께 바뀐다

딜러명만 바꾸면 안 됩니다 — **매매상사·연락처가 옛 딜러 것으로 남습니다.**
카인포 기준으로 자료가 등록되므로 카인포부터 바꾸고, 그 값을 앱으로 가져와
경기조합에도 같은 값이 쓰이게 합니다.

**`[딜러 바꾸기 (카인포)]`** — 사람이 하는 순서 그대로입니다.

1. 고객정보의 「매매상사 / 딜러명」 옆 **[검색]**
2. 「매매상사/딜러 검색」 창에서 **상사/딜러/연락처** 칸에 이름을 넣고 [검색]
3. 목록에서 **딜러명이 정확히 같은 줄**의 **[선택]** — 하나면 앱이 고르고,
   여럿이면 앱에 목록을 띄워 사람이 고릅니다
4. 알림 창의 **[확인]** 까지 누릅니다 (이걸 눌러야 고객정보가 바뀝니다)
5. 바뀐 **딜러명·매매상사·연락처를 앱에 되돌려 넣습니다**

목록의 칸 이름이 없어도 값의 생김새로 읽습니다 — 연락처를 기준으로 바로 앞이
딜러명, 그 앞에서 가장 긴 글자가 매매상사입니다. 검색 창이 이미 떠 있으면 다시
열지 않습니다(두 번 열면 화면이 꼬입니다). `src/carinfo-dealer.js`.

경기조합에서 고른 값도 같은 방식으로 앱에 반영합니다.

### 경기조합 등록 화면은 "사이트가 여는 방식" 으로 연다

크롬에서는 접수차량 리스트(`carCheckList.do`)에서 **[접수등록]** 을 눌러 등록 화면을
띄웁니다. 주소는 리스트 그대로이고 등록 화면은 그 위에 얹힙니다.

앱은 그동안 `pop_carcheck.do` 를 **곧바로** 열었습니다. 화면은 같아 보이지만
**그 화면을 띄운 부모 창이 없습니다.** 사원선택 창은 고른 값을 부모 창에 돌려주는데
돌려줄 곳이 없으니 조용히 실패합니다 — 크롬에서는 되는데 앱에서만
「상사가 선택되지 않았습니다」 가 뜨던 진짜 이유입니다.
(진단에 `화면 조각: ["pop_carcheck.do", "about:blank"]` 로 드러났습니다)

지금은 리스트를 열고 [접수등록] 을 눌러 사이트가 하던 대로 띄웁니다. 등록 화면이
얹힌 **화면 조각**을 찾아, 값 넣기·딜러 고르기를 모두 그 조각에 대고 합니다
(`ensureCarmodooForm` · `runFrame`).

### 경기조합 딜러는 "고르는" 것이다

「1. 신청인 및 접수정보」 의 칸은 두 가지로 나뉩니다.

| 칸 | 뜻 |
|---|---|
| `#j_dealerName` | **딜러명 — 여기에 이름을 치고 ENTER** |
| `#jDNo` | 딜러번호 — 고르면 채워진다 (누르면 딜러명 칸으로 focus 를 넘긴다) |
| `#j_dealerHp` · `#jSNo` · `#j_sangsaName` | 고르면 채워진다 |

화면 안내가 「딜러명을 넣고 ENTER」 라 처음에는 그 문구 옆의 `#jDNo` 에 넣고 엔터를
쳤습니다. 아무 일도 없었습니다. 실제로는 `#jDNo` 의 처리기가
`$('#j_dealerName').focus();` 라, **사람이 치는 곳은 딜러명 칸**이었습니다.

앱은 그동안 **결과칸**(`#j_dealerName`)에 글자만 넣었습니다. 화면에는 이름이 보이지만
사이트가 쥐고 있는 딜러·상사 번호는 비어 있어, 저장할 때
**「상사가 선택되지 않았습니다」** 가 떴습니다.

**딜러 고르기가 맨 먼저입니다.** 딜러·상사가 잡혀야 나머지 정보를 등록할 수 있어서,
경기조합 전송은 이것부터 하고 고를 사람이 여럿이면 거기서 멈춥니다. 앱에서 고르면
이어서 나머지를 보냅니다.

**엔터는 여러 통로로 시도합니다.** 화면마다 무엇을 듣는지가 달라서, 되는 것이 나올
때까지 차례로 해 봅니다.

1. 창에 **진짜 키**를 넣는다 (`webContents.sendInputEvent`) — 누르기 직전에 딜러명
   칸을 다시 잡는다. 창을 앞으로 내는 사이 입력 자리가 옮겨간다.
   실제로 엔터가 **BODY 로 가서** 아무 일도 일어나지 않았다
2. 사이트가 쥔 함수 **`getDealerInfo()`** 를 직접 부른다 (화면을 살펴 확인한 이름이다)
3. 페이지 안에서 키 이벤트를 만들어 보낸다 (`keyCode` 를 얹어서)
4. 칸에 적힌 처리기(`onkeydown="if(event.keyCode==13)…"`)를 직접 부른다
5. 칸 옆의 찾기 단추(돋보기·검색)를 누른다

**사원선택은 창이 아니라 화면 조각입니다.**

```
pop_carcheck.do
about:blank
popSearchDealer.do?search=박형명&ssNo=&target=regist_check   ← 사원선택
```

주소에 찾는 이름이 붙습니다. 앱은 이 조각을 찾아 표를 읽습니다. 이걸 못 알아보고
**한 번 더 눌렀더니 이름 없는 전체검색(`search=`)까지 열려 화면이 꼬였습니다.**
지금은 조각이 생겼는지부터 보고, 있으면 다시 누르지 않습니다. 이름이 붙은 조각을
먼저 고릅니다 — 이름 없는 조각은 전체 목록이라 거기서 고르면 엉뚱한 사람이 잡힙니다.

**고른 값은 앱이 직접 넣습니다.**

사원선택 조각은 고른 값을 `window.opener` 로 부모 창에 써 넣습니다. 그런데 앱에서는
`opener` 가 없어 조각 안에서 이렇게 실패합니다 (모의로 그대로 재현했습니다).

```
Cannot read properties of null (reading 'document')
```

원래는 사원선택 창이 부모 창(조합 등록 화면)에 값을 써 넣습니다. 그런데 **앱 안에서는
그 통로가 동작하지 않습니다** — 크롬에서는 줄을 누르면 바로 채워지는데, 앱의 조합
창에서는 같은 팝업에서 더블클릭해도 신청인정보가 그대로 비어 있었습니다.

필요한 값은 사원선택 표에 다 들어 있으므로 앱이 직접 넣습니다.

| 표의 칸 | 넣는 곳 |
|---|---|
| 사원코드 | `#jDNo` (딜러번호, 숨은 칸) |
| 사원명 | `#j_dealerName` |
| 휴대폰번호 | `#j_dealerHp` |
| 상사코드 | `#jSNo` (상사번호, 숨은 칸) |
| 상사명 | `#j_sangsaName` |

먼저 사이트가 하던 대로 줄을 누르고 [확인] 을 눌러 봅니다. 그래도 칸이 비어 있으면
그때 앱이 직접 넣습니다 — 크롬에서 나오는 결과와 같은 값입니다.

**겹쳐 뜨는 창은 iframe 안에 있을 수 있습니다.** `executeJavaScript` 는 맨 바깥
화면에서만 도는데, 그러면 표가 있어도 안 보입니다. 그래서 바깥부터 안쪽 조각까지
차례로 훑습니다(`runInFrames`).

그래도 목록이 안 뜨면 **카인포에서 가져온 딜러명·연락처·상사명을 그대로 넣어 둡니다.**
다만 딜러·상사 번호는 비어 있어 저장할 때 경고가 뜰 수 있다는 것을 결과에 함께
적습니다 — 채워진 것처럼 보이게 두고 넘어가지 않습니다.

그래도 안 되면 그 화면이 무엇을 듣고 있는지 함께 알려줍니다 — 지금 입력이 어디로
가는지, 칸에 적힌 처리기, form 이름, 이름이 닮은 함수들, 화면에 있는 표.
추측 대신 그 내용을 보고 맞춥니다.

지금은 사람이 하는 대로 합니다.

1. 찾는 칸에 딜러명을 넣고 **ENTER** (진짜 키)
2. **사원선택** 창이 뜬다
3. **딜러명 · 매매상사 · 연락처가 모두 맞는 사람**이 딱 하나면 앱이 고르고
   [확인] 까지 누른다
4. 여럿이거나 하나도 없으면 그 줄들을 앱에 띄워 **사람이 고른다**

사원선택 창의 머리줄은 이렇습니다 —
`지역 · 상사명 · 상태 · 사원명 · 휴대폰번호 · 사원구분 · 사원코드 · 사업번호 · 상사코드`.
앱은 이 이름으로 칸을 찾아 맞춰 봅니다. **이름만 맞는 사람은 고르지 않습니다** —
같은 이름이 다른 상사에 또 있기 때문입니다.

**표를 찾을 때 머리줄을 확인합니다.** 사원명·상사명·휴대폰번호가 있는 표만 봅니다.
이 조건이 없으면 엉뚱한 목록을 읽습니다 — 실제로 조합 창의 탭 이름
(1신청인 및 접수정보 …)을 딜러 목록인 줄 알고 보여준 적이 있습니다.

목록은 팝업 창으로 뜹니다(이 화면에 뜨는 경우도 대비해 두 곳을 다 봅니다).
기다리는 일은 앱이 합니다
(목록이 뜨며 화면이 새로 그려지면 페이지 안의 스크립트는 사라집니다 — P2).
`[딜러만 고르기 (조합)]` 로 이 단계만 따로 시험할 수 있습니다.
`src/carmodoo-dealer.js`.

### 팝업은 진짜 창으로 연다 (405 가 나던 이유)

예전에는 `window.open` 으로 뜨는 팝업을 본 창에 실어(`loadURL`) 한 창에서 다 보려
했습니다. 그런데 그렇게 열면 주소를 **GET 으로** 가져옵니다.

카인포 **[사진등록]** 은 빈 팝업을 먼저 띄우고 그 창으로 form 을 **POST** 하는
방식이라, GET 으로 가져가면 서버가 **405(허용되지 않은 방법)** 를 돌려주고
「요청한 페이지를 찾을 수 없습니다」로 끝났습니다. 크롬에서는 멀쩡한데 앱에서만
안 되던 이유입니다.

지금은 팝업을 **진짜 창**으로 엽니다(`javascript:` 만 막습니다). 로그인 정보는 연
창에서 그대로 물려받습니다. 열린 팝업은 앱이 기억해 두었다가(`sitePopup`) 필요할 때
그 창을 다룹니다 — 카인포 점검내역이 팝업으로 뜨는 경우 값도 그 창에 넣습니다.

### 자동차 사진 8칸

`11. 자동차 사진` 에서 사진을 붙입니다. 1 전면 · 2 후면 · 3 계기판은 자리가
정해져 있고 4~8은 기타입니다. 칸을 눌러 고르거나 파일을 끌어다 놓으면 되고,
여러 장을 한 번에 고르면 그 칸부터 차례로 채워집니다.

**사진 파일을 복사하지 않고 "그 파일이 있는 자리(전체 경로)" 만 기억합니다.**
나중에 두 사이트에 올릴 때 그 경로를 사이트의 파일 선택칸에 그대로 넣어야 하기
때문입니다. 그래서 사진을 옮기거나 지우면 칸에 빨갛게 **파일 없음** 이라고 뜹니다.

값은 `state.photo1` … `state.photo8` 에 담기고 임시저장·기록에도 함께 들어갑니다.

**어느 칸이 어디로 가는가**

| 앱 | 경기조합 (4 자동차사진) | 카인포 (사진등록 팝업) |
|---|---|---|
| 1. 전면사진 | 앞면 | 앞면 |
| 2. 후면사진 | 뒷면 | 뒷면 |
| 3. 계기판사진 | — | 좌측면 |
| 4. 기타 | — | 우측면 |
| 5. 기타 | — | 기타1 |
| 6. 기타 | — | 기타2 |
| 7. 기타 | — | 기타3 |
| 8. 기타 | — | 기타4 |

조합은 두 장만 받습니다. 자리는 **고정**입니다 — 앱 6번에 넣은 사진은 늘 기타2 로
갑니다(중간이 비어 있어도 밀리지 않습니다).

전송을 누르면 입력칸을 다 채운 뒤 사진을 올립니다. 조합은 「4 자동차사진」 탭으로
옮겨서, 카인포는 [사진등록] 팝업을 띄워서 넣습니다.

**파일 고르기 창을 어떻게 피하는가** — 자리를 누르면 윈도우가 파일 고르기 창을
띄우는데, 그 창이 뜨면 페이지가 멈춥니다(앱은 「응답이 없어 중단했습니다」로 끝납니다).

처음에는 페이지의 파일칸 `click` 을 막아 창을 피했습니다. 그런데 **카인포는 칸을
`<label>` 로 눌러 열어서 그 방법이 통하지 않았습니다.** 창이 실제로 떠 버려 사진이
한 장도 안 올라갔습니다.

지금은 크롬에게 **파일 고르기 창을 아예 열지 말라**고 시킵니다
(`Page.setInterceptFileChooserDialog`). 무슨 방법으로 누르든 창이 뜨지 않고,
"어느 파일칸이 열렸는지"만 알려주므로 그 칸에 경로를 바로 꽂습니다
(`DOM.setFileInputFiles`). 사진 여러 장을 올리는 동안 조종은 한 번만 붙였다 뗍니다.

**기다리는 일은 앱이 한다 (P2)** — 「사진 확인 응답이 없어 중단했습니다(25초)」의
정체는 느림이 아니라 **스크립트가 죽은 것**이었습니다. 사진이 올라가면 사이트가
화면을 새로 그리는데, 그때 페이지 안에서 기다리던 스크립트가 통째로 사라져 답이
영영 오지 않습니다. 지금은 "지금 어떤가"만 짧게 묻고(`buildPhotoWatchScript`)
사이 간격은 앱에서 쉽니다. 화면이 바뀌는 중이라 물음이 실패해도 그냥 다시 묻습니다.

**자리는 사진(img)이 아니라 사진을 담는 상자여야 한다** — 카인포 앞면·뒷면·좌측면·
우측면이 `img` 로 잡히는 바람에 그 안에서 사진을 찾을 수 없어, 올라갔는데도
"바뀌었다"를 영영 못 알아챘습니다. 이제 `img`·`canvas` 는 자리 후보에서 뺍니다
(실제 화면에서는 `div#imgName1~8` 이 잡힙니다).

**「수정되었습니다」 안내창** — 카인포는 사진 한 장이 올라갈 때마다 안내창을 띄우고,
그걸 닫아야 다음 장을 넣을 수 있습니다. 그래서 확인 단계에서 그 창을 찾아 닫습니다
(화면 한가운데 떠 있는 확인·OK 만 누릅니다). 사이트가 `alert` 로 알리는 경우도
있어 올리는 동안에는 `alert` 를 잠시 막아 둡니다 — 뜨면 페이지가 통째로 멈춥니다.

**자리를 어떻게 가려내는가 (한 번 틀렸던 곳)** — 처음에는 '뒷면' 글자에서 부모를
타고 올라가 큰 상자를 찾았습니다. 그런데 두 자리가 한 상자 안에 나란히 있어서
둘 다 같은 부모가 잡혔고, 뒷면을 눌러도 아무 일이 없었습니다. 그런데도 파일을
꽂아 버리니 사이트는 직전에 기억해 둔 자리(앞면)에 그대로 올렸습니다 —
**전면·후면이 둘 다 앞면에 들어간 이유**입니다.

지금은 이렇게 합니다.

- 이름표와 상자를 **좌표로 짝짓습니다** (이름표는 제 상자 바로 아래에 붙어 있다)
- 십자가를 누른 뒤 **사이트가 파일칸을 실제로 불렀는지** 확인하고, 부르지 않았으면
  올리지 않고 멈춥니다 — 엉뚱한 자리에 넣느니 알리는 편이 낫습니다
- 넣기 전 두 자리의 모습을 적어 두었다가, **의도한 자리가 바뀌었는지** 확인합니다.
  다른 자리가 바뀌었으면 그 사실을 알립니다
- 올릴 자리에 표(`data-cc-slot`)를 달아 둡니다. 사진이 붙으면 화면 모양이 달라져
  자리를 다시 못 찾는 일이 있었습니다

**자리 찾기는 화면 구조를 가리지 않습니다.** 태그를 미리 정해 두면 놓칩니다 —
실제로 `figcaption` 같은 이름표를 못 읽어 "자리를 찾지 못했습니다" 가 났습니다.
지금은 모든 요소를 훑어 크기·내용물로 가리고, 표(table)·ul·껍데기 중첩·figure·
이름표가 상자 안에 있는 경우까지 모두 같은 자리를 집어냅니다.

**사진만 따로 시험하기** — 전체 전송을 다시 돌리지 않아도 됩니다.

- `[사진만 전송 (조합)]` · `[사진만 전송 (카인포)]` : 사진만 올려 봅니다
- `[사진 화면 조사]` : 사이트를 고르면 그 화면에서 **찾은 자리(8칸)**, 이름표 위치,
  상자 후보, 파일칸, 지금 붙어 있는 사진을 보여주고
  `%APPDATA%\carcheck-dual\photo-probe.json` 에도 남깁니다.
  자리를 못 찾을 때 이걸 보면 바로 맞출 수 있습니다.

**속도** — 처음에는 사진 여덟 장을 올리는 데 한참 걸렸습니다. 자리를 찾으려면
화면의 모든 요소 크기를 재야 하는데(브라우저가 배치를 다시 계산해 특히 느립니다),
이걸 자리마다·부호마다 되풀이하고 있었습니다. 세 가지를 고쳤습니다.

1. 한 번 잰 것은 담아 두고 다시 쓴다 (화면이 새로 그려지면 자동으로 다시 잰다)
2. 이름표는 한 번만 훑어 표로 만든다
3. 정해진 시간을 무조건 기다리지 않고, 사이트가 반응하면 바로 넘어간다
   (사진마다 붙였다 떼던 브라우저 조종도 한 번만 붙인다)

같은 조건(요소 2,500개를 더 얹은 무거운 화면)에서 여덟 장 기준 **7.3초 → 0.35초**.

안내창 처리를 넣은 뒤에도 **여덟 장 1.5초**입니다 — 안내창이 뜨면 바로 닫고 넘어가고,
안내창이 없는 조합에서는 짧게만(0.25초) 살핍니다. 무조건 기다리게 두었더니
같은 작업이 7.3초로 되돌아갔습니다.

두 사이트가 같은 방법을 쓰므로 코드도 한 곳입니다 — `src/photo-upload.js`.

### 절개도 맞추기 (부위별 자리·크기)

**`6_절개도_맞추기.bat`** 를 실행하면 브라우저에서 절개도를 직접 고칠 수 있습니다.

- 부위 상자를 **끌어 옮기고**, 여덟 모서리 손잡이로 **크기**를 바꿉니다
- 기둥(A·B·C필러)은 양 끝점과 굴곡으로 맞춥니다
- 방향키 0.5씩(Shift 5씩), **Alt+방향키는 크기**
- 「좌우 대칭」을 켜 두면 좌측면을 고칠 때 우측면이 함께 따라갑니다
- 차체 밑그림도 가로·세로·크기로 옮기거나 키울 수 있습니다
- 바꾼 모습이 오른쪽 미리보기에 앱 크기 그대로 나옵니다
- [되돌리기] 는 한 단계씩, [처음값으로] 는 프로그램 기본 배치로

[저장] 하면 `%APPDATA%\carcheck-dual\diagram.json` 에 담기고, 프로그램을 다시 켜면
그대로 그려집니다. 파일이 없으면 `parts-diagram.js` 의 기본 배치를 씁니다.

**검은 창을 닫으면 저장이 안 됩니다.** 저장은 그 창(작은 서버)이 받아 파일에 적는
구조라, 창을 닫거나 Ctrl+C 로 멈추면 「Failed to fetch」가 납니다. 그래서 화면이
5초마다 창이 살아 있는지 보고, 꺼져 있으면 빨간 알림을 띄웁니다. 그때는
[파일로 내려받기] 로 `diagram.json` 을 받아 `%APPDATA%\carcheck-dual\` 에 넣으면
똑같이 적용됩니다.

담기는 내용은 부위 37칸(`{ "sideL:pt3@LF": { "box": [x, y, 너비, 높이] } }`,
기둥은 `line`)과 그림 네 장의 밑그림 위치·크기(`views`)입니다.

### 절개도 기둥(A·B·C필러)만 맞추기

기둥은 네모 띠가 아니라 문턱에서 지붕으로 가로지르는 선입니다. 그림이 앞이 위쪽·
지붕이 오른쪽이라, A(앞유리)와 C(뒷유리)는 기울고 B(앞뒤 문 사이)는 곧습니다.

기울기가 눈에 안 맞으면 **`5_절개도_기둥맞추기.bat`** 를 실행하세요.
브라우저에서 파란 점(문턱 끝)·주황 점(지붕 끝)을 끌어 맞추고 [저장] 하면

```
%APPDATA%\carcheck-dual\pillar.json
```

에 숫자가 적히고, 이중등록 프로그램을 다시 켜면 그대로 그려집니다.
좌측면만 맞추면 우측면은 좌우로 뒤집혀 따라갑니다.
값은 `[문턱끝x, 문턱끝y, 지붕끝x, 지붕끝y, 굵기, 굴곡]` (그림 좌표 160 × 270).
굴곡은 기둥 가운데가 얼마나 배부른가로, 0 이면 곧은 선입니다.
좌우를 뒤집을 때 휘는 쪽도 함께 뒤집힙니다.
파일이 없으면 `parts-diagram.js` 의 `PILLARS` 기본값을 씁니다.

### 카인포는 주행거리 칸이 둘이다

성능점검의 **주행거리**(`#distance`)와 보증정보의 **현재주행거리**(`#currentKm`)가
따로 있습니다. 조회하면 현재주행거리에 옛 숫자가 들어오는데, 점검원이 주행거리만
고치면 그 옛 숫자가 그대로 남아 두 값이 어긋났습니다.

이제 앱에서 주행거리를 고치면 현재주행거리가 따라갑니다(`syncCurrentKm`).
사람이 현재주행거리를 직접 고친 적이 있으면 그 값을 그대로 둡니다.
전송할 때는 넣은 값이 실제로 남아 있는지 **되읽어 확인**하고,
사이트가 되돌리면 결과창에 그 사실을 적습니다.

### 카인포 점은 부호마다 다르다

판금(W)은 교환(X)보다 점이 많고 자리도 다릅니다. 점 자체가 어떤 부호를 받는지
말해 줍니다 — id 의 꼬리표와 class 양쪽에 적혀 있습니다.

```
part-168            교환 전용        class="status status-x part-168"
part-168-w          판금 전용        class="status status-w part-168-w"
part-173            교환·판금·요철·부식·손상
                    class="status status-x status-w repair-u repair-c repair-t part-173"
```

그래서 두 가지를 합니다.

1. **찾을 때**: 이름표(`CI_DOT`)의 id 로 못 찾으면, 같은 자리 번호(`168`)를 가진 점
   가운데 **그 부호를 받는 것**을 고릅니다. 이름표는 교환으로 익힌 것이라
   이 되짚기가 없으면 판금은 "점이 나타나지 않았습니다" 로 끝납니다.
2. **학습할 때**: `[카인포 절개도 학습]` 이 여섯 부호를 하나씩 골라 가며
   각 부호에서 어떤 점이 보이는지 먼저 훑고, 새로 보이는 점만 눌러 확인합니다.
   결과에는 점마다 **받는 부호 목록**이 함께 남습니다
   (`carinfo-parts.json` 의 `dots` / `byCode`).
3. **표**: 학습 결과에서 **근거가 분명한 것만** 추려 `CI_DOT_CODE` 에 넣었습니다.
   근거는 둘뿐입니다 — 같은 자리번호(`82-xw` ↔ `82-auct`), 사이트가 붙인 무리
   이름(`part-194-group` 안의 `194-xw`). 교환·판금은 37곳 중 31곳이 채워졌고,
   판금이 교환과 **다른 자리**인 곳은 5곳입니다(루프패널·플로어패널·리어패널·
   사이드멤버 앞 좌우).

한 자리에 여러 부호를 찍으면 **부호마다 제 자리**에 따로 찍습니다.
부호를 바꿀 때는 그 자리에 딸린 점(교환·판금·수리)을 모두 훑어 지운 뒤 다시 찍습니다.

**아직 비어 있는 칸**
- 필러패널 A·B·C : 지난 학습 결과와 합치면서 부호 정보가 버려졌습니다.
  (합치는 방식을 고쳤으니 학습을 한 번 더 돌리면 채워집니다)
- 외판 1·2·4·5·6·8 의 수리 부호(부식·흠집·요철·손상) : 수리 점은 눌러도
  부위칸이 켜지지 않아 어느 부위인지 확인할 방법이 없습니다.
  좌표로 추측하지 않고 비워 둡니다 — 전송할 때 사람에게 알립니다.
