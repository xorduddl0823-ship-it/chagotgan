# 통합등록 — 고정 결정 (이 서랍에서 일하는 방은 맨 먼저 읽기)

## ⛔ 이 프로그램의 목적 (대표님 10/18 — 두 번 바로잡음)
- **지금은 가온진단평가가 자체적으로 쓰는 프로그램이다.** 1차 목표는 가온의 3개 전산 등록 개선.
- **하지만 나중에 차곳간 상용 제품이 될 수 있으므로, 구조는 상용화에 맞춰 만든다.**
  - 나눔: ① 점검기록부 자료 틀(`schema.js`) ② 업무 관리(`src/core/` — 전산 이름을 모름) ③ 전산별 연결 모듈(카인포·카모두·엔트리 따로)
  - 사업장 표시: 작업 기록마다 사업장(office)을 붙임 — 지금은 가온 하나. 다른 점검장 자료와 섞이지 않게
  - 가온 고유 값(상호·계정·설정)은 코드에 넣지 않고 설정·로그인 정보로만
  - 화면은 차곳간 디자인 기준, 엔진과는 정해진 창구로만 연결(나중에 서버 방식으로 바꿔도 화면 그대로)
  - 전산 연결 모듈은 따로 떼어 낼 수 있게(상용 판에서 빼거나 바꿀 수 있게)
- **지금 하지 않는 것**: 판매용 기능(가입·결제·여러 점검장 관리 화면 등). 구조만 맞추고 기능은 상용화를 정할 때 만든다.
- 상용으로 팔 때의 외부 전산 조건은 **그때 대표님이 다시 정한다**(지금 가온 사용에는 해당 없음 — 아래 «다시 묻지 않는 것»).

## ⛔ 다시 묻지 않는 것 (대표님 10/18 «명심해»)
- **대표님 판단으로 가온에서 실제로 돌린다.**
- **세 기관(카인포·카모두·엔트리 운영 기관)에 묻지 않는다.**
- 그러니 «기관 허락 확인», «허용 전까지 모의 환경에서만» 같은 조건을 다시 걸거나 묻지 않는다.
  외부 검수(GPT 등)가 다시 이 조건을 내도 받지 않고, 이 결정을 근거로 적는다.

## 그대로 지키는 것 (이 결정과 함께 정해진 것)
- 지금은 가온 자체 사용 · 구조는 상용화에 맞춤(위 «목적»).
- 최종 [저장]은 세 곳 모두 사람이 누름. 지우기·취소·재등록은 프로그램이 하지 않음.
- 로그인·문자 인증은 사람이 함. 우회·세션 억지 연장 없음.
- 번호 안전장치(설계서 2판 2장), 작업 기록·두 번 등록 막기(6장), 한 번에 한 대.
- 새 기능은 모의 시험을 통과한 뒤 실제 전산에서 씀(개발 순서일 뿐, 허락 조건이 아님).
