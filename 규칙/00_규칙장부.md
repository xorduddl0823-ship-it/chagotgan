# 차곳간 규칙 장부

> 관리: 총괄 방만 고칩니다. 다른 방은 바꾸고 싶은 규칙이 있으면 총괄 방에 요청합니다.
> 「대표님 말씀」은 대표님이 대화방에서 직접 하신 말을 그대로 옮긴 것입니다.

---

## 1. 서비스 구조

| 번호 | 규칙 | 근거 |
|---|---|---|
| 1-1 | 사용자 제품(워시·체크·딜러, 추후 파킹·스튜디오·무브·트레이드)은 **입구(로그인) 하나**로 들어옵니다. 계정에 허락된 제품만 열립니다. | 대표님 말씀: "계정에 따라 권한을 다르게 주어, A계정 체크, B계정 워시, 관리는 나혼자" |
| 1-2 | 제품 화면 파일은 **제품마다 따로** 둡니다. 통합 입구는 그 파일들을 묶는 상자입니다. | 한 제품 실수가 다른 제품을 멈추지 않게 하기 위함 |
| 1-3 | **관리(컨트롤센터)는 통합 입구에 넣지 않습니다.** 주소(admin), 배포, 로그인을 따로 둡니다. | 대표님 동의 (2026-10-13) |
| 1-4 | 사용자 제품은 **같은 주소(도메인) 아래** 둡니다. 한 번 로그인하면 제품을 옮겨 다녀도 다시 로그인하지 않게 하기 위함입니다. | 지금은 app.cgg.co.kr / check.cgg.co.kr 로 나뉘어 있어 합칠 방법을 서버·홈페이지 방이 정함 |
| 1-5 | 휠·리페어는 별도 제품이 아니라 **워시 가입 때 고르는 업종**입니다. | 워시 원본의 업종 값(wash / wheel / repair) |
| 1-6 | 화면 파일 하나가 **PC와 모바일을 함께** 처리합니다. 앱은 그 화면을 담는 **액자**입니다. 앱 전용 화면은 만들지 않습니다. | 대표님 말씀: "사용자페이지를 앱으로 실행하되 기능은 모바일화 된 페이지를 그대로" |
| 1-7 | 앱은 **홈 화면 추가형(PWA)** 으로 먼저 시작하고, 아이폰 블루투스 같은 이유가 생기면 스토어 등록형으로 넘어갑니다. | 비용·시간이 적음 |

## 2. 보안

| 번호 | 규칙 |
|---|---|
| 2-1 | **권한은 서버가 검사합니다.** 화면에서 단추를 숨기는 것은 보안이 아닙니다. 서버는 권한 없는 계정의 요청을 거절해야 합니다. |
| 2-2 | **비밀 열쇠는 수파베이스 서버 비밀값에만** 둡니다. 화면 파일·문서·대화·저장소에는 이름만 적습니다. |
| 2-3 | 관리 로그인은 아이디·비밀번호 뒤에 **문자 6자리 확인**을 반드시 거칩니다. |
| 2-4 | 모든 배포 전에 **보안 방 검사**를 통과해야 합니다. (`운영/02_배포_전_보안_검사표.md`) |
| 2-5 | 개인정보(딜러), 위치 정보(무브), 돈 거래(트레이드)를 다루는 기능은 **만들기 전에** 보안 방 검토를 받습니다. |

현재 서버 비밀값 **이름** 목록 (값은 적지 않음):
`ANTHROPIC_KEY`, `POPBILL_LINKID`, `POPBILL_SECRET`(또는 `POPBILL_SECRETKEY`), `SOLAPI_KEY`, `SOLAPI_SECRET`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `CGG_INTERNAL_KEY`(서버끼리), `STAFF_MSG_MAX`(직원 문자 하루 한도), `TOSS_SECRET_KEY`, `PAY_READY`, `PAY_PG`, `PAY_CLIENT_KEY`(토스 결제 · 정기 결제용 이름은 토스 계약 뒤 추가)

## 3. 디자인과 화면

| 번호 | 규칙 | 근거 |
|---|---|---|
| 3-1 | **워시가 뼈대의 출발점**입니다. 다만 같은 항목은 한쪽으로 덮어쓰지 않고, 워시·체크 중 **더 좋은 쪽을 항목마다 골라**(대조표 → 대표님 확인) 공통 부품 하나로 만들어 둘 다 씁니다. | 대표님 지시 · 10/18 «체크가 좋은 게 있고 워시가 좋은 게 있어» |
| 3-2 | 뼈대·스타일·공통 기능·화면 순서는 **모든 제품이 100% 같아야** 합니다. ("99%는 실패") 다른 것은 제품별 설정 한 덩어리뿐입니다. | 대표님 말씀: "모든 스크롤 및 같은 패턴의 규칙, 소스, 뼈대 등 100% 다 같아야" |
| 3-3 | **탭 이름은 제품마다 다를 수 있습니다.** 디자인과 뼈대만 같게 합니다. | 대표님 말씀: "워시 체크 관리는 엄연히 업체들이 다르기 때문에 탭이 다를 수 밖에" |
| 3-4 | **탭 순서는 일하는 순서**이므로 바꾸지 않습니다. | 대표님 말씀: "일 순서대로 목록을 둔거라 순서는 안바뀌었으면 함" |
| 3-5 | 워시의 「현장 화면」은 메뉴가 아니라 **머리말 맨 앞 버튼**에 둡니다. | 대표님 말씀: "현장화면은 따로 머리말에 두어야 함" |
| 3-6 | 디자인 기준은 **차곳간 UI 기준틀**과 **합친 디자인 J안**입니다. 화면 일곱 칸, 표 열 순서, 창 크기 3종은 기준틀을 따릅니다. | 디자인 방 결과물 |
| 3-7 | 만들기 전에 **시안부터** 보여 주고, 대표님이 확인한 뒤 실제 파일에 넣습니다. | 대표님 지시 |
| 3-8 | **약관 글은 손대지 않습니다.** | 대표님 지시 |
| 3-9 | **공통 기능은 모든 제품에 한 번에** 넣습니다(워시·체크·파킹·스튜디오·딜러·관리 해당분). 공통 부품 파일로 만들고, 예외는 «제품 전용»(체크 = 검사비·성능보험료·검사소·재검사 / 워시 = 현장 입고·출고 사진·배달·자재)만. 끝낼 때 «다른 제품 반영 표»를 적고 총괄이 다음 판 일감으로 넘깁니다. | 대표님 말씀 10/18: "체크에 하기로 한 기능은 워시에도, 앞으로 파킹·스튜디오도 기본은 다 같이" |

## 4. 문구

| 번호 | 규칙 |
|---|---|
| 4-1 | **고등학생이 바로 이해하는 말**, 해요체로 씁니다. 단, 손님이 처음 보는 **가입·로그인·오류 안내**는 일반 사이트 표준형(「~습니다」, 예: 「인증번호를 발송했습니다.」)으로 씁니다. (대표님 확정 2026-10-15) |
| 4-2 | "돈" 대신 **"금액"** 이라고 씁니다. |
| 4-3 | 「관제센터」는 **「관리」** 로 부릅니다. |
| 4-4 | 「알람」 대신 **「알람 소리」**. |
| 4-5 | 상태 이름은 **진행 중 · 확인 필요 · 보류 · 완료** 네 가지로 통일합니다. 「하는 중 · 끝남 · 막힘」 같은 옛 이름은 쓰지 않습니다. (대표님 확정 2026-10-14) |

## 5. 서버와 외부 연결

| 번호 | 규칙 |
|---|---|
| 5-1 | 서버는 **수파베이스 프로젝트 하나**를 모든 제품이 함께 씁니다. |
| 5-2 | **구글 Apps Script·구글 시트는 완전히 폐기**합니다. 남은 부분은 수파베이스로 옮깁니다. (대표님 말씀: "구글스크립트는 이제 모든 기억속에서 지우고") |
| 5-3 | 서버와 화면이 주고받는 모양은 모든 제품이 같습니다: 요청 `{shop, token, fn, args}` → 응답 `{result}` 또는 `{__err}` |
| 5-4 | 체크가 워시보다 앞선 기능(매출 내역, 입·출금 내역, 세금계산서)은 **체크 것을 워시로 옮겨** 씁니다. |
| 5-5 | **팝빌 계좌조회는 건당 유료**, **발급한 세금계산서는 취소할 수 없습니다.** 반드시 테스트 모드로 먼저 시험하고, 실제로는 1건만 시험합니다. |
| 5-6 | **손님·직원에게 보내는 안내는 알림톡이 먼저**입니다. 모든 사용자 제품(워시·체크·딜러·홈페이지 가입 등)은 솔라피 카카오 알림톡으로 보내고, 알림톡이 실패할 때만 솔라피가 자동으로 문자로 대신 보냅니다. 문자만 따로 보내는 기능을 새로 만들지 않습니다. 템플릿 코드는 관리 설정 칸에 두고, 비어 있으면 문자로 보냅니다. 알림톡은 정보성만 되므로 결제·충전·연장을 권하는 문구와 버튼은 넣지 않습니다. (대표님 지시 2026-10-15, 근거: `운영/기획/2026-10-15_알림톡_우선_단가비교.md`) |

## 6. 작업방 운영

| 번호 | 규칙 |
|---|---|
| 6-1 | 방마다 고칠 수 있는 서랍이 정해져 있습니다 (`규칙/01_방_구성표.md`). |
| 6-2 | 같은 파일을 두 방이 동시에 고치지 않습니다. |
| 6-3 | 결정은 총괄 방이 `운영/04_결정_기록.md`에 남깁니다. |
| 6-4 | 배포는 대표님만 합니다 (Cloudflare 업로드). |
| 6-5 | 바꾼 내용은 저장소에 기록(커밋)을 남겨, 언제든 이전 상태로 되돌릴 수 있게 합니다. |
| 6-6 | **대표님 시간은 가장 아껴야 합니다.** 대표님 확인 없이 할 수 있는 일은 먼저 끝까지 해 둡니다. 정할 것이 있으면 각 방이 추천안으로 먼저 진행해 두고, 대표님께는 **결정 시안 4~5가지만** 모아서 드립니다. (대표님 지시 2026-10-14) |
| 6-7 | 대표님께 드리는 결정 시안은 **고르기만 하면 바로 적용**되게 준비합니다. 시안마다 ① 한 줄 설명 ② 미리보기(아티팩트) ③ 추천 표시를 붙이고, 고른 뒤 남은 일은 방이 바로 끝냅니다. 질문은 총괄 방이 모아서 한 번에 드립니다. 각 방이 대표님께 따로 묻지 않습니다. |
