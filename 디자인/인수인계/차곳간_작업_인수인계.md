## 1. 절대 규칙 (사용자가 여러 번 강조)

1. **100% 똑같이** — 모든 창, 검색 창, 디자인, 워딩, 내용, 팝업. 글자 크기·색·여백·줄 수까지. **99%는 실패.**
2. **워시가 기준(마스터)** — 체크가 두 번째, 관리가 세 번째.
3. **절대 새로 만들지 않는다. 카피·복사만 한다.** 비슷하게 다시 구현하면 반드시 어긋난다.
4. **체크에만 있는 좋은 것은 체크 코드를 그대로 워시로** 가져온다 (매출 내역·팝빌이 그런 경우).
5. **시안(아티팩트) 먼저.** 글로 설명하지 말고 그림으로 보여주고 고르게 한다.
6. **파일 주기 전에 직접 대조 검증.** 세 제품을 브라우저에 띄워 `getComputedStyle` 값을 표로 비교, 불일치 0일 때만 전달.
7. **구글 앱스스크립트는 쓰지 않는다.** Supabase · 팝빌 · Cloudflare · Anthropic · 솔라피만.
8. 서버 호출·자료 저장·계산 방식은 함부로 바꾸지 않는다. 단추·기능을 없애지 않는다(옮기면 어디로 옮겼는지 알린다).
9. 이용약관 · 개인정보처리방침 · 환불정책 글은 손대지 않는다.
10. **배포는 사용자가 직접** 한다 (Cloudflare 업로드).
11. 도구 호출 설명은 **한국어로**.

## 2. 내가 2시간 날린 함정 (반복 금지)

| 함정 | 증상 | 해법 |
|---|---|---|
| **같은 이름, 다른 동작** | 워시 `won()`은 「원」을 붙이고 체크 `won()`은 콤마만 → `0원대`, `0원원` | 복사 전 함수 동작 확인. 매출 화면은 `swon()` 따로 둠 |
| **전역 변수 누락** | 체크 `ts()`가 쓰는 `var TS={}`를 안 가져와 워시 매출 탭 전체 사망 (`TS is not defined`) | 복사할 때 의존 전역까지 |
| **CSS 클래스 누락** | `.csub`(설명글)를 빠뜨려 글자가 크고 검게 | 클래스 목록을 뽑아 대조 |
| **DOM 뼈대 차이** | 체크는 `homegrid > hgL/hgR`, 워시는 이름 없는 `div` → 같은 CSS가 한쪽만 먹음 | **CSS보다 뼈대(클래스 이름)를 먼저 같게** |
| **CSS 위치** | 파일 앞쪽에 넣으면 뒤의 원본 규칙에 밀림 | **마지막 `</style>` 직전**에 |
| **검증 코드가 CSS를 지움** | `document.body.innerHTML=""` 하면 body 안 `<style>`도 지워져 "적용 안 됨"으로 오판 | 테스트 div만 `appendChild` 후 `remove()` |
| **브라우저 캐시** | 고쳤는데 옛 화면 | 포트를 바꿔 새 서버, 또는 `curl`로 파일 직접 확인 |
| **좁은 미리보기** | 2열 레이아웃이 1열로 떨어져 측정 무의미 | `resize_window`로 1600px 이상, foreground 탭에서 |

POST  { shop, token, fn, args:[...] }  →  { result } 또는 { __err }

### 로그인은 이미 공유 중
체크 서버가 `wash_sessions` 표를 그대로 읽는다. 소스 주석에도 "차곳간(wash) 계정을 그대로 씁니다".

`ybfpxmmjofyvfprtvmhj` (이름 `chagotgan-wash`)
Edge Functions 3개: `check-api`(810 req/h) · `dealer-api` · `wash-api`(247 req/h)

### 비밀값 (티와이컴퍼니 공용)

## 9. 최종 목표 — 한 파일 통합 + 권한

사용자 계획: 나중에 **세 제품을 한 파일로 합치고 계정 권한으로 가른다.**
(A계정=체크, B계정=워시, 관리=사용자 본인만)

그러려면 아직 다른 이것들을 먼저 통일해야 한다:

| | 워시 | 체크 | 관리 |
|---|---|---|---|
| 화면 만드는 방식 | `<section id="vXxx">` + `renderXxx()` | `PAGE.xxx` + `AFTER.xxx` | 또 다름 |
| 탭 전환 | `S.tab` + `decideMode()` | `go(k)` + `draw()` | `#nav` |
| 표 함수 | `gTable` | `tableBlock` | 없음 |
| 자료 담는 곳 | `S.records` 등 | `CARS` `BILLS` 등 | 또 다름 |
| CSS | 파일 안 | 파일 안 | 아예 다름 |

**통일 방향 (제안):**
1. 화면 방식을 `PAGE.xxx` + `AFTER.xxx` 하나로 (체크 방식이 화면 추가가 쉬움)
2. 공통 부품 한 벌 — `head` `card` `sums` `tableBlock` `ask` `openSheet` `call`
3. **CSS 한 파일** `cgg-ui.css` — 새 디자인은 이 파일만 교체
4. 서버 한 곳 (Supabase), 창구 이름 통일
5. 권한으로 메뉴 가르기

```js
var MENU = { wash:[…], check:[…], admin:[…] };
var canSee = ME.products;   // 서버가 내려줌. 여러 개면 머리말에 제품 바꾸기 단추
```

**새 디자인을 덮어쓸 예정**이므로 ①서버 부르는 곳을 `call()` 하나로 모으고 ②자료와 모양을 분리하고 ③CSS를 한 파일로 빼고 ④화면 이름표(`homegrid` `hgL` `hgR` `cal` `todo` `tablebox`)를 세 제품이 공유하게 해 두면, 디자인이 바뀌어도 기능이 안 깨진다.
