## 바뀐 것
| 안내 | 받는 사람 | 템플릿 (ataKey) | 보내는 변수 (확정본 그대로) |
|---|---|---|---|
| 출고 안내 (출고할 때 · 다시 보내기) | 딜러 | 출고안내 (`out`) | 딜러명 · 상사명 · 차량번호 · 작업내용 · 목적지 · 출고일시 · 업체전화 · 업체명 · 보기코드 |
| 청구서 (보내기 · 예약 발송) | 거래처 | 청구서 (`bill`) | 기간 · 받는곳 · 업체명 · 건수 · 금액 · 입금기한 · 계좌 · 업체전화 · 보기코드 |
| 추가 작업 «딜러에게 보내기» | 딜러 | 추가작업 (`add`) | 차량번호 · 업체명 · 작업내용 · 금액 · 업체전화 · 보기코드 |

- 업체가 **자기 알림톡을 켜 둔 경우**는 그대로 업체 것 먼저 (원래 기능).
- 본사 템플릿 코드가 아직 비어 있거나 옛 서버면 서버가 «템플릿 ID가 없습니다» → **그 자리에서 v115 와 똑같은 문자로 다시** 보내요. 그 뒤로는 화면을 닫을 때까지 바로 문자(두 번 묻지 않음).
- 알림톡이 받는 분께 안 닿으면 솔라피가 문자로 대신 보내요 (`disableSms:false`). 문자로 대신 갈 글은 지금 쓰는 문자 글 그대로.
- 추가 작업: «알림톡으로 보내기»(앞) + «문자 앱으로 직접»(뒤). 보낸 뒤 알림 글은 «알림톡을 보냈어요» / «문자를 보냈어요».
- 보기코드(단추 주소)는 출고 · 추가 작업은 `viewLink`, 청구서는 `viewBill` 로 받은 주소에서 꺼내 써요 (원래 있던 창구).
- **안 바꾼 것**: 직원 «주소 안내»(새 템플릿 심사 뒤) · 도매상 «자재 주문»(휴대폰 문자 앱 그대로, 총괄 결정) · 휴대폰 문자 앱으로 여는 곳들.

## 확인 (가짜 서버 — sb5 처럼 «코드 없음 → 거절» / `?ata=on` 이면 «코드 있음»)
- 출고 · 코드 없음: 알림톡(out) 시도 → 거절 → **사진 문자로 다시** · 두 번째 출고는 바로 사진 문자 · 알림 글 «문자를 보냈어요»
- 출고 · 코드 있음: 알림톡(out)만, 변수 9개 확정본 이름 그대로 · 알림 글 «알림톡을 보냈어요»
- 청구서 · 코드 없음: 알림톡(bill) → 문자 / 코드 있음: 알림톡(bill)만, 변수 9개
- 세 배치 · 매니저 · 폰 · 사진 서명 주소 시험 그대로 오류 0

## 추가 (2026-10-15 오후 · 서버 sb6 짝 · 총괄 결정)
- **업체 알림톡 기본 문안 · 넣을 수 있는 값**을 확정본 이름으로 (`#{업체}` → `#{업체명}`, `#{딜러}` → `#{딜러명}`, `#{상사명}` · `#{작업내용}` · `#{출고일시}` · `#{보기코드}` 등). 업체가 예전에 적어 둔 문안의 옛 이름도 그대로 채워지게 같이 넘겨요(업체 알림톡에서만). 본사 알림톡(ataKey)에는 **확정본 변수만** 보내요.
- 업체 알림톡에도 **보기코드**(사진 · 청구 내역 보기 단추)가 들어가게, 보내기 전에 한 번 받아요.
- **입금 기한** 칸: 청구서 › 2. 청구서 보내기 › «입금 계좌» 바로 밑 (예: «매월 10일», 30자). «문구·계좌·기한 저장»으로 저장. 비어 있으면 알림톡에 **«업체에 문의»**. 저장은 원래 쓰던 업체 설정(config)이라 **서버 저장 칸을 새로 만들 필요 없어요.**
- **입금 확인 안내** (입금확인 · `ataKey:"deposit"`): 입출금 › 받아야 할 금액 › [입금 확인] 창에 «거래처에 입금 확인 안내 보내기» 체크칸 (기본 꺼짐 — 새 안내라 본사 알림톡 전에는 문자 요금이 들 수 있어서). 변수: 받는곳 · 금액 · 업체명 · 확인일시 · 기간 · 업체전화.
- 서버 sb6 은 코드가 없으면 서버가 알아서 문자로 보내고, sb5 · 옛 서버면 화면이 «템플릿 ID가 없습니다»를 보고 문자로 다시 보내요 → 어느 서버와도 안 깨져요.
