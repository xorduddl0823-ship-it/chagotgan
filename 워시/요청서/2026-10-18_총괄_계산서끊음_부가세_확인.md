## 무엇이 틀렸나
- 딜러·상사의 계산서 칸 첫 번째 고르기 «계산서 끊음»을 화면이 «안 끊음»으로 읽었어요.
- 그래서 단가표가 «부가세 별도»(기본값)이면 청구서에 **부가세 10%가 빠진 금액**이 찍혔어요.
- 단가표가 «부가세 포함»이면 받을 금액은 맞아요. 청구서의 부가세 줄만 0으로 보여요.
- 예전 글자 «세금계산서 발행»으로 저장된 줄은 바르게 읽혀요.
- 새로 만드는 딜러·상사는 기본값이 «계산서 끊음»이라, 고치지 않고 저장한 줄은 거의 다 걸려요.
- 저장소에서 가장 오래된 워시 판(실제 주소 판으로 보는 v111 사본)에도 같은 줄이 있어요. 운영/05 63번에는 «운영 v109»로 적혀 있어요.
  **실제 주소 판이 v109·v111 어느 쪽이든 걸려 있다고 보는 게 맞아요.**
  확인: app.cgg.co.kr 머리말 판 번호(운영/05 10번)
- 보낸 청구서는 금액이 그때 값으로 저장돼요. 화면을 고쳐도 지난 청구서는 바뀌지 않아요. 고친 판은 앞으로 만드는 청구서부터 바르게 셈해요.

## 확인 SQL (읽기만 · 번호·이름 안 나옴, 개수·합계만)
Supabase › SQL Editor에 그대로 붙여 넣어 실행해요. 아무것도 고치지 않아요.
`GAON`(가온)과 `ADMIN`은 뺐어요. 시험 업체 코드가 더 있으면 맨 아래 `not in (...)` 칸에 넣어요.

```sql
-- ① 금액이 틀렸을 수 있는 «보낸» 청구서: 개수 · 업체 수 · 보낸 금액 · 빠진 부가세(추정 10%)
with cfg as (
  select shop, coalesce(data->>'vatMode','out') as vat_mode
  from wash_docs where col = 'settings' and id = 'config' and demo = false
),
who as (
  select shop, 'company' as unit, data->>'name' as name, coalesce(data->>'taxType','') as tax
  from wash_docs where col = 'companies' and demo = false and data is not null
  union all
  select shop, 'dealer', data->>'name', coalesce(data->>'taxType','')
  from wash_docs where col = 'dealers' and demo = false and data is not null
),
b as (
  select d.shop,
         case when d.data->>'unit' = 'company' then 'company' else 'dealer' end as unit,
         d.data->>'name' as name,
         case when (d.data->>'amount') ~ '^-?[0-9]+(\.[0-9]+)?$'
              then round((d.data->>'amount')::numeric) else 0 end as amount
  from wash_docs d
  where d.col = 'bills' and d.demo = false and d.data is not null
    and coalesce(d.data->>'sentAt','') <> ''
)
select count(*)                      as 청구서_수,
       count(distinct b.shop)        as 업체_수,
       coalesce(sum(b.amount),0)     as 보낸_금액_합계,
       coalesce(sum(round(b.amount*0.1)),0) as 빠진_부가세_합계
from b
left join cfg c on c.shop = b.shop
where b.shop not in ('GAON','ADMIN')
  and coalesce(c.vat_mode,'out') <> 'in'
  and exists (select 1 from who w
              where w.shop = b.shop and w.unit = b.unit and w.name = b.name
                and w.tax ~ '끊음' and w.tax !~ '안\s*끊' and w.tax !~ '미발|없음');

-- ② 앞으로 걸릴 수 있는 거래처 수 (지금 «계산서 끊음»으로 저장된 딜러·상사)
select count(*) as 거래처_수, count(distinct shop) as 업체_수
from wash_docs
where col in ('companies','dealers') and demo = false and data is not null
  and shop not in ('GAON','ADMIN')
  and coalesce(data->>'taxType','') ~ '끊음'
  and coalesce(data->>'taxType','') !~ '안\s*끊|미발|없음';
```

- 결과 읽는 법: ①이 0이면 실제로 틀리게 나간 청구서는 없어요. 0이 아니면 **빠진_부가세_합계**가 덜 받은 금액(추정)이에요.
- 한계: 청구서는 받는 곳 «이름»으로 거래처를 찾아요. 청구서를 보낸 뒤 거래처 계산서 칸을 바꿨다면 그때와 다를 수 있어요.

## 추천 (작은 판 먼저 올릴지)
1. **추천 — ①이 0이면 작은 판은 필요 없어요.** 출시 때 v130을 올리면 끝이에요.
2. ①이 0이 아니고 v130 올리는 날이 3일 넘게 남았다면: 워시 방이 «실제 판 + 이 한 줄만 고친 판»을 만들어 드려요.
   - 고치는 줄: `if(/미발|없음/.test(t))` → `if(/미발|없음|안\s*끊/.test(t))` 와 `/발행|발급/` → `/발행|발급|끊음/`
   - 먼저 대표님이 머리말 판 번호를 알려 주셔야 해요. 저장소에 그 판 원본이 있어야 정확히 한 줄만 바꿀 수 있어요. v111 사본은 있고, v109는 없어요.
   - 그 다음 보안 확인을 받고, 대표님이 올려요.
3. 이미 덜 받은 금액은 화면이 자동으로 고치지 않아요. 해당 업체에 차액을 따로 알릴지는 대표님이 정해요.
